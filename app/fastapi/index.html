00

Python 速通：只学 FastAPI 用得到的那部分

目标：30 分钟过完。心智模型一句话——Python 就是「不用分号、靠缩进分代码块、用 dict 代替对象」的 JS。下面每节左边 Python、右边你熟悉的 JS/TS，看对照就懂。

0.1 变量：不用 let / const，直接赋值

PYTHON

name = "chat"      # 定义字符串，不用写 let/const
count = 3          # 数字也一样，直接赋值
price = 9.9        # 小数就是 float
ok = True          # 布尔值首字母大写：True / False
nothing = None     # 空值叫 None，不叫 null

JS / TS 对照

const name = "chat";
const count = 3;
const price = 9.9;
const ok = true;      // 小写 true / false
const nothing = null; // Python 里写作 None

Python 是动态类型：变量不用声明类型，同一个变量可以先装数字再装字符串（不推荐，但语法允许）。类型主要写在函数参数和类字段上，给 FastAPI 做校验用，见 0.4。

0.2 容器：list 就是数组，dict 就是对象

PYTHON

tags = ["a", "b"]        # list，相当于 JS 数组
tags.append("c")         # 往末尾加元素，相当于 push
first = tags[0]          # 下标取值，和 JS 一样

user = {"name": "lin", "age": 18}  # dict，相当于 JS 对象
n = user["name"]         # 用方括号 + 键取值
n2 = user.get("name")    # get 取不到返回 None，不报错
user["vip"] = True       # 加新键，直接赋值

JS / TS 对照

const tags = ["a", "b"];
tags.push("c");
const first = tags[0];

const user = { name: "lin", age: 18 };
const n = user.name;      // JS 用点号，Python 用方括号
const n2 = user?.name;
user.vip = true;
最容易写错的一点：Python 里取 dict 的值用 user["name"]，没有 user.name 这种点号写法（点号是给对象属性和 Pydantic 模型用的）。字符串拼接常用 f-string：f"hi {name}"，就是 JS 的模板字符串 `hi ${name}`。

0.3 函数：def 开头，缩进代替大括号

PYTHON

def add(a, b=1):   # def 定义函数；b=1 是默认参数
    return a + b   # 靠缩进（4 个空格）表示在函数里

add(2)             # 不传 b，用默认值 → 3
add(2, b=5)        # 按名字传参，叫关键字参数 → 7
add(2, 5)          # 按位置传参也行 → 7

JS / TS 对照

function add(a, b = 1) {  // 靠 { } 分代码块
  return a + b;
}

add(2);            // 3
add(2, 5);         // 7（JS 没有按名字传参）
  • 缩进就是语法：同一层缩进必须对齐，缩进错了直接报错。看到冒号 : 就意味着下一行要缩进。
  • 没有分号，没有大括号：一行一句，块靠缩进区分。刚开始最不习惯的就是这个，看多了就好。
  • 函数可以有多个返回值：return a, b 实际上是返回一个元组，接收时 x, y = f() 拆开，像 JS 的数组解构。

0.4 类型注解：写法几乎就是 TS 把 number 换成 int

PYTHON

def greet(name: str, age: int = 0) -> str:
    # name: str 表示 name 是字符串，相当于 TS 的 name: string
    # age: int = 0 表示 age 是整数、默认 0
    # -> str 表示返回值是字符串
    return f"hi {name}"

session_id: str | None = None
# str | None 表示「字符串或者空」，相当于 TS 的 string | null

JS / TS 对照

function greet(name: string, age: number = 0): string {
  return `hi ${name}`;
}

let session_id: string | null = null;

关键区别：TS 的类型在运行时会被擦掉，Python 的注解运行时还在——FastAPI 正是靠这些注解在运行时做校验和生成文档，所以在 FastAPI 里类型注解不是装饰，是功能本身。常用对照：str↔string、int↔整数、float↔小数、bool↔boolean、list[str]↔string[]、dict↔对象。

0.5 类：class + __init__，self 就是 this

PYTHON

class Counter:               # class 定义类
    def __init__(self):      # __init__ 是构造函数
        self.n = 0           # self 就是 this，必须显式写出来

    def inc(self):           # 每个方法第一个参数都是 self
        self.n += 1          # 用 self.n 访问自己的字段
        return self.n

c = Counter()                # 创建实例，不用写 new
c.inc()                      # 调用方法，self 自动传入

JS / TS 对照

class Counter {
  constructor() {     // 对应 __init__
    this.n = 0;       // this 对应 self（但不用写在参数里）
  }
  inc() {
    this.n += 1;
    return this.n;
  }
}
const c = new Counter();  // JS 要写 new，Python 不用
c.inc();
好消息：FastAPI 里你最常写的类是 Pydantic 模型，它是「简化版类」——只写字段名 + 类型，不用写 __init__，Pydantic 自动帮你生成构造函数：class Item(BaseModel): name: str 就完事了。这是全教程最友好的部分。

0.6 装饰器：@ 开头的那行，做的事就是「把函数交给别人登记一下」

PYTHON

def log(fn):            # 一个普通函数，参数是另一个函数
    def wrapper():      # 在里面定义新函数
        print("调用前")  # 先做点事
        return fn()     # 再调用原来的函数
    return wrapper      # 返回新函数

@log                    # 把下面的函数交给 log 处理
def hello():
    print("hello")

hello()  # 实际跑的是 wrapper：先打印「调用前」，再打印 hello

JS / TS 对照

function log(fn) {
  return function () {
    console.log("调用前");
    return fn();
  };
}

// JS 没有 @ 语法，要手动包一层：
const hello = log(function hello() {
  console.log("hello");
});
hello();

记住一句话就够应付 FastAPI：@app.get("/") 等价于 函数 = app.get("/")(函数)，也就是把函数注册进路由表。装饰器是 FastAPI 路由的全部秘密，第 01 章会细讲。

0.7 async / await：和 JS 几乎一模一样

PYTHON

import asyncio           # 异步工具包，相当于 JS 内置的 Promise 体系

async def fetch_data():  # async def 定义异步函数
    await asyncio.sleep(1)  # await 等待，相当于 JS 的 await + 定时器
    return {"ok": True}     # 返回 dict

async def main():
    data = await fetch_data()  # 调用异步函数必须 await，不然拿到的是协程对象
    print(data)

JS / TS 对照

async function fetchData() {
  await new Promise(r => setTimeout(r, 1000));
  return { ok: true };
}

async function main() {
  const data = await fetchData();
  console.log(data);
}
  • async for chunk in ... 对照 JS 的 for await (const chunk of ...)，流式输出时用。
  • 最大的坑和 JS 一样：忘了 await。JS 里忘 await 拿到 Promise，Python 里忘 await 拿到 coroutine 对象，还会打一条警告。
  • 同步等待千万别写 time.sleep() 放在 async 函数里，要用 await asyncio.sleep()，原因第 02 章讲。

01

入门：先跑起来，再理解原理

目标：30 分钟内写出第一个接口，并在 /docs 里点着调通它。每个例子都是「先最简版，再展开」。

1.1 安装与最小例子

pip install fastapi "uvicorn[standard]"
# pip 是 Python 的包管理器，相当于 npm
# fastapi 是框架本体；uvicorn 是跑服务的服务器，相当于 node 运行时那一层
# 引号别漏：uvicorn[standard] 表示连带装齐标准版的额外依赖

第一步 · 最简版：一个文件、一个接口

# main.py —— 文件名叫 main，后面启动命令会用到
from fastapi import FastAPI  # 导入 FastAPI 类，相当于 import express

app = FastAPI()  # 创建应用实例，相当于 const app = express()

@app.get("/")  # 注册路由：GET 请求访问 / 时，交给下面这个函数
def read_root():  # 处理函数，不需要 req / res 参数
    return {"hello": "world"}  # 返回 dict，FastAPI 自动转成 JSON 响应
uvicorn main:app --reload
# main 是文件名（模块名），app 是文件里 FastAPI() 实例的变量名，别写反
# --reload 是开发模式：改代码自动重启，生产环境不要加
# 打开 http://127.0.0.1:8000/docs 就是自动生成的 Swagger 文档，能直接点着调接口

第二步 · 加上路径参数和查询参数（FastAPI 入门的完整形态）

@app.get("/items/{item_id}")  # {item_id} 是路径参数，占位写法
def read_item(item_id: int, q: str | None = None):
    # item_id: int —— 名字和路径里的占位对上，就是路径参数；标了 int，传非数字直接 422
    # q: str | None = None —— 不在路径里，所以是查询参数；有默认值 None，表示可不传
    return {"item_id": item_id, "q": q}  # 访问 /items/5?q=hi 就返回 {"item_id": 5, "q": "hi"}

1.2 app 和 @app 到底什么关系？

同一个东西。app = FastAPI() 先创建一个应用实例，里面存着所有路由。@app.get("/") 就是调用它身上的 get 方法，把下面的函数注册成路由（装饰器的原理见 0.6）。

# 装饰器写法，等价于下面这样手动注册：
def read_root():  # 先定义一个普通函数
    return {"hello": "world"}  # 函数体和之前一样

read_root = app.get("/")(read_root)  # 把函数交给 app.get("/") 处理，登记进路由表
  • 没有单独的 @app 写法，一定是 @app.get / @app.post，@ 只是 Python 装饰器语法。
  • 变量名不固定：写成 my_app = FastAPI()，就得写 @my_app.get("/")，启动也要改成 uvicorn main:my_app。
  • 前端类比：Express 是 const app = express(); app.get("/", handler)，装饰器只是把注册挪到了函数头顶。

1.3 函数名可以随便取吗？

可以。路由只看装饰器，不看函数名，hello()、foo() 都能跑。

展开唯一的例外：函数名会影响文档

函数名默认会变成文档里的 operationId，别在同一文件里重复定义同名函数——后一个 def 会盖掉前一个在代码里的名字，虽然路由本身还能跑，但看着很乱，文档里也容易混。起个有意义、不重名的名字就行。

1.4 核心就 4 个概念

① 装饰器 = 路由

@app.get / @app.post，跟 Express 的 app.get() 一样，函数名不重要，路径和方法才重要。

② 类型注解 = 校验 + 文档

传错类型直接 422，不用手写 if (!price) return 400，/docs 里自动显示结构。

③ 三种参数分得很清

路径参数 /items/{id}、查询参数 ?skip=0、请求体（Pydantic 模型）——位置决定来源。

④ def 还是 async def

要等 IO（大模型、DB、外部 API）用 async def；纯计算用 def，FastAPI 自动丢线程池。

1.5 用 Pydantic 定义请求体

第一步 · 最简版：只写字段和类型

from pydantic import BaseModel  # 导入 Pydantic 的基类，所有请求模型都继承它

class Item(BaseModel):  # 定义一个数据模型，相当于 TS 里定义 interface + 校验规则
    name: str  # 必填字段：名字是字符串，没默认值就必须传
    price: float  # 必填字段：价格是小数，传 "abc" 这种非数字会直接 422
    is_offer: bool | None = None  # 可选字段：布尔或空，默认 None，不传也不报错

@app.post("/items/")  # 注册 POST /items/ 路由
def create_item(item: Item):  # 参数类型是 Item 模型，FastAPI 就知道这是请求体，按模型校验
    return item  # 直接返回模型，自动序列化成 JSON
新手最容易踩的 4 个坑： ① uvicorn main:app 里 main 是文件名、app 是变量名，别写反；② 改代码不生效多半是没加 --reload；③ Pydantic 现在是 v2，别抄 v1 的 class Config 老写法；④ 别直接 return ORM 对象，先转成 Pydantic 模型，否则容易序列化报错。想在字段上加长度、范围这类约束（进阶写法），看 2.5 的 Field。

1.6 接 LangChain 的典型形态（你以后最常用的）

from pydantic import BaseModel  # 请求体模型还是靠 Pydantic

class ChatRequest(BaseModel):  # 前端 POST /chat 时要传的 JSON 结构
    message: str  # 用户消息，必填字符串
    session_id: str | None = None  # 会话 ID，可选；不传就是新会话

@app.post("/chat")  # 注册 POST /chat
async def chat(req: ChatRequest):  # 用 async def：因为要等大模型返回，是 IO 等待
    result = await agent.ainvoke(  # ainvoke 是 LangGraph 的异步调用，await 等它跑完
        {"messages": [("user", req.message)]},  # 把用户消息包成 LangGraph 的输入格式
        config={"configurable": {"thread_id": req.session_id or "default"}}  # thread_id 决定续哪段对话；没传 session_id 就用 default
    )
    return {"reply": result["messages"][-1].content}  # 取最后一条消息的文本返回；[-1] 就是数组最后一个元素，和 JS 一样

前端 fetch("/chat", {method:"POST", body: JSON.stringify({message:"hi"})}) 就能调通。到这里入门就结束了，下面的进阶默认收起，切到「入门 + 进阶」再继续。

02

进阶：从「会写接口」到「会写项目」

目标：能扛住一个真实 Agent 项目的结构，而不是把所有接口堆在 main.py。每节先给最简版，再展开。

2.1 Depends：依赖注入，就是声明式中间件

类比 NestJS / Angular 的 DI。鉴权、拿 DB 连接这类事别在每个接口里手写，声明出来让 FastAPI 帮你跑：

第一步 · 最简版：一个校验 API Key 的依赖

from fastapi import Depends, Header, HTTPException  # Depends 声明依赖；Header 读请求头；HTTPException 主动抛 HTTP 错误

async def verify_api_key(x_api_key: str = Header(...)):  # 这是一个依赖函数：参数从请求头 x-api-key 里取
    # Header(...) 里的 ... 表示必填，没传这个头直接报错
    if x_api_key != "secret-key":  # 和预设的 key 对不上
        raise HTTPException(401, "invalid api key")  # 抛错中断请求，返回 401；raise 相当于 JS 的 throw
    return x_api_key  # 校验通过，把 key 返回出去

@app.post("/chat")  # 路由照常注册
async def chat(req: ChatRequest, _: str = Depends(verify_api_key)):
    # 接口多了一个参数：Depends(verify_api_key) 表示「先跑 verify_api_key，通过了才进函数体」
    # 参数名写 _ 是惯例：表示这个值只是用来触发校验，函数体里不用它
    ...  # ... 是 Python 的占位符，表示这里省略了函数体

第二步 · 带 yield 的依赖：自动清理，相当于 try/finally

def get_db():  # 依赖函数：负责给出一个数据库连接
    db = SessionLocal()  # 先打开一个连接（SessionLocal 是提前配好的连接工厂）
    try:  # try 相当于 JS 的 try，配合下面的 finally 做兜底清理
        yield db  # yield 把连接「借」给接口用；接口跑完后，执行会回到这里继续往下
    finally:  # 不管接口成功还是报错，最后都会执行这里
        db.close()  # 关掉连接，防止连接泄漏

依赖可以嵌套：get_current_user 依赖 verify_token，get_admin 再依赖它，层层复用。

2.2 APIRouter：按业务拆模块

第一步 · 在子文件里定义 router，写法和 app 几乎一样

# routers/chat.py —— 聊天相关的接口单独放一个文件
from fastapi import APIRouter  # APIRouter 是「小号的 app」，专门用来分组

router = APIRouter(prefix="/api/v1/chat", tags=["chat"])
# prefix：这个文件里所有路径自动加前缀 /api/v1/chat，写版本号就改这一处
# tags：文档里分组显示的名字，/docs 里会按它归类

@router.post("/")  # 注意是 @router 不是 @app；实际路径 = 前缀 + "/" = /api/v1/chat/
async def chat(...): ...  # 接口实现和之前一样，这里省略

第二步 · 在 main.py 里组装

# main.py 只做组装，不写具体接口
from routers.chat import router as chat_router  # 导入 chat 模块的 router，起个别名防重名

app.include_router(chat_router)  # 把 chat 的全部路由挂到 app 上
app.include_router(feedback_router)  # 同理挂 feedback 的，路径前缀是 /api/v1/feedback

2.3 Lifespan：启动时加载 Agent，别每次请求都重建

from contextlib import asynccontextmanager  # 导入装饰器，用来定义 lifespan 函数

@asynccontextmanager  # 把下面这个函数变成「启动/关闭管理器」
async def lifespan(app: FastAPI):  # 服务启动时 FastAPI 会调用它
    app.state.agent = build_agent()  # yield 之前是启动逻辑：构建 Agent 只跑这一次，结果挂在 app.state 上全局取用
    print("agent loaded")  # 打条日志确认加载完成
    yield  # yield 是分界线：服务运行期间停在这里，等关服务时继续往下执行
    app.state.agent = None  # yield 之后是关闭逻辑：释放 Agent 等资源

app = FastAPI(lifespan=lifespan)  # 创建 app 时把 lifespan 交给它，启动/关闭就都归它管

老写法 @app.on_event("startup") 已废弃，现在都用 lifespan。接口里取 Agent：agent = req.app.state.agent（需要给接口加一个 Request 参数拿到 app）。

2.4 流式输出：Agent 必须会，不然前端只能干等 10 秒

from fastapi.responses import StreamingResponse  # 流式响应类型，一边生成一边往前端推
import json  # 把 dict 转成 JSON 字符串要用

@app.post("/chat/stream")  # 注册 POST /chat/stream
async def chat_stream(req: ChatRequest):  # 接口函数本身
    async def gen():  # 在接口里定义一个异步生成器：它不 return，而是多次 yield 吐数据
        async for chunk in agent.astream(  # astream 是流式调用：Agent 每产出一块就给一块，相当于 for await
            {"messages": [("user", req.message)]},  # 输入还是同样的消息格式
            config={"configurable": {"thread_id": req.session_id}}  # 用 session_id 续对话
        ):
            msg = chunk.get("agent", {}).get("messages", [None])[-1]  # 从这块状态里安全地取最后一条消息，取不到给 None
            if msg and msg.content:  # 有消息且有文本才往外推
                yield f"data: {json.dumps({'text': msg.content})}\n\n"  # SSE 格式：一行 data: 开头、两个换行结尾，缺一不可
        yield "data: [DONE]\n\n"  # 全部推完后发一个结束标记，前端靠它关流
    return StreamingResponse(gen(), media_type="text/event-stream")  # 把生成器包成流式响应返回，media_type 告诉前端这是事件流

想把工具调用过程也推给前端（显示「正在查知识库…」），用 agent.astream_events()，区分 on_chat_model_stream / on_tool_start / on_tool_end。

2.5 校验、错误、跨域：生产标配三件套

第一步 · 在 1.5 的最简模型上加约束（Field）

from pydantic import BaseModel, Field  # Field 用来给字段加约束和默认值

class ChatRequest(BaseModel):  # 还是那个请求模型
    message: str = Field(..., min_length=1, max_length=4000)
    # Field(...) 的 ... 表示必填；min_length/max_length 限制消息长度，超了直接 422 不用手写 if
    session_id: str | None = Field(None, max_length=64)  # 可选，传了也不能超过 64 字符
    temperature: float = Field(0.7, ge=0, le=2)  # 默认 0.7；ge=0 / le=2 表示必须在 0 到 2 之间

第二步 · 统一错误格式 + 跨域

@app.exception_handler(ValueError)  # 注册异常处理器：接口里抛出 ValueError 时走这里
async def value_error_handler(request: Request, exc: ValueError):  # request 是当前请求，exc 是抛出的异常对象
    return JSONResponse(status_code=400,  # 统一返回 400
        content={"code": "BAD_INPUT", "msg": str(exc)})  # 固定格式 {code, msg}，前端不用猜错误长什么样

# 跨域：前端 localhost:3000 调 localhost:8000，不加直接被浏览器拦
app.add_middleware(CORSMiddleware,  # 给 app 装上跨域中间件
    allow_origins=["http://localhost:3000"],  # 只允许这个前端地址跨域，生产别写 "*"
    allow_credentials=True, allow_methods=["*"], allow_headers=["*"])  # 允许带 Cookie、所有方法和请求头

2.6 异步的坑 + 后台任务

最常见的翻车：在 async def 里直接调同步阻塞代码（同步 DB 驱动、Playwright 同步 API、重计算），会把整个事件循环卡住。要么接口改用 def 让 FastAPI 丢线程池，要么 await run_in_threadpool(sync_func)。
from fastapi import BackgroundTasks  # 后台任务工具：响应返回后再慢慢执行

@app.post("/feedback")  # 注册 POST /feedback
async def submit_feedback(req: Feedback, bg: BackgroundTasks):  # 多声明一个 bg 参数，FastAPI 自动注入
    bg.add_task(save_to_db_and_index, req)  # 把「写库 + 建索引」登记为后台任务，接口不等它
    return {"status": "accepted"}  # 立刻返回，任务在响应发出后执行

注意：BackgroundTasks 只适合丢了无所谓的活，重要的批量任务要上队列——那是第 03 章 3.5 的内容。

03

高级：敢把它放到生产上

以「日均 10 万条反馈 + Agent 分析 + 对接 TAPD」这种量级为例，这 7 块是落地和面试都会被追问的。没到做生产系统的阶段可以先跳过。

3.1 分层架构：接口里别写业务逻辑

# routers/chat.py 只做翻译：HTTP <-> Service
@router.post("/chat")  # 路由层只负责收请求、发响应
async def chat(req: ChatRequest, svc: ChatService = Depends(get_chat_service)):
    # svc 是通过依赖注入拿到的业务服务，接口自己不 new、也不写业务
    return await svc.ask(req.message, req.session_id)  # 转手交给 Service，拿到结果直接返回
# services/chat.py 纯业务，不认识 FastAPI，可以脱离 HTTP 单测
# repositories/feedback_repo.py 只管 SQL，业务层不直接拼查询

测试时用依赖覆盖，不用真起数据库：app.dependency_overrides[get_db] = lambda: fake_db（lambda 是 Python 的匿名函数，相当于 JS 的箭头函数 () => fake_db）。面试点：Depends 默认缓存，同请求多次依赖同一函数只跑一次；想每次都跑加 use_cache=False。

3.2 异步数据库 + 连接池 + LLM 并发限流

engine = create_async_engine("postgresql+asyncpg://...",  # 创建异步数据库引擎；asyncpg 是 PostgreSQL 的异步驱动
    pool_size=20, max_overflow=10, pool_pre_ping=True)  # 连接池：常备 20 条、最多再借 10 条；pre_ping 是用之前先探活，防拿到死连接
async_session = async_sessionmaker(engine, expire_on_commit=False)  # 造一个会话工厂；expire_on_commit=False 表示提交后对象还能读，不用再查一次

async def get_db():  # 依赖函数：每个请求给一个会话
    async with async_session() as session:  # async with 是「用完自动关」的语法，相当于 JS 的 using / try-finally
        yield session  # 把会话借给接口，请求结束自动回收

llm_sem = asyncio.Semaphore(10)  # 信号量：全局最多 10 个并发调模型，防打爆上游限速
async with llm_sem:  # 进这个块前先抢名额，抢不到就排队等
    result = await agent.ainvoke(...)  # 名额内才真正调模型

3.3 安全：JWT + Scope + 产品隔离

一个真实教训：权限只在 UI 层做了、检索层没过滤，用户就能查到别的产品的数据。正确做法是鉴权在依赖层做一次，数据隔离在 Repository 层强制带条件，接口层不信任前端传来的 product_id：

oauth2 = OAuth2PasswordBearer(tokenUrl="/auth/token")  # 声明 token 从哪个接口发、请求时从 Authorization 头里取

async def get_current_user(security_scopes: SecurityScopes,  # security_scopes 是 FastAPI 注入的：这个接口要求哪些权限
                           token: str = Depends(oauth2)):  # 先通过 oauth2 依赖把 token 字符串拿出来
    payload = decode_jwt(token)  # 解码并验签，得到 {user_id, product_ids, scopes}；验不过这里就抛错了
    if "feedback:read" not in payload["scopes"]:  # 要求的权限不在 token 里
        raise HTTPException(403, "scope 不足")  # 返回 403：身份没问题，但权限不够
    return payload  # 校验通过，把用户信息交给接口

@router.get("/feedback")  # 注册 GET /feedback
async def list_feedback(product_id: str,  # 前端传来的产品 ID——注意：只能当「想查哪个」，不能当「有权查」
    user = Security(get_current_user, scopes=["feedback:read"])):  # Security = 带权限要求的 Depends
    if product_id not in user["product_ids"]:  # 拿 token 里的授权列表对一遍
        raise HTTPException(403, "无权访问该产品")  # 不在授权范围内直接 403
    # 往下所有查询都必须带 product_id 条件，Repository 层再强制加一遍，双保险

3.4 幂等 + 限流 + 超时：有副作用的操作必备

# 幂等：TAPD 建单不能因为前端重试就建两张
async def check_idempotency(key: str = Header(..., alias="Idempotency-Key")):  # 从请求头 Idempotency-Key 取客户端生成的唯一 key
    if await redis.set(key, "1", nx=True, ex=86400):  # nx=True 表示「key 不存在才写入」；ex=86400 是一天后过期
        return key  # 写入成功 = 第一次提交，放行
    raise HTTPException(409, "重复提交")  # 写不进去 = 这个 key 用过了，按重复提交处理

# 限流：Redis 原子计数，每 IP 每分钟 60 次
count = await redis.incr(f"rl:{client_ip}")  # incr 是原子自增，多实例并发也不会数错
if count == 1: await redis.expire(f"rl:{client_ip}", 60)  # 第一次计数时给 key 设 60 秒过期，窗口自动重置
if count > 60: raise HTTPException(429, "too many requests")  # 超限返回 429

# 超时：LLM 调用必须有上限，别让慢请求占住连接
async with asyncio.timeout(30):  # 30 秒内没跑完就抛 TimeoutError
    result = await agent.ainvoke(...)  # 在超时保护下调模型

3.5 任务队列：BackgroundTasks 扛不住大批量

BackgroundTasks 只在当前进程、请求结束后跑，服务一重启任务就丢。日均 10 万条的正确分工：接口只做校验 + 落库 + 推任务马上返回 202 Accepted，Worker 另起进程做清洗、脱敏、切分、建索引、调 TAPD，前端用 GET /jobs/{job_id} 轮询状态。

@app.post("/feedback/batch", status_code=202)  # status_code=202 表示「已受理，还没处理完」
async def ingest_batch(items: list[FeedbackItem]):  # 一次收一批反馈，list[FeedbackItem] 相当于 TS 的 FeedbackItem[]
    job_id = await enqueue_index_job(items)  # 只把任务推到队列（Redis Stream / ARQ / Celery），重的活不在这里做
    return {"job_id": job_id, "status": "queued"}  # 立刻返回 job_id，前端拿它轮询处理状态

3.6 可观测性 + 健康检查

  • 统一日志：自定义 APIRoute 记录 request_id、路径、耗时、状态码，Trace ID 一路透传到 LangSmith，Agent 每一步工具调用都能对上一次 HTTP 请求。
  • GET /healthz：进程活着就 200（存活探针）。
  • GET /readyz：DB、Redis、模型都连通才 200，否则 503 不接流量（就绪探针）。
  • 再往上：OpenTelemetry + Prometheus 看指标和链路。

3.7 WebSocket vs SSE + 部署

SSE 是单向推，够用但前端不能中途打断。需要双向交互（用户中途说「停」、Agent 中途问「确认吗」）用 WebSocket，注意断开时清理 LangGraph checkpoint、并做心跳——Agent 跑 2 分钟没输出，网关会以为连接死了。

@app.websocket("/ws/chat")  # 注册 WebSocket 路由，写法和普通路由一样换个装饰器
async def ws_chat(ws: WebSocket):  # ws 是这条长连接本身
    await ws.accept()  # 先接受连接，不 accept 前端会一直等待
    try:  # 用 try 包住整个收发循环，专门接下面的断开异常
        while True:  # 长连接就是一个死循环：收一条、处理一条
            data = await ws.receive_json()  # 等前端发消息（前端随时能发「取消」）
            async for event in agent.astream_events(data["message"], version="v2"):  # 订阅 Agent 的事件流
                if event["event"] == "on_chat_model_stream":  # 是模型吐 token 的事件
                    await ws.send_json({"type":"token",  # 按 {type, text} 的约定格式推给前端
                      "text": event["data"]["chunk"].content})  # chunk 里就是这一小段增量文本
    except WebSocketDisconnect:  # 前端断开会抛这个异常，在这里收尾
        pass  # pass 是空占位；实际要在这里清理 checkpoint，别留僵尸任务
部署一句话：单进程 uvicorn main:app 只适合开发；生产用 gunicorn -k uvicorn.workers.UvicornWorker -w 4。每个 worker 有自己的连接池和 Agent 实例，Agent 占内存时 worker 数别贪多，先压测再定。推荐骨架：main.py 只组装（lifespan + CORS + include_router），routers/ 放接口，deps.py 放鉴权和 DB，services/ 放业务和 Agent。

技巧速查：12 个实战小招

都是日常最顺手的写法，看到哪条有用直接抄。注释同样可以一键开关。

1 · Annotated 起别名

CurrentUser = Annotated[dict, Depends(get_current_user)]  # 把「类型 + 依赖」打包成一个别名
@app.get("/me")  # 之后每个接口只写参数类型 CurrentUser 就行
async def me(user: CurrentUser): ...  # user 就是校验后的当前用户

鉴权不用每行写一长串。

2 · 整个 Router 一起鉴权

router = APIRouter(prefix="/admin",  # 管理类接口单独一个 router
  dependencies=[Depends(require_admin)])  # dependencies 挂在 router 上：下面所有接口先过这一关

不用每个接口单独加。

3 · Enum 做查询参数

class Sort(str, Enum):  # 定义枚举：值只能是这几个之一
    newest = "newest"; hottest = "hottest"  # 分号在一行里分隔两句，平时代码别这么写，这里为省行数
def list_items(sort: Sort = Sort.newest): ...  # 默认 newest；传别的值直接 422

文档自动变下拉框，传错值直接 422。

4 · 多值查询用 list

def list_items(tags: list[str] = Query(default=[])): ...  # 声明成 list，FastAPI 自动收集重复参数
# ?tag=a&tag=b 直接拿到 ["a","b"]，不用自己 split

5 · response_model 藏字段

@app.get("/users/{id}", response_model=UserOut,  # 用 UserOut 决定输出结构，没声明的字段不返回
  response_model_exclude_none=True)  # 值为 None 的字段直接省略，前端不用判空

密码哈希、内部 ID 不漏出去。

6 · 换 ORJSON 提速

app = FastAPI(default_response_class=ORJSONResponse)  # 创建 app 时换掉默认的 JSON 序列化器
# pip install orjson 就行，别的代码不用改

还能直接返回 datetime / UUID。

7 · 生产关文档

is_prod = os.getenv("ENV") == "prod"  # 读环境变量判断是不是生产
app = FastAPI(docs_url=None if is_prod else "/docs")  # 生产把 /docs 关掉；a if cond else b 是 Python 的条件表达式
# 单个接口隐藏：给装饰器加 include_in_schema=False

8 · 校验报错改中文

@app.exception_handler(RequestValidationError)  # 专门接校验失败异常
async def validation_handler(request, exc):  # exc 里是 Pydantic 的详细错误列表
    return JSONResponse(422, {"msg": "参数不对",  # 固定返回 422 + 一句人话
      "errors": [{"field": ".".join(map(str, e["loc"][1:])),  # 把错误路径拼成 a.b.c 的字段名
                   "msg": e["msg"]} for e in exc.errors()]})  # 这一整行是列表推导式，相当于 JS 的 exc.errors().map(e => ...)

9 · 分页参数收成一个类

class Pagination:  # 把分页参数收成一个类，到处复用
    def __init__(self, skip: int = 0,  # 构造函数：skip 默认 0
                 limit: int = Query(20, le=100)):  # limit 默认 20、最大 100，Query 在这里限定它来自查询参数
        self.skip, self.limit = skip, limit  # 存到自己身上；一行给两个字段赋值
def list_items(p: Pagination = Depends()): ...  # 接口里 Depends() 一下就拿到分页对象

10 · 大文件分块写

async with aiofiles.open(path, "wb") as f:  # 异步打开文件，用完自动关
    while chunk := await file.read(1024*1024):  # 每次读 1MB；:= 是「赋值并判断」一体的海象运算符，读到空就是读完
        await f.write(chunk)  # 读一块写一块，内存里永远只有 1MB

别 await file.read() 一次读完，会吃爆内存。

11 · Response 设 Cookie / Header

def login(response: Response):  # 多声明一个 Response 参数，FastAPI 会把响应对象给你
    response.set_cookie("token", "xxx",  # 往响应里种 Cookie
      httponly=True, samesite="lax")  # httponly 让 JS 读不到这个 Cookie，防 XSS 偷 token
    return {"ok": True}  # 返回值还是照常写，Cookie 会自动带上

12 · 测试要用 with 触发 lifespan

with TestClient(app) as client:  # with 块里才会触发 lifespan 加载 Agent；with 相当于「进入时启动、退出时清理」
    r = client.post("/chat", json={"message": "hi"})  # 在块里正常发请求测接口

另记：Depends 默认缓存，use_cache=False 才每次重跑。

术语速查（一句人话版）

Pydantic

数据校验库。你写一个带类型的类，它负责检查进来的数据合不合格，FastAPI 的校验和文档都靠它。

装饰器

写在函数头顶、@ 开头的那行。作用是把函数交给另一个函数「登记或加工」一下，路由注册就是这么做的。

Depends（依赖注入）

把接口需要的前置工作（鉴权、拿 DB 连接）声明在参数上，FastAPI 在调接口前自动先跑好递给你，不用每个接口手写。

ASGI / uvicorn

ASGI 是 Python 异步服务的接口规范（相当于 Node 里 server 的约定）；uvicorn 是按这个规范真正监听端口、跑起 app 的服务器。

lifespan

服务的「开机和关机流程」：开机时加载 Agent、建连接池，关机时清理。写成一个函数，中间用 yield 分隔开、关两段。

序列化

把 Python 对象（dict、模型、datetime）转成能发给前端的 JSON 文本的过程；反过来解析请求 JSON 是反序列化。

幂等

同一个操作执行一次和执行多次，结果一样。比如建单接口带幂等 key，前端重试多少次都只会建出一张单。

SSE

Server-Sent Events：服务器单向往前端推数据的长连接方式，格式就是一行行 data: ...，打字机式输出用的就是它。

Scope（权限范围）

token 里带着的权限清单，比如 feedback:read。接口声明自己需要哪个 scope，token 里没有就返回 403。

checkpointer / thread_id

LangGraph 存对话状态的机制：thread_id 标示是哪一段对话，checkpointer 负责把每步状态存到 Redis / DB，换个进程也能续上。
