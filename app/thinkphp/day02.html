Day 2：一次请求经历了什么：请求生命周期

面试最爱问的一道题：“一个请求进来，ThinkPHP 内部发生了什么？” 这道题答好了，面试官基本就认定你“真用过框架，而不是只会写控制器”。今天把这条主线从入口文件一路讲到响应发送：入口引导 → App 初始化 → 路由匹配 → 中间件洋葱模型 → 控制器调度 → 响应发送，顺带讲清 PHP-FPM 同步模型这个常考点。

一、核心解释

1. 主线：十步走完一次请求

先记住这条主线，面试时按这个顺序说，一步都不要跳：

入口引导 → Composer 自动加载 → App 初始化（路径、配置、环境变量 .env、服务注册）→ Http::run → 路由匹配 → 中间件管道（洋葱模型）→ 控制器调度（反射 + 依赖注入）→ 响应生成与发送 → HttpEnd 收尾。

其中 App 初始化做的四件事最常被追问：定路径（应用根目录、运行时目录等）、加载配置（config/ 目录）、读环境变量（.env）、注册服务（把路由、日志、数据库等服务放进容器）。

2. 入口文件：只有 6 行

所有 Web 请求都从 public/index.php 进来，标准骨架只有 6 行有效代码（完整逐行注释见第二节）：先 require Composer 自动加载文件，再 new App() 创建应用实例并取出 http 对象，$http->run() 跑完整条链路并返回 Response，$response->send() 把响应发给浏览器，最后 $http->end($response) 做收尾。入口文件越薄越好——业务逻辑一律不写在这里。

3. 关键类速查表

类职责
think\App应用实例：初始化路径、配置、环境变量、服务注册，是整个请求的“总管”
think\Http请求处理入口：run() 跑链路、end() 收尾
think\Route路由：把 URL 匹配到控制器和方法
think\Middleware中间件管理：组织洋葱管道
think\Request请求对象：参数、请求头、Cookie 的统一读取口
think\Response响应对象：内容、状态码、响应头的统一发送口
think\Container容器：管理对象创建与依赖注入，App 就是它的子类

面试答法：“入口 new App() 初始化，Http::run 驱动链路，Route 匹配，Middleware 组织洋葱管道，控制器由容器通过反射 + 依赖注入调度，最后 Response 发送、HttpEnd 收尾。” 能把这七个类各说一句话，这道题就稳了。

4. 中间件：洋葱模型

中间件管道是标准的洋葱模型：请求从最外层中间件一层层向内穿，到达控制器后再一层层向外返回。先注册的中间件，先处理请求、后处理响应。典型用法：外层放日志、跨域，内层放鉴权、限流。Koa、Express 也是同一模型——你在 JS 里理解的 next() 放行机制，原封不动搬过来。

5. 内置事件：三个钩子点

框架在生命周期里预埋了三个事件，业务可以在这些点挂监听：AppInit（应用初始化完成时）、HttpRun（请求开始运行时）、HttpEnd（请求结束收尾时）。事件定义在 app/event.php。面试答法：“事件是框架留给业务的钩子，比如在 HttpEnd 里记请求日志、在 AppInit 里做自定义初始化，不用改框架代码。”

6. PHP-FPM 同步模型：面试常考点

这是 PHP 与 Node 最本质的区别，面试官很爱追问：PHP-FPM 是同步模型，每个请求都从干净状态启动，请求结束即销毁对象与静态属性。配置要重新加载、容器要重新创建、静态属性不会带到下一个请求。好处是请求之间天然隔离、不用担心状态污染；代价是每次请求都有重复的初始化开销（所以才有路由缓存、配置缓存这类优化手段）。而 Node 是常驻进程：启动一次，服务多个请求，内存里的状态会一直留着。

容易踩的坑：不要把状态存在静态属性或全局变量里，指望它跨请求共享——请求一结束就全销毁了。需要跨请求共享的东西（登录态、计数器）要放 Redis、数据库或 Session 里。反过来也别在 Node 思维下写 TP 代码：TP 里没有“启动时初始化一次、一直复用”这回事。

二、代码示例

示例 1：入口 public/index.php 标准骨架（逐行注释）

<?php
namespace think;

// Composer 自动加载：按 PSR-4 把类名映射到文件，之后 new App() 才能找到类
// __DIR__ 是当前文件所在目录，相当于 Node 里的 __dirname
require __DIR__ . '/../vendor/autoload.php';

// new App() 创建应用实例（内部做初始化：路径、配置、.env、服务注册）
// ->http 取出 Http 对象：-> 相当于 JS 的 .，就是访问对象属性
$http = (new App())->http;

// run() 跑完整条链路：路由匹配 → 中间件 → 控制器调度，返回 Response 对象
$response = $http->run();

// 把响应头与内容真正发给浏览器
$response->send();

// 收尾：触发 HttpEnd 事件，做日志、清理等扫尾工作
$http->end($response);

示例 2：洋葱模型最小演示（纯 PHP，不依赖框架，直接 php onion.php 可跑）

<?php
// 用闭包嵌套演示"先进后出"：$next 相当于 Express/Koa 的 next()
// 调用 $next() 才放行到下一层；不调用，请求就卡在这一层

function layer($name, $next)
{
    echo "进入 {$name}\n";  // 请求进来时执行（{$name} 插值 ≈ JS 模板字符串 ${name}）
    $next();                // 放行到下一层
    echo "离开 {$name}\n";  // 响应出去时执行
}

// 从内向外包三层：最内层是控制器，外面依次是鉴权、日志
// use ($app) 是 PHP 闭包捕获外层变量的写法——PHP 闭包默认不捕获，必须显式 use
// JS 闭包自动捕获，PHP 必须写 use，这是 JS 转 PHP 最容易写错的一点
$app = function () {
    echo "控制器：处理业务\n";
};
$app = function () use ($app) { layer('鉴权', $app); };
$app = function () use ($app) { layer('日志', $app); };

$app();
// 输出：
// 进入 日志
// 进入 鉴权
// 控制器：处理业务
// 离开 鉴权
// 离开 日志

看输出就懂洋葱模型：日志先注册，所以最先“进入”、最后“离开”；控制器在最中心，只执行一次。

动手任务（10 分钟）

1. 把示例 2 存成 onion.php 跑一遍，确认输出顺序；再加一层“限流”包在鉴权外面，预测输出顺序再验证。
2. 把示例 2 里某层的 $next() 注释掉再跑——控制器还执行吗？这就是中间件“拦截请求”的本质（比如鉴权失败直接返回 401，不放行）。
3. 打开 Day 1 建的 tp 项目的 public/index.php，对照示例 1 逐行读一遍，确认和骨架一致。

三、ThinkJS 对比

ThinkJS 的请求流程和 TP 高度同构，只是跑在 Node 常驻进程上：

环节ThinkPHPThinkJS
入口public/index.php，每请求启动一次development.js / production.js 启动 Koa 应用，启动一次服务多个请求
应用实例think\Appthink.app 就是 Koa Application 实例
中间件洋葱管道（think\Middleware）中间件洋葱圈；ThinkJS 3.0 执行完全由中间件驱动
路由think\Route 匹配路由解析 /controller/action
校验层验证器（后续课讲）Logic 层（参数校验）
执行控制器调度（反射 + 依赖注入）Controller Action 执行
响应Response->send()ctx.body 返回
进程模型PHP-FPM 同步：每请求干净启动、结束销毁Node 常驻进程：内存状态跨请求保留

面试加分句：“两者的链路几乎一样：入口 → 中间件洋葱圈 → 路由 → 控制器 → 响应。最大区别是进程模型：TP 每个请求都是全新初始化，天然隔离但有重复开销；ThinkJS 常驻进程，状态能复用但要自己管内存泄漏和状态污染。”

四、小测验（点选项判分，答完点解析）

得分：0 / 3

1. ThinkPHP 的唯一 Web 入口文件是？

解析：选 B。public/index.php 是唯一 Web 入口；think 是命令行入口，不走 Web 请求。

2. PHP-FPM 同步模型下，请求结束后静态属性会怎样？

解析：选 B。每个请求从干净状态启动、结束即销毁，这是 PHP 与 Node 常驻进程最本质的区别。

3. 中间件洋葱模型中，先注册的中间件是？

解析：选 A。先注册的在最外层：请求进来时最先碰到它，响应出去时最后经过它——先进后出。

五、面试高频问答

Q1：说一下 ThinkPHP 一次请求的完整生命周期。

入口 public/index.php 引导 → Composer 自动加载 → App 初始化（路径、配置、.env、服务注册）→ Http::run → 路由匹配 → 中间件管道（洋葱模型）→ 控制器调度（反射 + 依赖注入）→ 响应生成与发送 → HttpEnd 收尾。按这个顺序说，一步不要跳。

Q2：App 初始化具体做了哪几件事？

四件：定路径（应用根目录、运行时目录等）、加载配置（config/ 目录）、读环境变量（.env）、注册服务（把路由、日志、数据库等服务放进容器）。

Q3：入口文件 public/index.php 里有什么？

只有 6 行有效代码：require Composer 自动加载、new App() 并取出 http 对象、$http->run() 跑链路返回 Response、$response->send() 发送、$http->end($response) 收尾。入口越薄越好，业务逻辑不写在这里。

Q4：PHP-FPM 模型和 Node 常驻进程有什么区别？对写代码有什么影响？

PHP-FPM 每个请求从干净状态启动，请求结束即销毁对象与静态属性：好处是请求间天然隔离、不用担心状态污染；代价是每次请求都有重复初始化开销。Node 常驻进程启动一次服务多个请求，内存状态跨请求保留，性能好但要自己管状态污染和内存泄漏。写 TP 代码时不要指望静态属性跨请求共享，跨请求状态放 Redis、数据库或 Session。

Q5：中间件洋葱模型是什么意思？中间件和事件有什么区别？

洋葱模型指请求从最外层中间件一层层向内穿、响应再一层层向外返回，先注册的先处理请求、后处理响应。中间件是在请求链路中途拦截和加工（鉴权、日志、限流）；事件是框架在生命周期特定点（AppInit、HttpRun、HttpEnd）留给业务的钩子，不在请求主链路上做拦截。

六、加分项

简历讲法：别写“熟悉 ThinkPHP 生命周期”，写“能讲清 TP 请求全链路：入口引导 → App 初始化（配置/.env/服务注册）→ 路由匹配 → 中间件洋葱管道 → 容器反射 + 依赖注入调度控制器 → 响应发送与 HttpEnd 收尾；理解 PHP-FPM 每请求干净启动的模型，知道静态属性不能跨请求共享”。前者是名词，后者是可追问的理解。
