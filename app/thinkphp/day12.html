Day 12：ThinkPHP vs ThinkJS 全面对比 + 面试串讲

最后一课做两件事：第一，把 ThinkPHP 和 ThinkJS 并排放在一张表里——这两个框架不是偶然长得像，ThinkJS 从一开始就是照着 ThinkPHP 的设计思想做的；第二，把 12 课的面试高频问答串讲一遍，面试前照着这份清单过一遍，心里就有底。读完这课，这门课的“知识地图”就完整了，剩下的就是动手写一个项目，把知识变成手感。

一、核心解释

1. 渊源：ThinkJS 是照着 ThinkPHP 的设计思想做的

ThinkJS 的作者是李成银（@welefen），360 奇舞团成员。他在 2013 年下半年开始做 ThinkJS 时，参考了 ThinkPHP——多处资料都确认了这一点：“ThinkJS 很多特性来源于 ThinkPHP”、“借鉴了 ThinkPHP 的设计思想”。所以你在前面 11 课里反复看到的相似点（MVC 分层、中间件、模型、配置分层）不是巧合，是有意的传承：作者想给 Node.js 做一个像 ThinkPHP 一样好用的 MVC 框架。

版本线记三个节点就够了：ThinkJS v2.0 在 2015 年 10 月发布（基于 ES2015+）；v3.0 在 2017 年 10 月发布，核心基于 Koa 2.x，兼容全部 Koa 特性与中间件；3.2 起支持 TypeScript。本课只说 ThinkJS 3.x 线。

面试答法：“ThinkJS 作者李成银在 2013 年做 ThinkJS 时参考了 ThinkPHP 的设计思想，所以两者在 MVC 分层、中间件、模型这些概念上高度相似；v3.0 起核心基于 Koa 2.x，兼容 Koa 中间件，3.2 起支持 TypeScript。最大的不同不在 API 形状，而在运行时：PHP 同步阻塞、每请求重建，Node 异步非阻塞、常驻进程。”

这张表怎么记？抓住三条主线就够了：① 运行时不同（同步阻塞 vs 异步非阻塞、每请求重建 vs 常驻进程）——这是所有差异的根；② 形态相似（路由、控制器、中间件、模型、配置、缓存、会话，概念几乎一一对应）——这是 ThinkJS 借鉴 ThinkPHP 的直接证据；③ 生态不同（TP 背靠国内大 PHP 生态，ThinkJS 小众，队列、模板这些能力更多依赖 npm 通用生态而不是框架自带扩展）。

容易踩的坑：面试时不要说“ThinkJS 就是 Node 版的 ThinkPHP”。概念上像，但运行时、进程模型、异步模型完全不同——常驻进程的跨请求状态污染、异步错误处理，都是 PHP 里不存在的问题。说“设计思想同源、运行时不同”，比说“就是同一个东西”准确得多。

二、代码示例

示例：同一个功能——“取用户列表”，两种写法对照

下面是同一个接口在两个框架里的骨架写法。注意对照的点：路由怎么定义、控制器长什么样、请求参数怎么取、数据怎么查。

<?php
// ThinkPHP 写法
// 路由：route/app.php 里用 Route 门面注册
// Route::get('user/list', 'User/list');

// 控制器：app/controller/User.php，继承 BaseController
namespace app\controller;

use think\Request;
use think\facade\Db;

class User extends BaseController
{
    // 方法参数由容器自动注入 Request 实例（Day 10）
    public function list(Request $request)
    {
        $page = $request->param('page', 1); // param 取请求参数，第二个参数是默认值
        // Db 门面查库：静态调用转发给容器里的数据库服务实例
        $users = Db::name('user')->page($page, 10)->select();
        return json($users); // json() 助手返回 JSON 响应
    }
}
// ThinkJS 写法
// 路由：约定 /user/list 直接对应 user 控制器 + listAction，
// 也可以在 src/config/router.js 里自定义映射。

// 控制器：src/controller/user.js，继承 think.Controller
module.exports = class extends think.Controller {
  // 方法名以 Action 结尾：listAction 对应 /user/list
  async listAction() {
    // this.get() 取 GET 参数，this.post() 取 POST 参数
    const page = this.get('page') || 1;
    // think-model 查库：this.model('user') 取 user 模型
    const users = await this.model('user').page(page, 10).select();
    return this.json(users); // this.json 返回 JSON 响应
  }
};

对照着看，四个对应关系一目了然：Route::get 注册路由 vs 约定 /controller/action；BaseController + 普通方法 vs think.Controller + XxxAction；$request->param() vs this.get() / this.post()；Db::name() vs this.model()。形状几乎一样，差别只在语言习惯（PHP 同步写法 vs JS 的 async/await）。

三、ThinkJS 对比：概念迁移表（给 JS 开发者的锚点）

你是 JS/TS 开发者，学 ThinkPHP 最快的方法是“锚定已知概念”。下面这张表把 TP 的核心概念映射到你熟悉的 JS 生态——面试时如果一时想不起 TP 的术语，先说 JS 里的对应物，再说 TP 里叫什么，面试官立刻就懂你掌握到什么程度。

ThinkPHP 概念JS 生态对应物备注
TP 路由Koa Router / express router都是“方法 + 路径 → 处理函数”的映射
TP 中间件Koa 中间件洋葱模型，$next 相当于 Koa 的 next()
TP 容器NestJS DI / Awilix / Inversify都是依赖注入容器，反射或装饰器解析依赖
TP 门面静态代理（JS 无直接对应物）近似于单例导出：export default new Cache() 后处处 import 同一个实例
TP ModelPrisma / TypeORM / Sequelize都是 ORM：模型类对应表，关联、预载、查询构建器概念相通
TP Validatezod / joi都是声明式校验：定义规则，框架负责跑校验、返回错误
TP Cachenode-cache / ioredisfile 驱动对应进程内缓存，redis 驱动对应 ioredis
TP 队列BullMQ都是把耗时任务丢进队列异步执行
TP Sessionkoa-session都是服务端会话，生产用 Redis 存

唯一没有直接对应物的是门面。JS 里没有 __callStatic 这种魔术方法，也就没有“静态调用转发给实例”这套惯用法。最接近的形态是单例导出：一个模块 export default new CacheService()，各处 import 进来用的是同一个实例——调用形态简洁、依赖被隐藏，这两点和门面的优缺点恰好一致。面试时说出这句类比，能说明你不是在背概念，而是真的理解了机制。

四、小测验（综合卷）

得分：0 / 6

1. ThinkPHP 与 ThinkJS 在进程模型上的根本差异是？

解析：选 C。PHP-FPM 每次请求拉起应用、跑完销毁；Node 应用由 PM2 常驻内存。常驻进程要注意跨请求状态污染，PHP 每次请求干净启动，天然没有这个问题。

2. ThinkJS 的渊源，哪个说法正确？

解析：选 A。ThinkJS 作者李成银（@welefen，360 奇舞团），2013 年下半年开始 ThinkJS 时参考 ThinkPHP；多处资料确认“ThinkJS 很多特性来源于 ThinkPHP”。它不是 TP 官方产品。

3. TP 的门面在 JS 生态里最接近什么？

解析：选 B。JS 没有 __callStatic 这种魔术方法，门面无直接对应物；最接近的是单例导出——调用简洁、依赖被隐藏，优缺点和门面一致。

4. TP 8.x 线相对 TP6 的变化，以下哪项正确？

解析：选 B。TP8 相对 TP6：注解路由剥离为 think-annotation 扩展，PHP 版本要求提到 8.0+。多应用仍由 think-multi-app 扩展提供。

5. 关于缓存穿透、击穿、雪崩，哪个说法正确？

解析：选 C。穿透：查不存在的数据，缓存和库里都没有；击穿：单个热点 key 过期，大量并发直击数据库；雪崩：大批量 key 集中过期。三个是不同的问题，应对方法也不同。

6. 避免模型关联 N+1 查询，TP 里正确的做法是？

解析：选 A。N+1 是指查 N 条主数据又触发 N 次关联查询；with 预载让框架用一次额外的查询把关联数据批量取回，是标准解法。

五、面试高频问答（串讲）

Q1：说说 ThinkPHP 一次请求的生命周期。

入口 public/index.php 创建应用（think\App，本身也是容器）并运行；应用注册服务、加载配置；路由匹配到控制器和方法；请求穿过中间件（全局、应用、路由、控制器四级）；容器用反射解析控制器方法参数并自动注入（如 Request 实例）；执行控制器方法返回响应；中间件后置逻辑执行后响应发出。PHP-FPM 下整个过程每次请求重建，请求结束即销毁。

Q2：中间件有哪几级？执行顺序是怎样的？

四级：全局中间件、应用中间件、路由中间件、控制器中间件。执行顺序由外到内：全局最先、控制器最近，形态是洋葱模型——请求一层层向内穿过 handle($request, $next)，$next($request) 之后的代码在响应返回时由内向外执行。面试追问“鉴权放哪一级”：全站鉴权放全局，某个应用独有的放应用级，个别路由的放路由级。

Q3：门面是怎么实现的？有什么优缺点？

think\Facade 通过 __callStatic 把静态调用转发给容器里的实例，子类用 getFacadeClass() 返回服务类名。门面是静态代理，不是真正的静态类，实例仍由容器管理。优点是调用简洁，缺点是隐藏依赖、测试时要通过容器替换实例。

Q4：容器是怎么做依赖注入的？

容器通过 PHP 反射读取构造函数或方法参数的类型提示，递归实例化依赖，再注入目标对象。控制器方法参数、中间件、命令、事件监听都靠这套机制自动装配。类定义了静态 __make(App $app, ...) 时容器优先调用它（如 think\Middleware::__make 从配置加载中间件）；$app->invoke() 用反射调用任意可调用对象并自动注入参数。

Q5：模型关联与 N+1 问题怎么解决？

模型关联描述表与表的关系（如用户与订单的一对多）。N+1 是指查出 N 条主数据后，每条又单独触发一次关联查询，总共 N+1 次查询。解法是 with 预载：告诉框架提前用一次批量查询把关联数据取回来。面试时可以补一句：预载之外，查询字段加索引、只取需要的字段也是常规优化。

Q6：事务一般怎么写？

涉及多步写操作要保证要么全成功、要么全回滚时就用事务。常用两种写法：闭包式（把一组操作包进事务闭包，闭包内抛异常自动回滚、正常结束自动提交）和手动式（开启事务、执行操作、成功提交、异常回滚）。注意事务里不要放远程调用、发邮件这类不可回滚的操作，耗时任务放队列里做。

Q7：验证器的 scene 场景是解决什么问题的？

同一个模型在不同场景下校验规则不同：比如注册时密码必填，修改资料时密码可不填。Validate 验证器用 scene 定义场景，每个场景指定用哪些规则，调用时选场景即可，不用为每个场景写一个验证器类。ThinkJS 里对应的校验放在 Logic 层，用 __before 做前置校验。

Q8：缓存穿透、击穿、雪崩分别是什么？怎么应对？

这三个是缓存通用概念，不只针对 TP。穿透：请求不存在的数据，缓存和数据库里都没有，每次都打到库；应对是缓存空值（短过期）或用布隆过滤器拦截。击穿：单个热点 key 过期瞬间，大量并发请求直击数据库；应对是热点 key 永不过期加后台刷新，或用互斥锁让一个请求重建缓存。雪崩：大批量 key 在同一时间过期，请求洪峰打垮数据库；应对是过期时间加随机抖动、热点数据预热、多级缓存。

Q9：多应用怎么判断？部署多应用有什么坑？

系统以 app/controller 目录是否存在作为判断单应用的依据；部署多应用后必须删除它，否则框架仍按单应用走。多应用通过 think-multi-app 扩展实现，app/ 下每个子目录是一个应用，各有独立的 config、route、middleware.php、event.php；config/app.php 的 app_map 做应用映射，domain_bind 做域名绑定。

Q10：TP8 与 TP6 有哪些差异？ThinkJS 和 TP 有什么同与不同？

TP8 相对 TP6：注解路由剥离为 think-annotation 扩展（核心更精简、能力按需安装），PHP 版本要求提到 8.0+。ThinkJS 与 TP 的同：设计思想同源——作者李成银做 ThinkJS 时参考了 ThinkPHP，MVC 分层、路由、中间件、模型、配置这些概念高度相似；不同：运行时根本不同，TP 是 PHP 8.0+ 同步阻塞、PHP-FPM 每请求重建，ThinkJS 是 Node 异步非阻塞、常驻进程（要注意跨请求状态污染），v3.0 核心基于 Koa 2.x，3.2 起支持 TypeScript；生态上 TP 背靠国内大 PHP 生态，ThinkJS 小众。

六、加分项

结课：动手项目建议。课程学完，知识还在纸上。建议动手做一个对照项目，把 12 课的内容变成手感：

1. 用 TP8 写一个 API 后台：带登录（Session 或 token）、一套完整 CRUD（用模型关联 + with 预载，刻意避开 N+1）、队列发邮件（think-queue 扩展，注册成功后异步发欢迎邮件）。部署时按 Day 11 的清单走一遍：Nginx root 指向 public、关调试、跑三个 optimize 缓存命令。

2. 再用 ThinkJS 写同款：同样的登录、CRUD、队列发邮件（队列用 npm 生态的 bull 等）。写完对照差异：路由约定 vs Route 门面、XxxAction vs 普通方法、this.get vs $request->param、PM2 常驻 vs PHP-FPM 每请求重建。亲手写过一次，对比表的每一行就都有了体感。

3. 面试前过一遍：把 12 课的面试问答从头过一遍，重点是 Day 12 第五节的 10 条串讲——能不看答案说出要点，就算准备好了。祝面试顺利。
