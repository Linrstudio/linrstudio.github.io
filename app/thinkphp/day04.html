Day 4：控制器与请求响应

Day 2 讲了请求生命周期，Day 3 讲了路由怎么把 URL 映射到“某个控制器、某个操作”。今天就落到这个“某个”上：控制器长什么样、请求参数怎么拿、响应怎么回。这是面试里最常被追问的一层——答法不难，难的是把“为什么这样设计”说清楚。

一、核心解释

1. 控制器：一个类，public 方法就是 Action

控制器就是一个普通的 PHP 类，继承 app\BaseController（应用自带的基类）或 think\Controller（框架基类）。类里每个 public 方法就是一个可访问的操作（Action）：路由解析出控制器名和操作名后，框架实例化控制器类、调用对应的方法，方法的返回值就是响应内容。

面试答法：被问“请求怎么走到业务代码”，按这条线答：路由解析出控制器与操作 → 容器实例化控制器 → 调用 Action 方法 → 方法返回 Response。控制器是这条线的最后一站，也是你写业务代码的第一站。

2. BaseController 自带什么

继承 BaseController 后，控制器里直接可用的成员就这几个，面试常考，记住一张表就够了：

成员作用
$request当前请求实例（think\Request），取参数、判断请求类型都靠它
$app应用实例（think\App），拿配置、容器等
$batchValidate是否批量验证，验证器相关，Day 8 展开
$middleware控制器中间件列表，Day 5 展开
initialize()初始化方法，每个 Action 执行前运行
validate()数据验证方法，Day 8 展开

3. 初始化：用 initialize()，不要覆写 __construct

父类的 __construct 已经做了初始化工作（注入 $app、$request 等）。如果你在子类里写了自己的 __construct，又忘了调 parent::__construct()，这些初始化就全丢了——$this->request 可能是空的，中间件注册也可能失效，报错还不好定位。

框架留的口子就是 initialize()：父类构造器里会调用它。需要初始化逻辑（比如检查登录、加载公共数据）就写在这里，不要动 __construct。

经典面试坑：“在控制器里覆写 __construct 会怎样？”——答：父类 __construct 做了初始化，覆写后不调 parent::__construct() 会破坏初始化；正确做法是把初始化逻辑写进 initialize()，框架会在构造时自动调用它。

4. 依赖注入与参数绑定：Action 的参数从哪来

Action 方法的参数有两种来路，面试都爱问：

类型提示注入：方法参数带类型提示时，容器自动注入对应实例。比如 index(Request $request)，框架看到 Request 类型提示，就把当前请求实例注进来，不用你手动 new。JS 对照：像 NestJS 里用装饰器取请求对象，只不过 TP 靠类型提示自动识别，不用写装饰器。

按名绑定请求参数：方法参数没有类型提示时，框架按参数名从请求参数里找值传进来。比如 show($id)，访问 ?id=5 时 $id 就是 5。相当于 Express 里手动写 req.query.id，只不过 TP 帮你取了。

两种方式可以混用：show(Request $request, $id)，前者容器注入，后者按名绑定。

5. Request 对象：取参数的统一入口

请求对象是 think\Request，门面是 think\facade\Request（门面的机制 Day 10 展开，现在只要知道门面就是静态调用的壳）。常用方法一张表：

方法作用
param()取全部请求参数（GET、POST、路由参数合并）
get() / post()分别取 GET / POST 参数
header()取请求头
cookie()取 Cookie
file()取上传的文件
method()取请求方法（GET、POST 等）
isGet() / isPost() / isAjax()判断请求类型
module() / controller() / action()取当前模块 / 控制器 / 操作名

版本注意：TP6 起推荐用 Request 对象；5.1 的 input() 助手已不推荐。面试答法：新项目用 Request 对象注入取参，input() 只在老代码里见，知道它就行，不要在新代码里用。

6. Response：return 什么，浏览器就收到什么

控制器方法的返回值就是响应，规则很简单：

return 字符串：直接输出。return 数组：框架自动转 JSON，这是写 API 最常用的方式。助手函数：json($data) 明确返回 JSON，可指定状态码与响应头；view() 渲染模板；redirect() 跳转。底层类是 think\Response，JSON 响应类是 think\response\Json，也可以用 Response::create($data, 'json') 通用创建。

提前返回：想在中间逻辑里直接结束并返回响应（比如权限不足），抛一个 think\exception\HttpResponseException，把响应对象带进去。框架捕获这个异常后直接输出响应，后续代码不再执行——相当于 Express 里 return res.status(403).json(...) 提前 return，只不过 TP 用异常来中断流程。

二、代码示例

示例 1：User 控制器——注入、按名绑定、JSON 返回（放到 app\controller\User.php 可跑）

<?php
namespace app\controller;              // 命名空间，相当于 JS 的模块路径

use app\BaseController;                // use 相当于 import
use think\Request;                     // Request 类：请求对象

class User extends BaseController      // 继承基类，拿到 $this->request 等成员
{
    protected function initialize()
    {
        // 初始化逻辑写在这里，每个 Action 执行前都会跑一次
        // 不要覆写 __construct：父类构造器已做初始化，覆写又不调 parent::__construct() 会破坏它
    }

    // GET /user —— 用户列表
    public function index(Request $request)   // 类型提示：容器自动注入 Request 实例
    {
        $page = $request->param('page', 1);   // -> 相当于 JS 的 . ；param() 取参数，第二个参数是默认值
        return ['page' => $page, 'list' => []];  // => 是键值对，相当于 JS 对象里的冒号；return 数组自动转 JSON
    }

    // GET /user/5 —— 用户详情，$id 按名绑定请求参数
    public function show($id)
    {
        return '用户 #' . $id;         // . 是字符串拼接，相当于 JS 的 + ；return 字符串直接输出
    }

    // POST /user —— 新建用户
    public function store(Request $request)
    {
        if (! $request->isPost()) {    // isPost() 判断请求方法
            return json(['code' => 405, 'msg' => '只接受 POST']);  // json() 助手明确返回 JSON
        }
        $name = $request->post('name');  // post() 只取 POST 参数
        return json(['code' => 0, 'msg' => 'ok', 'name' => $name]);
    }
}

示例 2：几种返回方式与提前返回

<?php
namespace app\controller;

use app\BaseController;
use think\exception\HttpResponseException;

class Demo extends BaseController
{
    public function page()
    {
        // view() 渲染模板，第二个参数是传给模板的变量
        return view('demo/index', ['title' => '你好']);
    }

    public function jump()
    {
        return redirect('/user');      // redirect() 跳转到指定地址
    }

    public function secret()
    {
        $login = false;                // 假设这里是登录检查的结果
        if (! $login) {
            // 提前返回：抛 HttpResponseException，框架捕获后直接输出响应，后续代码不再执行
            throw new HttpResponseException(json(['code' => 403, 'msg' => '请先登录']));
        }
        return '秘密内容';
    }
}

3. 在 initialize() 里加一行日志或 echo，访问任意 Action，确认它每次都会先执行。

三、ThinkJS 对比

ThinkJS 的控制器与 TP 几乎同源，只差在 JS 的表达方式上：

维度ThinkPHPThinkJS
控制器定义class User extends BaseControllermodule.exports = class extends think.Controller
操作方法public 方法任意名方法名必须以 Action 结尾，如 indexAction()
取 GET 参数$request->get('id')this.get('id')
取 POST 参数$request->post()this.post()
返回统一 JSONreturn 数组 / json()this.success(data) / this.fail(msg)
请求上下文$this->requestthis.ctx（Koa 上下文）
前置钩子initialize()__before()，所有 Action 执行前运行
// ThinkJS 控制器：src/controller/user.js
module.exports = class extends think.Controller {
  __before() {
    // 所有 Action 执行前运行，相当于 TP 的 initialize()
  }
  async indexAction() {
    const id = this.get('id');      // 取 GET 参数，相当于 TP 的 $request->get('id')
    return this.success({id});      // 返回统一 JSON，相当于 TP 的 return json(...)
  }
};

记忆锚点：TP 的 initialize() 就是 ThinkJS 的 __before()；TP 的 return 数组自动转 JSON 就是 ThinkJS 的 this.success()。两边概念一一对应，差别只在语法。

四、小测验（点选项判分，答完点解析）

得分：0 / 3

1. 控制器需要初始化逻辑（比如检查登录），应该写在哪里？

解析：选 B。父类 __construct 已做初始化，覆写又不调 parent::__construct() 会破坏它；initialize() 就是框架留的初始化口子。

2. 控制器方法 return 一个数组，浏览器会收到什么？

解析：选 B。return 数组自动转 JSON，是 TP 写 API 最常用的方式；想明确控制状态码与响应头时用 json() 助手。

3. index(Request $request) 里的 $request 是从哪来的？

解析：选 A。带类型提示的方法参数由容器自动注入；没有类型提示的参数则按名绑定请求参数。

五、面试高频问答

Q1：控制器里为什么不用 __construct 做初始化？

父类 BaseController 的 __construct 已经做了初始化工作（注入 $app、$request 等）。子类覆写 __construct 又不调 parent::__construct()，这些初始化就全丢了。正确做法是把初始化逻辑写进 initialize()，父类构造器会调用它。

Q2：return 数组和 return json() 有什么区别？

return 数组时框架按默认方式自动转 JSON，简单够用；json() 助手返回 think\response\Json，可以明确指定状态码与响应头，控制更细。两者底层都是 Response，面试时答“数组是简写，json() 是显式控制”就够了。

Q3：怎么在控制器里提前返回响应、终止后续执行？

抛 think\exception\HttpResponseException，把响应对象带进去：throw new HttpResponseException(json([...]))。框架捕获这个异常后直接输出响应，后续代码不再执行。典型场景是权限检查不通过时直接返回 403。

Q4：TP6 为什么推荐用 Request 对象而不是 input()？

input() 是 5.1 时代的全局助手函数，TP6 起已不推荐。Request 对象是面向对象的方式：可通过类型提示依赖注入、方法语义清晰（get / post / header / file 各司其职）、便于测试。新项目用 Request 对象，input() 只在老代码里见。

加分项

生产视角：控制器保持瘦：只做参数接收、调用服务层、返回响应；业务逻辑放 Service 或 Model，控制器里不要直接写 SQL。面试官问“控制器里写了 500 行 SQL 怎么看”，答：难复用、难测试、难维护，抽到服务层。

简历讲法：别写“熟悉 ThinkPHP 控制器”，写“基于 ThinkPHP 8.x 搭建 API：控制器按资源拆分，Request 对象取参 + 依赖注入，统一 JSON 返回，权限不足时用 HttpResponseException 提前返回”。前者是名词，后者是可追问的做法。
