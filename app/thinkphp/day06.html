Day 6：数据库层：Db 查询构造器与事务

请求处理篇结束，今天进入数据篇。ThinkPHP 里操作数据库有两层：今天讲的 Db 查询构造器是底层——链式拼 SQL、直接打交道；Day 7 的模型 ORM 是上层——在构造器之上包了一层对象与关联。面试时两层都会问，但构造器是根：模型的方法最后都要落到构造器上。

一、核心解释

1. Db 门面与 name / table：从哪张表开始查

入口是门面 think\facade\Db（门面机制 Day 10 展开，现在只要会用）。一张表两种写法：Db::name('user') 自动加上配置里的表前缀（比如前缀是 tp_，实际查的就是 tp_user）；Db::table('tp_user') 写完整表名，不加前缀。

面试答法：被问“name 和 table 有什么区别”，答：name 写不带前缀的表名、框架自动加前缀，换前缀不用改代码；table 写完整表名，适合表名不在前缀规则内的情况（比如跨库查另一张表）。日常开发用 name 居多。

2. 链式查询：像搭积木一样拼 SQL

查询构造器的核心是链式调用：每个方法返回构造器本身，可以一直点下去，最后用一个终结方法执行。JS 对照：就像数组的 filter().map().slice() 链式调用，只不过这里拼的是 SQL。

方法作用对应 SQL
where('id', 1)条件（两参数是等于，三参数可写操作符，如 where('age', '>', 18)）WHERE
field('id,name')只取指定列SELECT id, name
order('id', 'desc')排序ORDER BY id DESC
limit(10)取多少条LIMIT 10
find()终结方法：查一条，返回数组，查不到返回 nullLIMIT 1
select()终结方法：查多条，返回数组的数组—

聚合方法也是终结方法：value() 取某个字段的值（一条记录的一个字段）、column() 取某一列（多条记录的某个字段）、count() 计数、sum() 求和。分页用 paginate(15)，每页 15 条，返回分页对象（包含当前页数据与分页信息）。

3. 写入：增删改与自增自减

方法作用
insert($data)插入一条，返回受影响行数
insertGetId($data)插入一条并返回自增 id
insertAll($list)批量插入多条
update($data)更新，需先写 where() 限定范围
delete()删除，需先写 where() 限定范围
inc('score', 5) / dec('num', 1)字段自增 / 自减，链式后接 update() 执行

inc() / dec() 值得单独记：它们是在数据库层面做原子自增自减，相当于 UPDATE user SET score = score + 5。面试常考“计数器怎么避免竞态”：答“不要先读出来再加回去，用 inc() 让数据库原子更新”，这就是标准答案。

容易踩的坑：update() 和 delete() 之前务必先写 where()，否则整张表都会被改掉或删掉。构造器不会拦你——没有 where 的 update 就是全表更新。生产事故里这一条能排进前三，面试官问“update 忘写 where 会怎样”就是在考这个。

4. 原生查询：想写 SQL 也行，但要用占位符

构造器拼不出的复杂 SQL，可以用原生查询：Db::query('select * from user where id=?', [1]) 查数据，Db::execute(...) 执行写操作。关键点是 ? 占位符 + 参数数组绑定：参数由驱动转义后再拼进 SQL，杜绝 SQL 注入。

面试答法：被问“怎么防 SQL 注入”，答两层：日常用查询构造器（参数自动绑定）；必须写原生 SQL 时用占位符 ? + 参数数组，绝不把用户输入直接拼进 SQL 字符串。

5. 事务：两种写法，闭包更常用

事务保证“一组操作要么全成功，要么全回滚”，典型场景是下单：插订单 + 扣库存，任一步失败都要撤销。TP 提供两种写法：

手动控制：Db::startTrans() 开启，try 里做操作，全部成功调 Db::commit() 提交，catch (\Exception $e) 里调 Db::rollback() 回滚。适合需要精细控制提交点的场景。

闭包自动：Db::transaction(function () { ... })，把操作写进闭包：闭包正常结束自动提交，抛异常自动回滚。代码更短，日常开发更常用。

面试答法：被问“两种事务写法怎么选”，答：闭包写法简洁、自动提交回滚，日常优先；手动写法适合跨方法、需要中途判断是否提交的复杂流程。

6. 读写分离与连接配置

连接配置在 config/database.php：default 设默认连接（一般是 mysql），charset 建议 utf8mb4（支持 emoji 与生僻字），prefix 是表前缀（Db::name() 自动加的就是它）。

读写分离的配置也在同一个文件里：'deploy' => 1 开启分布式，'rw_separate' => true 开启读写分离，主从地址配在 hostname 数组里（第一个是主库，其余是从库）。开启后读请求走从库、写请求走主库。

面试答法：被问“读写分离怎么配”，答：deploy 设 1、rw_separate 设 true、hostname 配主从地址数组。追问“主从延迟怎么办”时诚实答：强一致读要走主库，这是读写分离的固有代价，业务上一般用“写后短时间内读主库”来缓解。

二、代码示例

示例 1：查询、写入与分页（在控制器方法里可跑）

<?php
use think\facade\Db;               // Db 门面：数据库操作的统一入口

// 查一条：where('id', 1) 相当于 WHERE id = 1
$user = Db::name('user')->where('id', 1)->find();  // find() 返回一条记录（数组），查不到返回 null

// 链式查询：条件 + 字段 + 排序 + 条数，像 JS 数组的 filter().map().slice() 一样链下去
$list = Db::name('user')
    ->where('age', '>', 18)       // 三参数 where：字段、操作符、值；> 写在代码里是大于号
    ->field('id,name')             // 只取这两列，相当于 SELECT id, name
    ->order('id', 'desc')          // 按 id 倒序
    ->limit(10)                    // 取 10 条
    ->select();                    // select() 终结：返回多条记录的数组

// 聚合：count() 计数、sum() 求和，都是终结方法
$count = Db::name('user')->where('status', 1)->count();
$total = Db::name('order')->sum('amount');

// 分页：每页 15 条，返回分页对象（带当前页数据与分页信息）
$page = Db::name('user')->paginate(15);

// 写入：insertGetId() 插入并返回自增 id
$id = Db::name('user')->insertGetId(['name' => 'linr', 'age' => 30]);
Db::name('user')->where('id', $id)->update(['age' => 31]);   // update 前先 where，否则全表更新
Db::name('user')->where('id', $id)->inc('score', 5)->update(); // score 原子加 5，防竞态

示例 2：原生查询与事务两种写法

<?php
use think\facade\Db;

// 原生查询：? 占位符 + 参数数组绑定，参数由驱动转义，防 SQL 注入
$rows = Db::query('select * from user where id=?', [1]);
Db::execute('update user set age=? where id=?', [31, 1]);

// 事务写法一：手动控制提交与回滚
Db::startTrans();                  // 开启事务
try {
    Db::name('order')->insert(['user_id' => 1, 'amount' => 99]);
    Db::name('stock')->where('id', 1)->dec('num', 1)->update();  // 库存减 1
    Db::commit();                  // 全部成功才提交
} catch (\Exception $e) {
    Db::rollback();                // 任一步失败，全部回滚
    throw $e;                      // 回滚后把异常继续抛出去
}

// 事务写法二：闭包自动提交 / 回滚（日常更常用）
Db::transaction(function () {
    Db::name('order')->insert(['user_id' => 1, 'amount' => 99]);
    Db::name('stock')->where('id', 1)->dec('num', 1)->update();
});  // 闭包正常结束自动 commit，抛异常自动 rollback

示例 3：读写分离配置（config/database.php 片段）

<?php
return [
    'default' => 'mysql',          // 默认连接
    'connections' => [
        'mysql' => [
            'type' => 'mysql',
            'hostname' => ['192.168.1.1', '192.168.1.2'],  // 主从地址数组：第一个是主库，其余是从库
            'database' => 'demo',
            'username' => 'root',
            'password' => '',
            'charset' => 'utf8mb4',   // 字符集，建议 utf8mb4
            'prefix' => 'tp_',        // 表前缀，Db::name() 会自动加上
            'deploy' => 1,            // 1 开启分布式
            'rw_separate' => true,    // true 开启读写分离：读走从库，写走主库
        ],
    ],
];

动手任务（10 分钟）

1. 用示例 1 的链式查询查一张真实的表，把 field() 拿掉再跑一次，对比返回的字段有什么不同。
2. 故意在事务闭包里抛一个异常，确认插进去的订单有没有被回滚——亲手验证“抛异常自动 rollback”。
3. 把 inc('score', 5) 改成“先 select 读出 score，再 update 写回 score + 5”，想一想两个请求同时跑时会发生什么，这就是 inc() 要解决的竞态。

exports.model = {
  type: 'mysql',
  mysql: {
    handle: adapter,      // MySQL 适配器句柄
    database: 'demo',
    prefix: 'tp_',        // 表前缀，与 TP 的 prefix 同义
    encoding: 'utf8mb4',
    host: '127.0.0.1',
    port: 3306,

  }

// ThinkJS 链式查询：与 TP 几乎同源
const user = await model('user').where({id: 1}).find();   // 对应 TP 的 Db::name('user')->where('id', 1)->find()

记忆锚点：TP 的 Db::name('user') 就是 ThinkJS 的 model('user')；where / find / select / update / delete / count 两边方法名基本一致，只有新增是 insert() 对 add()、分页是 paginate() 对 page() + limit()。记住这两处不同，数据库层基本不用死记。

四、小测验（点选项判分，答完点解析）

得分：0 / 3

1. Db::name('user') 和 Db::table('tp_user') 的区别是？

解析：选 B。前缀是 tp_ 时，Db::name('user') 实际查 tp_user；Db::table('tp_user') 直接写完整表名，不加前缀。

2. Db::transaction(function () { ... }) 闭包里抛了异常，会发生什么？

解析：选 A。闭包写法的好处就是自动：正常结束自动 commit，抛异常自动 rollback，不用手写 try / catch。

3. 原生查询防 SQL 注入靠什么？

解析：选 C。绝不把用户输入直接拼进 SQL 字符串；用 ? 占位符 + 参数数组，驱动会负责转义。日常优先用查询构造器，它内部也是参数绑定。

五、面试高频问答

Q1：Db::name() 和 Db::table() 什么时候用哪个？

日常用 name：写不带前缀的表名，框架自动加前缀，换前缀不用改代码。table 写完整表名，适合表名不在前缀规则内的情况，比如跨库查另一张表。

Q2：两种事务写法怎么选？

闭包写法 Db::transaction(fn) 简洁、自动提交回滚，日常优先。手动写法 startTrans / commit / rollback 适合跨方法、需要中途判断是否提交的复杂流程。核心是保证“一组操作要么全成功，要么全回滚”。

Q3：paginate() 返回的是什么？

返回分页对象，包含当前页数据与分页信息（总数、当前页、每页条数等）。控制器里 return 它，框架会序列化成带分页信息的 JSON，前端直接用 total 和当前页数据渲染分页器。

Q4：inc() / dec() 有什么用？为什么不用“读出来再加回去”？

inc() / dec() 在数据库层面做原子自增自减，相当于 UPDATE ... SET score = score + 5。先读再写有两个请求同时跑时会互相覆盖（竞态）；原子更新不存在这个问题。计数器、库存、点赞数都应该用 inc() / dec()。

Q5：读写分离怎么配？有什么代价？

config/database.php 里 deploy 设 1 开分布式、rw_separate 设 true 开读写分离、hostname 配主从地址数组（第一个是主库）。代价是主从延迟：刚写入主库的数据，从库可能还没同步到，强一致读要走主库。

加分项

生产视角：查询构造器是底线，不是上限：复杂报表 SQL 别硬用链式拼，可读性会崩，用原生查询 + 占位符；高频查询记得看执行计划，where 字段有没有索引比写法花哨重要得多。

简历讲法：别写“熟练使用 ThinkPHP 数据库操作”，写“用 Db 查询构造器做订单列表：链式条件 + 分页，下单流程用 Db::transaction 保证插订单与扣库存原子性，计数器用 inc() 避免竞态”。前者是名词，后者是可追问的场景。
