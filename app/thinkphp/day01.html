Day 1：ThinkPHP 是什么：定位、版本线与安装

你 JS/TS 精通、PHP 能写但不精通，面试 PHP 岗位时，ThinkPHP 是最常被问到的国产框架：很多国内中小公司的后台系统、CMS、API 服务都跑在它上面。好消息是，ThinkPHP 的核心概念——MVC、路由、中间件、ORM、容器——和你在 JS 生态里见过的东西一一对应，缺的只是 PHP 侧的叫法和细节。今天先把定位、版本线、安装与目录结构立起来，后面 11 天逐块填血肉。

一、核心解释

1. 一句话定位

ThinkPHP 是国产开源的轻量级 PHP Web 开发框架，遵循 MVC 架构，特点是轻量、上手快、中文文档与社区强，在国内中小项目、后台系统、CMS 里很常见。框架遵循 PSR-2 代码风格与 PSR-4 自动加载规范——PSR-4 就是 PHP 版的“按目录找模块”：类名与文件路径一一对应，不用手动 require。

面试答法：“ThinkPHP 是国内最常用的轻量 PHP 框架之一，MVC 架构，核心瘦身、能力靠扩展；我用它做过后台系统和 API 服务，熟悉路由、中间件、ORM 和容器这套完整链路。”

2. 版本线演进：5.x → 6.x → 8.x

版本线关键变化
5.xapplication/ 目录、thinkphp/ 核心目录、input() 助手函数、注解路由内置
6.x（2019 年）app/ 目录、Composer 优先、容器/门面重构、think-orm 独立为组件、多应用拆为扩展
8.x基于 PHP 8.0+ 重构；注解路由剥离为扩展，改用 PHP 8 原生 #[Route(...)] Attribute

面试常问“5.x 和 6.x 最大的区别是什么”：答目录结构变了（application/ → app/）、Composer 成为标准安装方式、ORM 独立、多应用变成扩展，这四点就够了。

3. ThinkPHP 8 的关键变化

基于 PHP 8.0+ 重构（推荐 8.1/8.2），依赖 think-orm 3.0+，升级了 PSR 依赖；新增 think-dumper（支持远程调试）；6.0/6.1 可无缝升级到 8.x。最大的结构性变化是注解路由剥离出核心：8.x 之前注解路由内置，8.x 需要单独装 topthink/think-annotation 扩展，并改用 PHP 8 原生的 #[Route(...)] Attribute 写法，还要在路由文件里调用 AnnotationRoute::init() 才能生效（Day 3 展开）。

4. 目录结构：一眼认出 TP 项目

tp/
├── app/                  # 应用目录：业务代码都在这里
│   ├── controller/       # 控制器
│   ├── model/            # 模型（对应数据库表）
│   ├── view/             # 模板视图
│   ├── middleware/       # 中间件
│   ├── BaseController.php
│   ├── ExceptionHandle.php
│   ├── event.php         # 事件定义
│   ├── middleware.php    # 中间件注册
│   └── provider.php      # 服务提供者
├── config/               # 配置文件（app.php、database.php…）
├── route/                # 路由定义（默认 route/app.php）
├── public/               # Web 根目录，唯一入口 index.php 在这里
├── runtime/              # 缓存、日志等运行时文件
├── vendor/topthink/framework/  # 框架核心（Composer 装进来的）
├── .env                  # 环境变量（数据库密码等，不进版本库）
├── think                 # 命令行入口（php think run / php think make:controller…）
└── composer.json

记住三个最常被问的点：唯一 Web 入口是 public/index.php（其余目录不应暴露给 Web 服务器）；think 是命令行入口，相当于 Laravel 的 artisan、NestJS 的 nest CLI；.env 放敏感配置，和 Node 项目里的 .env 完全一个思路。

5. 核心瘦身、能力靠扩展

从 6.x 开始，ThinkPHP 走“核心瘦身”路线：很多能力不在核心里，而是独立扩展，需要时用 Composer 装：

扩展提供什么能力
think-multi-app多应用支持（一个项目跑多个应用，如 admin + api）
think-view模板引擎
think-queue消息队列
think-annotation注解路由（8.x 必装才有）

扩展通过 composer.json 的 extra.think.services 自动发现——装上就能用，不用手动注册。面试答法：“TP 核心只保留路由、容器、ORM 这些底座，多应用、队列、模板都是扩展，这样项目可以按需裁剪，不用的功能不进包。”

6. 与 Laravel 的定位差异

维度LaravelThinkPHP
定位全功能框架，全球生态大轻量框架，中文文档社区强
内置能力Eloquent / Blade / Artisan / 队列都内置核心瘦身，队列、模板、多应用靠扩展
常见场景国际化项目、大型应用国内中小项目、后台系统、CMS

关键一句：两者都是 MVC + 路由 + 中间件 + ORM + 容器，概念完全可迁移——你在 Laravel/Express/Koa 里理解的中间件洋葱模型、ORM、依赖注入，换到 TP 只是换了类名和写法。面试时不要踩一捧一，就说“选型看团队与项目规模”。

容易踩的坑：不要在面试里说某个 8.x 小版本是“最新版”——小版本一直在发，说错了立刻露馅。只说“8.x 线”就够了。同样，ThinkJS 只说 3.x 线，不要编 4.x。

二、代码示例

示例 1：安装、启动与更新（命令行）

# 创建项目：topthink/think 是官方应用骨架，tp 是目录名
composer create-project topthink/think tp

cd tp

# 启动内置开发服务器，访问 http://localhost:8000
php think run

# 只更新框架本身（不碰其他依赖）
composer update topthink/framework

示例 2：最小控制器（逐行注释 + JS 对照）

<?php
// namespace 声明命名空间 ≈ JS 的模块路径；PSR-4 按它找到这个文件
namespace app\controller;

class Index
{
    // 方法名 hello 对应 URL 里的操作名：访问 /index/hello 就会调它
    // $name：PHP 变量都以 $ 开头；= 'ThinkPHP' 是默认值，和 JS 默认参数一样
    public function hello($name = 'ThinkPHP')
    {
        // . 是字符串拼接，相当于 JS 的 +
        // 直接 return 字符串，框架会把它包成 Response 发出去
        return 'hello,' . $name;
    }
}

PHP 语法速记（JS 对照）：$变量 相当于 JS 的变量名（只是多了 $ 前缀）；-> 相当于 JS 的 .（调对象方法/属性）；:: 是静态调用，相当于 JS 的 Class.staticMethod()；=> 是键值对分隔符，相当于 JS 对象字面量里的 :；use 导入类，相当于 JS 的 import。

动手任务（10 分钟）

1. 在本机跑通 composer create-project topthink/think tp，php think run 启动后打开 http://localhost:8000，确认看到默认欢迎页。
2. 把示例 2 的控制器写进 app/controller/Index.php，访问 /index/hello，再改改默认值，确认 URL 操作名与方法名的对应关系。
3. 打开 public/index.php 看一眼入口骨架——只有 6 行，Day 2 会逐行拆它。

三、ThinkJS 对比

ThinkJS 和 ThinkPHP 同名不同语言：一个是 Node.js 框架，一个是 PHP 框架，但渊源很深。ThinkJS 作者李成银（@welefen），360 奇舞团，2013 年底参考 ThinkPHP 起步；多处资料确认“ThinkJS 很多特性来源于 ThinkPHP”。如果你用过 ThinkJS，TP 的很多概念你已经会了，只是换了语言。

维度ThinkPHPThinkJS
语言与底层PHPNode.js；ThinkJS 3.x 基于 Koa 2.x
控制器目录app/controllersrc/controller
模型目录app/modelsrc/model
配置目录config/src/config
独有目录app/middlewaresrc/logic（参数校验层）
核心命名Controller / Model / MiddlewareController / Model / Middleware / Adapter 对应

面试加分句：“我之前用过 ThinkJS，它就是参考 ThinkPHP 设计的，目录和命名高度相似，所以 TP 的 MVC 结构我上手很快；区别主要在运行模型——PHP-FPM 每个请求都是干净启动，Node 是常驻进程（Day 2 展开）。”

四、小测验（点选项判分，答完点解析）

得分：0 / 3

1. ThinkPHP 8 基于哪个 PHP 版本重构？

解析：选 B。TP8 基于 PHP 8.0+ 重构，推荐用 8.1/8.2；这也是它能用原生 #[Route] Attribute 的前提。

2. 在 ThinkPHP 8 里用注解路由，正确的做法是？

解析：选 B。8.x 把注解路由剥离为扩展，三步缺一不可：装扩展、写 Attribute、调 init()。

3. 多应用功能在 ThinkPHP 8 的核心里吗？

解析：选 B。从 6.x 起多应用就拆为扩展，8.x 延续“核心瘦身、能力靠扩展”的路线。

五、面试高频问答

Q1：一句话介绍 ThinkPHP，它适合做什么项目？

ThinkPHP 是国产轻量级 PHP MVC 框架，上手快、中文文档社区强，适合国内中小项目、后台管理系统、CMS 和 API 服务。核心瘦身、能力靠扩展，项目可以按需裁剪。

Q2：ThinkPHP 5.x、6.x、8.x 各有什么标志性变化？

5.x 是 application/ 目录、thinkphp/ 核心目录、input() 助手、注解路由内置；6.x（2019 年）改成 app/ 目录、Composer 优先、容器/门面重构、think-orm 独立、多应用拆为扩展；8.x 基于 PHP 8.0+ 重构，注解路由剥离为扩展、改用 PHP 8 原生 Attribute，新增 think-dumper 支持远程调试，6.0/6.1 可无缝升级。

Q3：ThinkPHP 8 对 PHP 版本有什么要求？

基于 PHP 8.0+ 重构，推荐 8.1/8.2；依赖 think-orm 3.0+。面试时只说 8.x 线，不要编某个小版本是“最新版”。

Q4：怎么安装和启动一个 ThinkPHP 项目？

composer create-project topthink/think tp 创建项目，cd tp 后 php think run 启动内置服务器，访问 http://localhost:8000；更新框架用 composer update topthink/framework。唯一 Web 入口是 public/index.php。

Q5：ThinkPHP 和 Laravel 怎么选？

两者都是 MVC + 路由 + 中间件 + ORM + 容器，概念可迁移。Laravel 是全功能框架、全球生态大，Eloquent/Blade/Artisan/队列都内置；ThinkPHP 轻量、上手快、中文文档社区强，国内中小项目、后台系统、CMS 常见。选型看团队熟悉度与项目规模，不要踩一捧一。

六、加分项

简历讲法：别写“了解 ThinkPHP”，写“用 ThinkPHP 8（PHP 8.1）做过后台系统与 API 服务：路由 + 中间件 + think-orm，熟悉请求生命周期与容器依赖注入；能按需选用 think-queue / think-multi-app 等扩展”。前者是名词，后者是可追问的架构。
