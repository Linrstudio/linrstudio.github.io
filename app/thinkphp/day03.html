Day 3：路由：注册、参数、分组与资源路由

路由是请求的“分诊台”：URL 进来之后，由路由决定交给哪个控制器、哪个方法。Day 2 的生命周期里，路由匹配就发生在 Http::run 之后、中间件之前——路由先定下来，后面才知道该跑哪些中间件、调哪个控制器。今天讲注册、参数、分组、资源路由与 MISS 路由，以及 TP8 注解路由的三步正确用法。

一、核心解释

1. 门面与注册方式

路由统一用门面 think\facade\Route 注册。门面（Facade）是 TP 给容器里的服务起的静态代理：你写 Route::get(...)，实际调的是容器里 think\Route 实例的方法。JS 对照：:: 是静态调用，相当于 JS 的 Class.staticMethod()。

方法含义
Route::get($rule, $route)只响应 GET 请求
Route::post($rule, $route)只响应 POST 请求
Route::put($rule, $route)只响应 PUT 请求
Route::delete($rule, $route)只响应 DELETE 请求
Route::any($rule, $route)响应任意请求方法
Route::rule($rule, $route, $method)通用注册，第三个参数指定方法

最简单的闭包路由：Route::get('think', function () { return 'hello,ThinkPHP8!'; });——访问 /think 就返回这句话。function () {} 是 PHP 的匿名函数，相当于 JS 的箭头函数。

2. 路由参数：必选、可选与全局规则

:id 是必选参数：Route::get('hello/:name', 'index/hello'); 访问 /hello/Arale 时，$name 就是 'Arale'，会作为参数传给 hello 方法。[:id] 是可选参数：方括号包起来，URL 里不带它也能匹配。JS 对照：:id 和 Express 的 /user/:id 是一个意思。

全局变量规则用 Route::pattern(['id' => '\d+'])：所有 :id 参数只匹配数字，/user/abc 就匹配不上这条路由。面试答法：“参数分必选和可选，pattern 可以全局约束参数格式，相当于给路由加了一层正则校验。”

3. 分组与域名路由

Route::group('api', function () {...}) 把一批路由收进 /api 前缀下，分组可挂中间件——比如整个 api 分组统一挂鉴权中间件，不用每条路由单独写。域名路由 Route::domain('api', ...) 则按域名分流：api.example.com 的请求走一组路由，www.example.com 走另一组。

4. 资源路由：一条语句注册一整组 RESTful 路由

Route::resource('blog', 'Blog'); 一条语句注册 blog 的整组 RESTful 路由，映射关系如下：

请求方法URL控制器方法用途
GET/blogindex列表
GET/blog/createcreate新建表单
POST/blogsave保存新建
GET/blog/:idread详情
GET/blog/:id/editedit编辑表单
PUT/blog/:idupdate更新
DELETE/blog/:iddelete删除

面试常问“资源路由和手写 7 条路由有什么区别”：答“效果一样，资源路由是约定俗成的简写，RESTful 风格的 CRUD 直接用它，少写样板代码；需要自定义时再手写。”

5. MISS 路由：兜底

Route::miss(function () {...}); 是兜底路由：所有未匹配到任何路由的请求都会落到这里，常用来做统一的 404 处理或自定义错误页。注意 MISS 路由要放在路由文件的最后——它一旦匹配就不会继续往下找。

6. 路由到类方法：两种写法

路由的第二个参数可以是 '控制器/操作' 的简写，如 'index/hello'；也可以写 '\完整类名@方法名'，如 '\app\controller\Index@hello'。简写是约定（按 app/controller 目录找），完整类名是显式指定，跨命名空间或特殊目录时用后者。

7. 路由流程四步

定义 → 检测 → 解析 → 调度。定义：路由文件里注册规则；检测：请求进来后按规则逐条匹配；解析：把匹配到的规则解析成控制器、方法与参数；调度：交给容器调度执行。面试时这四个词按顺序说出来，再展开讲任意一步的细节，就是满分答案。

8. 路由文件与多应用

路由定义在 route/ 目录，默认是 route/app.php；该目录下多个文件都有效，可以按模块拆成 route/api.php、route/admin.php 等。多应用模式下，各应用有自己的 route/ 目录，互不干扰。

9. 注解路由：TP8 的三步正确用法

TP8 把注解路由剥离出核心了，想用必须做满三步：① 装扩展 composer require topthink/think-annotation；② 用 PHP 8 原生 #[Route(...)] Attribute 写在方法上（不再是旧版的 @route 注释写法）；③ 在路由文件里调用 AnnotationRoute::init()，让框架扫描注解并注册。

容易踩的坑：只装扩展、不调 AnnotationRoute::init()，注解路由不会生效——这是 TP8 升级后最常见的“路由 404”原因之一。排查顺序：扩展装了没 → Attribute 写对没 → init() 调了没。

10. 路由缓存、开关与 URL 模式

生产环境可以用 php think optimize:route 生成路由缓存，避免每次请求重新解析路由规则（呼应 Day 2 的 PHP-FPM 每请求初始化开销）。config/app.php 里的 with_route 控制是否启用路由。URL 模式是 PATHINFO：域名/入口/控制器/操作/参数，如 example.com/index.php/index/hello/name/Arale（入口文件可通过服务器重写隐藏）。

二、代码示例

示例 1：route/app.php 综合示例（逐行注释）

<?php
// use 导入类，相当于 JS 的 import
use think\facade\Route;

// 最简单的闭包路由：访问 /think 返回一句话
Route::get('think', function () {
    return 'hello,ThinkPHP8!';
});

// :name 是必选参数，访问 /hello/Arale 时 $name 就是 'Arale'
// 'index/hello' 是"控制器/操作"简写，对应 app\controller\Index::hello()
Route::get('hello/:name', 'index/hello');

// 全局变量规则：所有 :id 参数只匹配数字，/user/abc 匹配不上
// ['id' => '\d+'] 是关联数组，=> 相当于 JS 对象字面量里的冒号
Route::pattern(['id' => '\d+']);

// 分组：/api 下的路由统一收在一起，分组可挂中间件（如鉴权）
// 闭包里继续用 Route::get 注册，分组前缀自动拼上
Route::group('api', function () {
    Route::get('user/:id', 'api/user/read');
});

// 资源路由：一条语句注册 blog 的整组 RESTful 路由
// （index/create/save/read/edit/update/delete，见第一节的映射表）
Route::resource('blog', 'Blog');

// 路由到类方法：完整类名 @ 方法名，显式指定、不走约定查找
Route::get('about', '\app\controller\Index@about');

// MISS 路由：兜底，所有未匹配的请求都落到这里
// 必须放在文件最后，否则会截断后面的路由
Route::miss(function () {
    return '404 Not Found';
});

示例 2：TP8 注解路由写法（需先装 think-annotation 扩展）

<?php
namespace app\controller;

// Route 属性来自 topthink/think-annotation 扩展（按扩展文档导入）
// #[...] 是 PHP 8 原生 Attribute，相当于 Java 注解 / C# 特性 / TS 装饰器
class Index
{
    #[Route('hello/:name', method: 'GET')]
    public function hello($name)
    {
        return 'hello,' . $name;
    }
}

// ---- 路由文件 route/app.php 里必须加这一行，否则注解不生效 ----
// AnnotationRoute::init();

三、ThinkJS 对比

ThinkJS 的路由分两层：默认约定路由 + 自定义路由，和 TP 的“显式注册为主、约定为辅”正好反过来。

维度ThinkPHPThinkJS
默认路由PATHINFO 模式：域名/入口/控制器/操作/参数约定路由 /controller/action，多模块是 /module/controller/action
自定义路由route/ 目录下用 Route::get 等注册src/config/router.js，如 [['/test/myGet', 'test/get']]
REST 路由Route::resource('blog', 'Blog') 注册整组[['/user/:id?', 'rest']] 映射到 getAction / postAction / putAction / deleteAction
参数写法:id 必选、[:id] 可选:id? 可选（问号后缀）
特色资源路由、MISS 兜底、路由缓存文件即路由：控制器文件放那儿就能访问，是 ThinkJS 的特色

面试加分句：“ThinkJS 默认是文件即路由、约定优先，自定义路由写在 router.js；TP 是显式注册为主，路由文件里一条条定义，资源路由和 MISS 兜底是 TP 更顺手的地方。两者 REST 映射的思路一样，都是按 HTTP 方法分发到不同处理函数。”

五、面试高频问答

Q1：ThinkPHP 的路由流程是哪四步？

定义 → 检测 → 解析 → 调度。定义是在路由文件里注册规则；检测是请求进来后按规则逐条匹配；解析是把匹配到的规则解析成控制器、方法与参数；调度是交给容器调度执行。

Q2：:id 和 [:id] 有什么区别？怎么约束参数格式？

:id 是必选参数，URL 里必须有；[:id] 是可选参数，不带也能匹配。用 Route::pattern(['id' => '\d+']) 做全局变量规则，所有 :id 只匹配数字，相当于给路由加了一层正则校验。

Q3：路由分组有什么好处？

Route::group('api', function () {...}) 把一批路由收进同一前缀下，还能统一挂中间件（比如整个 api 分组挂鉴权），不用每条路由单独写。域名路由 Route::domain 则按域名分流不同路由组。

Q4：资源路由 Route::resource 注册了哪些路由？

一条语句注册整组 RESTful 路由：GET /blog → index（列表）、GET /blog/create → create（新建表单）、POST /blog → save（保存）、GET /blog/:id → read（详情）、GET /blog/:id/edit → edit（编辑表单）、PUT /blog/:id → update（更新）、DELETE /blog/:id → delete（删除）。

Q5：TP8 的注解路由和旧版有什么不同？

旧版注解路由内置在核心里，用 @route 注释写法；8.x 剥离为 topthink/think-annotation 扩展，改用 PHP 8 原生 #[Route(...)] Attribute，还必须在路由文件里调用 AnnotationRoute::init() 才能生效。只装扩展不调 init() 是最常见的路由 404 原因之一。

六、加分项

简历讲法：别写“会用 TP 路由”，写“用 TP 路由做过 API 分组与 RESTful 资源路由：api 分组统一挂鉴权中间件，资源路由覆盖 CRUD，MISS 路由做统一 404；生产环境用 php think optimize:route 做路由缓存”。前者是名词，后者是可追问的实践。
