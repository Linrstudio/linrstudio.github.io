Day 7：模型 ORM：关联、软删除与模型事件

前面几天讲的是请求怎么进来、路由怎么分发、控制器怎么做事；今天讲数据层最核心的一块：模型 ORM。面试里 ORM 是必考区，考法很固定——关联怎么定义、N+1 怎么防、软删除怎么实现、模型事件怎么用。好消息是这些概念你在 JS 生态里都见过影子：模型就是 TypeORM 的 Entity、Prisma 的 model，一个类对应一张表，再加上一组操作这张表的方法。今天把 ThinkPHP 8.x 线的模型机制一次讲透。

一、核心解释

1. 模型是什么：一个类对应一张表

模型继承 think\Model，放在 app/model/ 目录下。表名按类名自动推断：User 模型对应 user 表（带上配置里的表前缀）；想改就用 protected $table 自定义表名，用 $pk 自定义主键（默认是 id）。

面试答法：“模型是 ORM 的实体类，一个模型类对应一张表；表名按类名自动推断，也可以用 $table 和 $pk 自定义。业务逻辑尽量放模型里，控制器只做调度。”

2. CRUD：五种写法一次记全

User::create([...]) 新增；User::find(1) 按主键查一条；User::where('status', 1)->select() 条件查多条；拿到实例后改字段再 $user->save() 保存；$user->delete() 删除。注意 -> 相当于 JS 的 .，是 PHP 访问对象成员的写法；:: 是静态调用，类似 JS 的 ClassName.staticMethod()。

面试高频追问：模型方法为什么能静态调用？因为静态调用经 PHP 魔术方法 __callStatic 转发到模型实例执行。User::find(1) 表面上是静态调用，实际是 __callStatic 接住调用、转交给实例去跑查询。答出“__callStatic 转发”这七个字，这道题就稳了。

3. 关联：七种关系，一张表记全

关联是 ORM 的重头戏，think-orm 3.0 提供七种关联：

关联方法关系举例
hasOne一对一用户 — 个人资料
belongsTo反向一对一文章 — 作者（文章属于作者）
hasMany一对多用户 — 文章
belongsToMany多对多文章 — 标签（经中间表）
hasOneThrough远程一对一用户 — 国家（经个人资料）
hasManyThrough远程一对多国家 — 文章（经用户）
morphOne / morphMany / morphTo多态评论可属于文章，也可属于视频

定义方式是在模型里写一个方法：public function profile() { return $this->hasOne(Profile::class); }。参数是 hasOne('关联模型类名', '外键', '主键')，默认外键是 user_id（当前模型名小写加 _id）。

一个容易错的细节：关联方法名是驼峰，读取时属性名自动转下划线。比如方法叫 userProfile()，读取时写 $user->user_profile。面试常拿这个当陷阱题。

4. N+1 问题与预载：with() 是面试必考点

查 100 个用户，再逐个取每个人的 profile，懒加载会发出 101 条 SQL——这就是 N+1 问题。解法是预载：User::with('profile')->select()，一次查询把关联数据一并取出。预载还可以带闭包加约束，只预载符合条件的那部分关联数据。

关联的写入和删除也有配套 API：together() 做关联自动写入/删除，比如 $article->together(['comments'])->delete() 删文章时把评论一起删掉；多对多中间表用 attach() / detach() 挂接和摘除。

5. 软删除：删了，但没完全删

在模型里 use think\model\concern\SoftDelete;（use 相当于 JS 的 import；trait 相当于 JS 的 mixin，把软删除能力混入模型），表里需要一个 delete_time 字段。此后 delete() 不再真删数据，只给 delete_time 写上时间戳；普通查询会自动排除已删记录。

配套方法：withTrashed() 包含已删记录一起查，onlyTrashed() 只看已删的，restore() 恢复，force()->delete() 真删。面试答法：“软删除是逻辑删除，数据还在表里，只打时间戳标记；需要恢复或审计的场景用它，真删用 force()。”

6. 获取器 / 修改器与字段控制

getStatusAttr($value, $data) 是获取器，读取字段时自动转换（比如把 0/1 转成“禁用/启用”）；setPasswordAttr($value) 是修改器，写入字段时自动转换（比如写入密码时自动加密）。命名规则是 get + 字段名驼峰 + Attr / set + 字段名驼峰 + Attr。

另外三个常用属性：$append 追加虚拟属性（表中没有、输出时算出来的字段）；$hidden / $visible 控制输出字段（转数组或 JSON 时哪些字段不出现，比如隐藏密码）；$autoWriteTimestamp 自动维护 create_time / update_time 两个时间戳字段。

7. 模型事件：数据变动的钩子

模型事件是在数据增删改前后自动触发的钩子。两种写法：一是在模型类里写静态方法，如 onBeforeInsert / onAfterInsert / onBeforeUpdate / onAfterDelete；二是用 Model::event('before_insert', function ($model) {...}) 注册回调。典型用途：写入前统一处理字段、删除前清理关联文件、写入后记操作日志。

容易踩的坑：① 关联方法名是驼峰，读取属性是下划线，写反了取不到数据；② 列表页忘了 with() 预载，N+1 直接把接口拖慢；③ 软删除的行还在表里，唯一索引（如 email）仍会冲突，恢复前要先用 withTrashed() 找到它；④ $user->save() 之前要先有实例——要么 find() 出来，要么 new 出来。

二、代码示例

示例 1：模型定义 + CRUD

<?php
namespace app\model;      // 命名空间：对应 app/model/ 目录，类似 JS 的模块路径

use think\Model;          // use 相当于 JS 的 import

class User extends Model  // 继承 think\Model，User 模型默认对应 user 表
{
    // 表名默认按类名推断；想改就取消下面这行的注释
    // protected $table = 'users';   // 自定义表名
    // protected $pk = 'uid';        // 自定义主键，默认是 id

    // 自动维护 create_time / update_time 两个时间戳字段
    protected $autoWriteTimestamp = true;
}
<?php
use app\model\User;

// 新增：create() 接收键值对数组，=> 相当于 JS 对象字面量的冒号
$user = User::create(['name' => 'Linr', 'status' => 1]);

// 按主键查一条；静态调用经 __callStatic 转发到实例
$user = User::find(1);

// 条件查询多条：-> 相当于 JS 的 .，链式调用
$users = User::where('status', 1)->select();

// 修改后保存：先有实例，再 save()
$user->name = 'Arale';
$user->save();

// 删除
$user->delete();

示例 2：关联定义 + 预载 + 软删除

<?php
namespace app\model;

use think\Model;
use think\model\concern\SoftDelete;  // trait：相当于 JS 的 mixin，混入软删除能力

class User extends Model
{
    use SoftDelete;  // 启用软删除，需要表里有 delete_time 字段

    // 一对一：一个用户对应一条个人资料
    // hasOne(关联模型类名, 外键, 主键)，默认外键是 user_id
    public function profile()
    {
        return $this->hasOne(Profile::class);
    }

    // 一对多：一个用户多篇文章
    public function articles()
    {
        return $this->hasMany(Article::class);
    }
}
<?php
use app\model\User;

// 预载：一次查询把 profile 一并取出，避免 N+1
$users = User::with('profile')->select();
echo $users[0]->profile->nickname;  // 关联属性直接当对象属性读

// 预载时带闭包加约束：只预载已发布的文章
$users = User::with(['articles' => function ($query) {
    $query->where('status', 1);
}])->select();

// 关联方法名是驼峰，读取时属性名自动转下划线：
// userProfile() 方法对应 $user->user_profile 属性

// 软删除：delete() 只写 delete_time，不真删
$user->delete();
// 包含已删记录一起查
$all = User::withTrashed()->select();
// 只看已删的
$trashed = User::onlyTrashed()->select();
// 恢复：先 withTrashed() 找到，再 restore()
$trashed[0]->restore();
// 真删
$user->force()->delete();

// 多对多中间表：给文章挂标签 / 摘标签
$article->tags()->attach($tagId);
$article->tags()->detach($tagId);

// 关联自动删除：删文章时把评论一起删掉
$article->together(['comments'])->delete();

示例 3：获取器、修改器与模型事件

<?php
namespace app\model;

use think\Model;

class User extends Model
{
    // 获取器：读取 status 字段时自动转换，0/1 变成中文
    public function getStatusAttr($value, $data)
    {
        return $value ? '启用' : '禁用';
    }

    // 修改器：写入 password 字段时自动加密
    public function setPasswordAttr($value)
    {
        return password_hash($value, PASSWORD_DEFAULT);
    }

    // 模型事件：插入前执行，$model 是当前模型实例
    public static function onBeforeInsert($model)
    {
        // 比如统一生成邀请码、补默认值
    }
}

// 模型事件的另一种写法：用 event() 注册回调
User::event('before_insert', function ($model) {
    // 插入前执行的逻辑
});

三、ThinkJS 对比

ThinkJS 3.x 线的 think-model 同样有关联模型（Relation Model）的概念，API 有 model.relation、model.setRelation(name, value)，支持 mysql / sqlite / postgresql 适配器——和 TP 一样，关联定义与数据库驱动是分开的两层，换库不用改模型代码。

模型事件在 ThinkJS 里叫模型钩子：afterFind / afterSelect 是在查询出数据后执行的钩子，对应 TP 的模型事件思路（在数据生命周期的关键点插逻辑）。另外两个 ThinkJS 的模型特点值得知道：模型会自动分析数据表字段类型、自动做数据安全过滤——TP 这边对应的分别是模型对字段类型的处理和验证器/获取器那一套，Day 8 会讲验证器。

面试怎么说：“两边都有 ORM 关联和模型钩子，思路相通；TP 的关联类型更全（七种，含远程和多态），ThinkJS 的关联 API 更精简。换框架时，关联关系的设计经验是可以平移的。”

五、面试高频问答

Q1：模型方法为什么能静态调用？

经 PHP 魔术方法 __callStatic 转发到模型实例执行。User::find(1) 表面是静态调用，实际是 __callStatic 接住调用、转交给实例去跑查询。所以模型既能静态调用，也能 new User 后实例调用。

Q2：什么是 N+1 问题，怎么解决？

查 N 条主数据，再逐条查关联数据，会发出 N+1 条 SQL。解法是预载：User::with('profile')->select() 一次查询把关联数据一并取出；预载还能带闭包加约束。列表页忘了预载是常见的性能坑。

Q3：软删除和真删除有什么区别？

软删除用 SoftDelete trait，表里要有 delete_time 字段；delete() 只写时间戳、不真删，普通查询自动排除已删记录。withTrashed() 包含已删、onlyTrashed() 只看已删、restore() 恢复、force()->delete() 真删。需要恢复或审计的场景用软删除。

Q4：关联方法名和读取属性名有什么讲究？

关联方法名是驼峰，读取时属性名自动转下划线：userProfile() 方法对应 $user->user_profile 属性。默认外键是当前模型名小写加 _id，比如 user_id，也可以在 hasOne('关联模型类名', '外键', '主键') 里显式指定。

Q5：获取器和修改器分别在什么时候触发？

获取器 getXxxAttr($value, $data) 在读取字段时触发，做展示转换；修改器 setXxxAttr($value) 在写入字段时触发，做入库前处理，比如密码加密。命名规则是 get/set + 字段名驼峰 + Attr。
