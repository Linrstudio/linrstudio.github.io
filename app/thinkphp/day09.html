Day 9：缓存、Session 与队列

缓存、Session、队列是后端面试的“基础设施三件套”：缓存决定接口快不快，Session 决定登录状态怎么存，队列决定耗时任务怎么异步做。ThinkPHP 8.x 线里这三块的 API 都很薄——门面 + 助手函数，真正的考点在配置与边界上：缓存驱动怎么换、Session 为什么默认没开、队列为什么是扩展而不是内置、没有调度器时定时任务怎么做。今天一次讲清。

一、核心解释

1. 缓存：Cache 门面 + 驱动可换

缓存用门面 think\facade\Cache，配置在 config/cache.php，默认 default 为 file 驱动。可选驱动有 file、redis、memcached——换驱动改配置即可，业务代码不用动，这就是门面 + 驱动模式的好处。

四个基本操作：Cache::set('key', $value, 3600) 存（第三个参数是有效期，单位秒）、Cache::get('key', $default) 取（取不到时返回默认值）、Cache::delete('key') 删、Cache::clear() 清空。想临时换存储，用 Cache::store('redis')->set(...) 切换到指定存储。

标签缓存是面试加分点：Cache::tag('tag')->set(...) 给缓存打标签，后续可按标签批量清除。比如文章详情都打上 article 标签，文章更新后一次清掉该标签下的所有相关缓存，不用逐个记 key。面试答法：“单机小项目用 file；多台服务器共享缓存或高并发时上 redis；有关联失效需求时用标签缓存批量清。”

2. Session：默认没开，先开中间件

Session 用门面 think\facade\Session，也有助手函数 session() 可读写。驱动同样是 file / redis / memcached。基本操作：Session::set / get / delete，以及 Session::getId() 取当前会话 ID。

最容易踩的坑：SessionInit 中间件默认在 app/middleware.php 里是注释掉的，需要手动开启 Session 才可用。Session 读不到值时先别怀疑代码，先去 app/middleware.php 看中间件有没有启用。另外还有 Cookie 门面 think\facade\Cookie 和助手函数 cookie()，负责浏览器侧的键值存储，和 Session 是一对搭档。

面试答法：“TP 的 Session 默认不启用，用到时手动开启 SessionInit 中间件；纯 API 项目常用 Token 鉴权，不一定需要 Session。”

3. 队列：扩展，不是内置

队列是扩展 topthink/think-queue（面向 TP6+），不是框架内置功能，这点面试常考。配置在 config/queue.php，用门面 think\facade\Queue，也有助手函数 queue()。

任务类实现 handle($job, $data)：$job 是任务对象，$data 是投递时传的数据；成功后必须调用 $job->delete() 标记完成。投递用 Queue::push($jobClass, $data, $queueName)，三个参数分别是任务类、数据、队列名。

消费命令：php think queue:work 启动 worker 处理队列，--queue 指定队列名，--daemon 以守护进程方式运行；queue:listen 是监听模式。失败处理有一套命令：queue:failed 查看失败任务、queue:retry 重试、queue:flush 清空、queue:restart 重启队列进程。连接器有三种：sync（同步执行，开发调试用）、database、redis。

4. 定时任务：TP 没有内置调度器

ThinkPHP 没有内置的任务调度器。生产环境的常见做法是 Linux crontab 调用 php think 自定义命令：先用 make:command 把定时逻辑写成一条命令，再在 crontab 里配执行时间。面试问“TP 怎么做定时任务”，答“框架没有内置调度器，生产用 crontab + 自定义命令”就是标准答案，不要编一个不存在的调度器 API。

容易踩的坑：① Session 读不到值，先查 app/middleware.php 里 SessionInit 有没有开启；② 队列任务成功后必须 $job->delete()，否则任务不会被标记完成；③ sync 连接器只用于开发调试，生产用 database 或 redis；④ 不要在 TP 里找内置调度器，定时任务靠 crontab。

二、代码示例

示例 1：缓存与 Session

<?php
use think\facade\Cache;
use think\facade\Session;

// 缓存：存 3600 秒，取不到时返回默认值
Cache::set('user_1', $user, 3600);
$user = Cache::get('user_1', null);
Cache::delete('user_1');
Cache::clear();

// 切换存储：这次读写走 redis
Cache::store('redis')->set('hot_list', $list, 600);

// 标签缓存：打上标签，后续可按标签批量清除
Cache::tag('article')->set('article_10', $article, 3600);

// Session：set / get / delete / getId()
Session::set('user_id', 1);
$userId = Session::get('user_id');
Session::delete('user_id');
$sid = Session::getId();

// 助手函数 session() 也可以读写
session('user_id', 1);

示例 2：队列任务类 + 投递 + 消费

<?php
namespace app\job;

class SendMail
{
    // 任务入口：$job 是任务对象，$data 是投递时传的数据
    public function handle($job, $data)
    {
        // 比如发邮件、发短信等耗时操作
        // ...

        // 成功后必须删除任务，标记完成
        $job->delete();
    }
}
<?php
use think\facade\Queue;

// 投递：任务类、数据、队列名
Queue::push(SendMail::class, ['to' => 'a@b.com'], 'mail');
# 消费：启动 worker 处理 mail 队列，--daemon 以守护进程方式运行
php think queue:work --queue=mail --daemon
# 监听模式：任务变化时自动重载
php think queue:listen
# 失败任务管理
php think queue:failed   # 查看失败任务
php think queue:retry    # 重试失败任务
php think queue:flush    # 清空失败任务
php think queue:restart  # 重启队列进程

示例 3：定时任务——crontab + 自定义命令

# TP 没有内置调度器，定时任务靠系统 crontab 调自定义命令
# 每天凌晨 2 点跑一次数据清理命令
0 2 * * * php /path/to/project/think cleanup

动手任务（10 分钟）

1. 用 Cache::set / get 存取一个值，再用 Cache::store('redis') 切换存储（本地没装 redis 也没关系，知道 API 怎么写就行）。
2. 故意不开启 SessionInit 中间件，跑一次 Session::set / get，确认拿不到值；再开启中间件重跑，对比结果。
3. 写一个最小队列任务类（handle($job, $data) 里只写一行日志 + $job->delete()），用 sync 连接器投递一次，确认任务同步执行。

三、ThinkJS 对比

缓存这块两边思路几乎一样，都是适配器模式：ThinkJS 在 src/config/adapter.js 里配 exports.cache = { type: 'file' }（可换 redis / memcache），用 think.cache(key, value) 读写；TP 在 config/cache.php 里配驱动，用 Cache 门面读写。Session 也类似：ThinkJS 用 this.session('userInfo')，TP 用 Session 门面或 session() 助手。

队列与定时任务两边也都“没有内置”：ThinkJS 同样没有内置队列与定时任务，队列走 bull / bee-queue 等 npm 生态，定时任务可用 node-schedule 或 think-crontab 扩展；TP 这边是 think-queue 扩展 + crontab。换句话说，这两个框架在基础设施层的取舍是一致的——核心框架保持精简，队列与调度交给扩展与系统工具。

面试怎么说：“缓存两边都是适配器模式，TP 是 Cache 门面 + config/cache.php，ThinkJS 是 think.cache + adapter.js；队列两边都没有内置，TP 用 think-queue 扩展，ThinkJS 用 bull / bee-queue；定时任务 TP 靠 crontab，ThinkJS 靠 node-schedule 或 think-crontab。”

得分：0 / 3

解析：选 A。SessionInit 默认在 app/middleware.php 里是注释掉的，必须手动开启 Session 才可用。

2. 队列任务成功执行后，任务类里必须做什么？

解析：选 B。handle() 成功后必须 $job->delete()，否则任务不会被标记完成。

五、面试高频问答

Q1：file / redis / memcached 缓存驱动怎么选？

单机小项目用 file，零依赖、够用；多台服务器要共享缓存或高并发场景上 redis；memcached 适合纯缓存场景。TP 用门面 + 驱动模式，换驱动改 config/cache.php 即可，业务代码不用动；也可以用 Cache::store('redis') 临时切换存储。

Q2：SessionInit 中间件为什么默认是注释掉的？

框架默认不启用 Session，用到时手动开启。不是所有项目都需要 Session——纯 API 项目常用 Token 鉴权，不依赖服务端会话。Session 读不到值时先查 app/middleware.php 里中间件有没有启用，再查驱动配置。

Q3：队列任务失败了怎么办？

think-queue 有一套失败处理命令：queue:failed 查看失败任务、queue:retry 重试、queue:flush 清空、queue:restart 重启队列进程。任务类里成功后要 $job->delete()，否则不会被标记完成。

Q4：ThinkPHP 怎么做定时任务？

TP 没有内置调度器。生产常用 Linux crontab 调用 php think 自定义命令：先用 make:command 把定时逻辑写成一条命令，再在 crontab 里配执行时间。不要编一个不存在的调度器 API。

Q5：标签缓存有什么用？

Cache::tag('tag')->set(...) 给缓存打标签，可按标签批量清除。比如文章详情都打上 article 标签，文章更新后一次清掉该标签下的所有相关缓存，不用逐个记 key，解决的是“关联失效”的问题。

六、加分项

简历讲法：别写“熟悉缓存与队列”，写“热点列表用 Cache 标签缓存 + redis 存储，更新时按标签批量失效；注册邮件、短信通知走 think-queue 异步投递，失败任务用 queue:failed / queue:retry 处理；每日报表用 crontab + 自定义命令定时跑”。前者是名词，后者是可追问的异步与缓存实践。
