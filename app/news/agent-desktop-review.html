agent-desktop 实测：不看截图，AI 照样能点按钮

2026-11-20 · 真实安装实测 · Linux 虚拟机（Xvfb + openbox，无真实显示器）

先说结论：它真能做到不用截图就操作桌面应用。我在一个没有显示器的 Linux 虚拟机里跑完了完整一轮——抓快照、按名字找到输入框、输一句话、点 OK，对话框把我输的文字原样吐了出来。全程没有一张截图，没有一次猜像素。

但装好之前，我先摔了两跤。

第一跤：仓库不在 vercel 下面

我是从 npm 装的。npm install -g agent-desktop，2 秒装好，版本 1.3.1。装之前我先去 GitHub 想看一眼 README，vercel/agent-desktop，404。真正的仓库是 vercel-labs/agent-desktop，25,648 星。包本身 32MB，Apache-2.0 协议，6 天前刚发过版。

装完先跑 agent-desktop status。在没有桌面会话的 shell 里，它直接说 accessibility 是 denied，还给了提示：没有 D-Bus 会话总线，用 dbus-run-session 起一个。进了会话再跑，granted，支持 window、sheet、alert、menu 四种 surface。这个报错算诚实的——它不装作能用，而是告诉你缺什么。

第二跤：没有窗口管理器，它认不出窗口

我打开一个 zenity 输入框当测试对象，然后 list-apps、snapshot 全报同一个错：

ACTION_NOT_SUPPORTED，"The native window type of accessibility
frame owned by pid N could not be proven"

翻译过来：没有窗口管理器，它没法把无障碍树里的窗口和 X11 客户端对上号。官方 Linux 文档里写了，他们自己的例子就是跑在 Xvfb + openbox 上。我装了 openbox 再试，zenity 立刻就出现了。

还有个跟它无关的小插曲：我的虚拟机 locale 是 POSIX，zenity 的中文参数直接报错，设了 LC_ALL=C.UTF-8 才好。这是我的环境问题，不是它的。

抓快照：3 个 ref，没有多余的东西

agent-desktop snapshot --app zenity -i --compact，返回 3 个 ref：输入框 e1，Cancel 按钮 e2，OK 按钮 e3。每个 ref 都带可用动作——输入框能 Click、SetValue、TypeText、SetFocus。

不过树本身很深：就算加了 --compact，输入框外面还包着 6 层 group。这是 GTK 对话框的真实结构，不是它啰嗦。换成 Slack、浏览器这种复杂应用，快照只会更大，README 建议先用 --skeleton 看骨架，再钻到某个区域里。

输入：它不是在模拟键盘

agent-desktop type @s15f4j7nlnbdxc:e1 "Hello from agent-desktop"，返回 delivered_verified。关键在 mechanism 那一行：semantic_api，EditableText.InsertText——它是调无障碍接口把文字插进去的，不是模拟键盘一个键一个键敲的。

再抓一次快照验证，输入框的 value 已经是 "Hello from agent-desktop"。对话框里也能直接看到这句话。

点 OK：闭环了

agent-desktop click @s1txpf6izk8w2z:e3，返回 delivered_unverified。unverified 不是失败——对话框点完就关了，没什么可验证的。这个诚实我喜欢，它不假装验证了没法验证的东西。

zenity 退出时把输入的文字打印到标准输出：Hello from agent-desktop。再跑 list-apps，空了。整轮下来不到 7 秒。

MCP：75 个工具，握手一次就通

接 Claude Code 走的是 MCP：agent-desktop mcp 起一个 stdio 服务。我没接 Claude Code，只是手动发了一次握手：server 是 agent-desktop 1.3.1，tools/list 返回 75 个工具，desktop_snapshot、desktop_click 都在。README 里给的配置就一行 mcpServers。

能用在哪，不能用在哪

它没有内置模型——README 里写了，循环在调用方。它只是手和眼睛：看无障碍树、按 ref 操作、再看一遍确认结果。脑子得你自己配，Claude Code 或者你自己的 agent。

Linux 上要 AT-SPI 和一个窗口管理器，无头环境得自己搭 Xvfb + openbox，Mac 和 Windows 我没测。测试对象 zenity 是个简单对话框，复杂应用的快照会大得多，得按 README 说的先骨架后钻取。--headed 物理输入我也没测。

适合的人：想给 agent 加电脑操作能力，又不想走截图猜像素那条路的人。25,648 星，Vercel Labs 出品，Apache-2.0，npm 一行装好，值得一试——先从一个小任务开始，别一上来就让它操作你的主力应用。

本文所有截图都是实测时直接截的 Xvfb 桌面（scrot 抓屏），没有重排、没有模拟。终端里的「停在这里，等截屏」是演示脚本的暂停提示，如实保留。测试环境：Linux 虚拟机，Xvfb + openbox，agent-desktop 1.3.1。原文链接：github.com/vercel-labs/agent-desktop
