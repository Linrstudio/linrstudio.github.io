Day 37：第 5 周复盘：Multi-Agent 项目与面试讲法

第 5 周的最后一课，把 Multi-Agent 和 MCP 收束成一个完整项目：从 Supervisor 分发、Planner 拆 DAG、Knowledge 检索、MCP 工具调用、纵深防御、Verifier 校验、Composer 合成，一条链路走下来。再讲这条链路怎么评测、面试怎么讲——第 5 周结束时，你手里应该有一个能讲清、能演示、能报数字的 Multi-Agent 项目，而不是一堆名词。

一、核心解释

1. 第 5 周复盘：一张表收束

2. 完整链路怎么走：一个任务从头到尾的顺序

拿“查某产品两版退货政策并对比”当例子，链路是：Supervisor 接到任务 → Planner 拆成 DAG（查 2024 版、查 2025 版、对照差异、合成）→ Knowledge Agent 跑 Multi-hop 检索（每跳留痕、带出处）→ 需要调工具时走 MCP（list_tools 发现、纵深防御过一遍）→ Verifier 按三项标准查（测试、引用、schema）→ 不过打回、超上限交给 Supervisor → Composer 分段合成、标出处、冲突显式写出。链路里的每一步都有名字、有标准、有留痕，面试时按这个顺序讲，面试官才能跟得上。

接力赛：六棒交接，一棒掉棒整队都得等

整条链路像一场接力：棒（任务）只能一棒一棒往下传，校验是裁判，不过就打回重跑，谁也不能自己改顺序抢跑。

3. EvalHarness 怎么评测多 Agent：五个指标一起报

单 Agent 的评测只看最终答案对不对，多 Agent 还要看每路的表现。五个指标：任务成功率（最终答案通过全部校验的比例）、每路成功率（Planner 拆得稳不稳、Knowledge 命中率高不高、Verifier 拦截率多少，定位弱环就靠它）、成本（平均 Token 和调用次数，并行越多成本越高，要报出来）、延迟（关键路径耗时，并行省下的时间要算进去）、失败分布（失败都栽在哪一步：检索、工具、校验还是合成）。只报任务成功率，会掩盖“某一路一直在失败、靠别的路兜底”的问题；五个一起报，弱环藏不住。

体检报告单：五个指标一起看，弱环藏不住

只报任务成功率就像只看体检总分：82% 看着还行，但知识一路只有 78%、失败 12 次都栽在检索上——五个指标一起报，弱环才藏不住。

4. 面试讲法：按任务讲，不要按名词讲

面试讲 Multi-Agent，最忌讳罗列名词：“我用过 Supervisor、MCP、Verifier”。要按任务讲：任务是什么、为什么要拆成多 Agent（单 Agent 的哪块天花板撞上了）、DAG 怎么拆的、每路的验收标准是什么、哪路失败过、怎么隔离和打回的、五个评测数是多少、如果重做会改哪里。讲的时候带一张图（Supervisor、Planner、Knowledge、Tool、Verifier、Composer 六个节点和箭头），图一摆，面试官就知道你不是背名词，是真搭过。

讲故事三段式：像破案一样讲你的项目

别一上来就报名词：先讲案发（任务和拆的理由），再讲破案（最难的失败和打回），最后结案（重做改哪里、五个评测数）——面试官听的是一个真搭过的故事，不是名词清单。

容易踩的坑：复盘只写“学到了什么”，不写“哪里还不行”。第 5 周复盘必须写两栏：做对的（链路、标准、留痕）和没做好的（哪路成功率低、成本哪里高、哪次冲突处理得不好），没做好的那栏就是下一个项目的起点。

四、可能的面试题与答案

Q1：第 5 周的完整链路怎么走？

Supervisor 接任务、Planner 拆 DAG、Knowledge 跑 Multi-hop 检索、工具走 MCP 加纵深防御、Verifier 按三项标准查、不过打回、Composer 分段合成标出处、冲突显式写出。每一步有名字、有标准、有留痕。

Q2：多 Agent 怎么评测？

五个指标一起报：任务成功率、每路成功率、成本、延迟、失败分布。只报任务成功率会掩盖某一路一直在失败、靠别的路兜底的问题；每路成功率定位弱环，失败分布告诉下一轮先优化哪里。

Q3：面试怎么讲 Multi-Agent 项目？

按任务讲：任务是什么、为什么拆（单 Agent 哪块天花板撞上了）、DAG 怎么拆、每路验收标准、哪路失败过、怎么隔离打回、五个评测数、重做改哪里。带一张六节点图，不要罗列名词。

Q4：Multi-Agent 和单 Agent 怎么选？

看 Day 31 的三项：拆开后每路是不是有独立输入、独立工具、独立验收标准？三项基本满足就拆，缺两项别拆；任务一步能做完，硬拆只多成本和出错点。

Q5：第 5 周之后还缺什么？

第 5 周补的是协作和工具治理，之前第 4 周的 Computer Use 安全边界、上线加固和最后 2 天的面试模拟，合起来才是一个完整的 AI Agent 项目闭环。

五、加分项

生产视角：第 5 周收尾时，先问三个问题：完整链路能按顺序讲清吗？五个评测数报了吗？弱环是哪一路、下一轮先优化它吗？三问有一个答不上来，第 5 周就不算闭环。

简历讲法：别写“做过 Multi-Agent 项目”，写“Supervisor 分发、Planner 拆 DAG、Knowledge 跑 Multi-hop 检索、MCP 工具加纵深防御、Verifier 三项标准校验、Composer 分段合成，任务成功率 82%、弱环 Knowledge 78%（待实测不要编数）”。前者是名词，后者是可追问的项目。
