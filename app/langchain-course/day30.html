Day 30：面试模拟 2：系统设计、手写代码与复盘 | LangChain 30 天实战课

先说一句取舍：冲刺计划里这一段原本是 3 天——项目深挖、系统设计、手写代码各一天。Day 29 已经做了项目深挖，剩下两天的内容并进这一课：系统设计和手写代码合在一起讲，再加一个复盘错题的收尾。不硬塞成 3 天，是因为这三件事面试时本来就是一道题：先画架构，再手写核心循环，最后讲你怎么从错里长进。

一、核心解释

1. 系统设计模拟：设计一个“客服 Agent”

面试官让你“设计一个客服 Agent”，他不是要你背架构图，是要看你脑子里有没有分层。是什么：一个能回答用户问题、能查订单、答不上来就转人工的 Agent。为什么这样分：用户的问题分三类——查状态的（走工具）、问政策的（走知识库）、吵架和敏感操作的（走人工），三类问题用同一种办法处理，迟早有一类翻车。怎么做：先画路由器，再画三条路，最后画三条底线。

路由（问题分给谁）：路由器先看问题类型：带订单号的去查订单工具，问“能不能退货”的去知识库，情绪激烈或涉及退款、改地址、删账号的直接转人工。路由规则先用关键词和意图分类写死，别一上来就让模型临场判断——规则可测，临场发挥不可测。

降级（坏了怎么办）：模型挂了，走缓存答案或直接转人工，并告诉用户“系统繁忙，已转人工”，不要假装正常；知识库检索为空，不要编答案，要说“没查到相关政策”，同时给两个选项：换个问法，或转人工。降级的核心就一句话：宁可承认不会，也别编一个错的。

评测（怎么知道它变好了）：离线先建评测集——50 到 100 条真实问题，每条写好标准答案和打分点，每次改提示词或换模型都跑一遍，看分数是升是降；线上再抽查——每天随机抽 5% 的真实对话，人工看有没有答错、答偏、泄露信息。只看线上好评率没用，好评率涨可能是用户懒得点差评。

安全（红线在哪）：两条红线不能碰。第一，用户数据不出界：订单号、地址、手机号只能传给有权限的工具，不能原样塞进提示词发给第三方模型，更不能出现在日志里；第二，敏感操作必须人工确认：退款、改地址、删账号这类动作，Agent 只能起草，不能直接执行，点确认的人必须是真人。

容易踩的坑：一上来就画十几个框的“完美架构”。面试里先画最小闭环——路由 + 一条工具路 + 一条知识库路 + 人工接管 + 一条降级线，画完再问面试官“要不要展开评测和安全”，让他带你往深里走。

2. 手写代码模拟：不用 LangChain，手写 Tool Calling 循环

面试官让你“不用框架写一个 Agent”，他想看的是你懂不懂循环的本质。是什么：Tool Calling 循环就四步——把用户消息发给模型；模型要么直接给答案，要么说“我要调工具 X，参数是 Y”；你执行工具，把结果追加进消息列表；再问模型，直到它给答案或到最大步数。为什么不用框架也行：LangChain、LangGraph 都是把这个循环包了一层，循环本身只是个 for 加 if。你能手写出来，说明你不是只会调 API。怎么做：先写一个本地桩模型（stub）代替真模型——按关键词决定调哪个工具，不调真实 API、不用 Key，循环跑通了再换真模型，循环一行不用改。最大步数必须设（通常 4–5 步），否则模型一直调工具，循环永远停不下来。示例 1 就是这段循环的完整实现，本地真跑通过，输出写在代码注释里了。

3. RAG 检索函数：先看懂“打分 + 取前 K”

检索听起来高大上，骨架就两步：给每篇文档打个分，按分取前 K 篇。是什么：retrieve(问题) 返回最相关的几篇文档，Agent 再拿着它们生成答案。为什么先学关键词版：向量检索只是把“打分”换成向量相似度，骨架一模一样——先看懂骨架，再换打分方法，就不会被新名词吓住。怎么做：示例 2 用本地 3 篇小语料：问题按字切，文档里命中词越多分越高，取前 2 篇。注意它的短板：第三个测试问题“今天天气怎么样？”明明和语料无关，却因为共用了一个“天”字，误命中了退货政策那篇——关键词只看字面重合，既会误命中，也认不出同义词（“包邮”和“免运费”它就认不出来）。生产里的做法是加两道保险：分数低于阈值就返回空、走降级；再把打分换成向量相似度。先跑通关键词版，再升级，这就是从能跑到能用的路。

4. 复盘错题：错题本的四步，错一次要长一智

面试官最爱问“讲一个你搞砸过的事”，他不是想听你认错，是想看你有没有复盘能力。是什么：错题本就四列——错题、根因、改法、再测。为什么四步缺一不可：只记错题不找根因，下次换个样子照样错；找到根因不改，等于没复盘；改了不重测，你根本不知道改没改对。怎么做：拿 Day 15 的 RAG 实验举例。错题：检索回来的文档答非所问；根因：切块太大，一篇文档里塞了三个主题，检索命中了主题 A 却拿去答主题 B；改法：按小节切块，每块只讲一个主题；再测：同一批问题重跑一遍，看命中率从多少升到多少，数字写下来。复盘到这一步，错题就变成了面试里的加分项：你讲的不是“我错过”，而是“我错过、找到原因、改了、测了、数字变好了”——面试官听到这套，就知道你上线后出问题也能自己兜住。

二、代码示例

示例 1：手写 Tool Calling 循环 + 本地桩模型（能跑的代码）

# 手写 Tool Calling 循环：纯 Python，不调真实 API，不需要 Key
# 桩模型 stub_llm 只按关键词做决定——真模型换掉它，循环不用动

def check_order(order_id):
    return f"订单 {order_id}：已发货，快递单号 SF888，昨天 18:00 已揽收。"

TOOLS = {"check_order": check_order}

def stub_llm(messages):
    tool_msgs = [m for m in messages if m["role"] == "tool"]
    if tool_msgs:
        return {"answer": f"查到了：{tool_msgs[-1]['content']}预计明天送达。"}
    last = messages[-1]["content"]
    if "订单" in last and "12345" in last:
        return {"tool": "check_order", "args": {"order_id": "12345"}}
    return {"answer": "已收到，我来帮你处理。"}

def run_agent(user_msg, max_steps=4):
    messages = [{"role": "user", "content": user_msg}]
    for step in range(max_steps):
        out = stub_llm(messages)
        if "answer" in out:
            return out["answer"]
        result = TOOLS[out["tool"]](**out["args"])
        print(f"第 {step + 1} 步：调工具 {out['tool']}，拿到：{result}")
        messages.append({"role": "tool", "content": result})
    return "已到最大步数，转人工接管。"

print(run_agent("我的订单 12345 到哪了？"))

# 本地实跑输出（python3 day30_ex1.py）：
# 第 1 步：调工具 check_order，拿到：订单 12345：已发货，快递单号 SF888，昨天 18:00 已揽收。
# 查到了：订单 12345：已发货，快递单号 SF888，昨天 18:00 已揽收。预计明天送达。

示例 2：RAG 检索函数（能跑的代码）

# RAG 检索函数：本地小语料 + 关键词打分，不调真实 API
DOCS = [
    {"id": 1, "text": "退货政策：7 天内无理由退货，商品需保持完好。"},
    {"id": 2, "text": "运费说明：满 99 元包邮，未满收 8 元运费。"},
    {"id": 3, "text": "换货流程：先申请换货，寄回旧品后发出新品。"},
]

def retrieve(query, top_k=2):
    # 思路：把问题按字切，命中词越多分越高；真实做法是向量相似度，
    # 关键词版能跑通，先看懂“检索 = 打分 + 取前 K”的形状
    scored = []
    for doc in DOCS:
        score = sum(1 for ch in query if ch in doc["text"])
        scored.append((score, doc))
    scored.sort(key=lambda x: x[0], reverse=True)
    return [doc for score, doc in scored[:top_k] if score > 0]

print(retrieve("我想退货怎么办？"))
print(retrieve("运费多少钱？"))
print(retrieve("今天天气怎么样？"))

# 本地实跑输出（python3 day30_ex2.py）：
# [{'id': 1, 'text': '退货政策：7 天内无理由退货，商品需保持完好。'},
#  {'id': 3, 'text': '换货流程：先申请换货，寄回旧品后发出新品。'}]
# [{'id': 2, 'text': '运费说明：满 99 元包邮，未满收 8 元运费。'}]
# [{'id': 1, 'text': '退货政策：7 天内无理由退货，商品需保持完好。'}]
# 注意第三行：问天气却命中了退货政策，只因共用一个“天”字。
# 这就是关键词检索的短板——生产里要加分数阈值，低于阈值返回空、走降级。

示例 3：降级与人工接管的守门函数（概念代码，先看形状）

# 概念代码，先看形状：降级与人工接管的守门函数
def answer_with_fallback(user_msg):
    try:
        result = run_agent(user_msg)   # 示例 1 的循环
    except Exception:
        return handoff(user_msg, reason="模型调用失败")
    if not result or "不知道" in result:
        return handoff(user_msg, reason="知识库没有相关内容")
    if is_sensitive(user_msg):  # 退款、改地址、删账号等敏感操作
        return handoff(user_msg, reason="敏感操作，需人工确认")
    return result
# 形状就三层：先抓异常、再判空答案、最后拦敏感操作。
# 每一层失败都走同一条路：转人工，并写清原因，方便复盘。

四、可能的面试题与答案

Q1：设计一个客服 Agent，架构怎么画？

先画最小闭环：用户问题 → 路由器 → 三条路（查订单工具、知识库检索、人工接管）→ 合成回答，底下再画三条底线（降级、评测、安全）。路由规则先写死、不靠模型临场判断；敏感操作必须人工确认；模型挂了、知识库空了都有降级线。画完问面试官要不要展开评测和安全，让他带你往深里走。

Q2：模型挂了 / 知识库空了，你怎么降级？

模型挂了走缓存答案或直接转人工，并告诉用户“系统繁忙，已转人工”；知识库空了就说没查到，给换个问法或转人工的选项。核心一句话：宁可承认不会，也别编一个错的答案。还要补一句：降级要写日志，不然复盘时不知道哪条路兜的底。

Q3：不用 LangChain，手写 Tool Calling 循环怎么写？

四步循环：发消息给模型 → 模型要么给答案、要么返回工具调用 → 执行工具、把结果追加进消息 → 再问模型，直到给答案或到最大步数（4–5 步）。先拿本地桩模型跑通循环，换真模型时循环不用改。能说出“最大步数防死循环”和“工具结果要追加进消息”这两点，就过关了。

Q4：RAG 检索怎么做？关键词和向量有什么区别？

骨架一样：给每篇文档打分、取前 K 篇。关键词版按字面命中打分，能跑通但会误命中、认不出同义词；向量版按语义相似度打分，更准，但要先把文档切块、向量化、建索引。生产里还要加分数阈值，低于阈值返回空、走降级。

Q5：讲一个你复盘过的错。

按“错题 → 根因 → 改法 → 再测”讲：比如 RAG 检索答非所问，根因是切块太大、一块里塞了三个主题，改法是按小节切块、每块一个主题，再测是同一批问题重跑、命中率从多少升到多少。面试官想听的不是你错过，而是你定位到具体技术点、改了、拿数字验证了。

五、加分项

生产视角：系统设计题答完，面试官心里其实在勾三个框：有没有路由（不是所有问题一个打法）、有没有降级（坏了怎么办）、有没有评测（怎么知道变好了）。三框勾满，再补一句安全红线（数据不出界、敏感操作人工确认），这道题就稳了。手写代码题同理：循环写对只是及格，答出“最大步数防死循环”和“桩模型先跑通”才是加分。

简历讲法：别写“设计过客服 Agent”，写“路由器分流三类问题（工具 / 知识库 / 人工），模型故障走缓存或转人工，离线评测集 50 条 + 线上 5% 抽查，敏感操作人工确认”。也别写“会手写 Agent”，写“手写 Tool Calling 循环（桩模型跑通，最大步数 4 步防死循环）+ 本地 RAG 检索（打分取前 K，加阈值降级）”。前者是名词，后者是面试官能顺着追问的设计。
