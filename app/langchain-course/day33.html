Day 33：Knowledge Agent：把 RAG 做成一个子 Agent

第 3 周的 RAG 是一条流水线，这课把它升级成一个子 Agent：Knowledge Agent。区别是，流水线是“查一次、答一次”，子 Agent 是“查不够就再查、查偏了就换词查、查不到就老实说”。Supervisor 把“需要查资料”的子任务派给它，它内部跑检索循环，最后交出带出处的结果，而不是一堆没整理的资料块。

一、核心解释

1. 从流水线到子 Agent：多出来的三样能力

流水线是固定顺序：切块、向量、检索、生成，一步走完就结束。子 Agent 多了三样：判断（这次检索够不够回答？不够就再查）、换策略（关键词查不到就换同义词、换向量查、换上一跳的结果当查询词）、止损（查了几轮还是不够，就停下来、诚实回答）。这三样让 Knowledge Agent 能处理流水线处理不了的复杂问题，比如 Day 21 补充过的 Multi-hop 问题。

2. Multi-hop 检索循环：分解、检索、判断、再检索

循环是四步：分解（原问题拆成有依赖的子问题）、检索（每跳查一次，TopK 不宜太大，5 左右就够）、判断（本跳的结果能不能回答本跳的子问题？能不能为下一跳提供查询词？）、再检索（不够就用新信息生成下一跳的查询）。比如“某产品 2024 版政策和 2025 版改了什么”：第一跳查 2024 版，第二跳用第一跳拿到的条款编号查 2025 版变更，第三跳对照两版回答。每跳的查询、命中块、判断结论都要写进状态，答错了才能定位是哪一跳歪了。

先记住一句话：多跳不是查得多，而是上一跳的答案变成下一跳的查询词。下面三个例子，一个比一个更能说明这句话。

什么时候不用多跳：问题里只有一个不知道的东西，比如“2024 版退货期限是几天”，一次检索就够了。硬拆成多跳，只会多出成本和出错点。判断标准和例 B 一样：问题里藏没藏着中间答案。

3. 引用与出处：子 Agent 的交付标准

Knowledge Agent 交给 Supervisor 的不是“答案”，而是“带出处的结果”：每条结论后面标 [资料 N]，每块资料带标题路径和原文片段。Supervisor 和 Composer 汇总时，只汇总带出处的部分，没出处的不进最终答案。引用还有一道 Day 18 的校验：结论里的数字、日期、人名，必须能在标的那块资料里找到，找不到就改写或删除，不把“引用对了出处、内容却是编的”放过去。

4. 检索失败时的诚实回答：没查到，比编一个更重要

检索失败有三种：查了几轮都没命中、命中的块和问题无关、资料本身就没有这部分。三种的处理都一样：停下来，写清“查了哪几轮、用什么词查的、为什么判定为没查到”，最终回答里说“资料里没有这部分”，而不是用模型训练知识去填空。诚实回答不是能力不足的遮羞布，是 RAG 系统可信的底线——用户能接受“没查到”，不能接受“查到了假的”。

容易踩的坑：检索循环没有跳数上限。没有上限的循环会在“换词再查”里无限转下去，成本和延迟一起炸。跳数上限通常设 3–5 跳，超了就停、诚实回答。

二、代码示例

示例 1：Knowledge Agent 的检索循环（概念代码，先看形状）

MAX_HOPS = 3  # 跳数上限，超了就停、诚实回答，不要无限转下去

def knowledge_agent(sub_question):
    trace = []   # 每跳留痕：查了什么、命中哪几块、判断结论
    query = sub_question
    for hop in range(MAX_HOPS):
        chunks = retrieve(query, top_k=5)   # 每跳 TopK 不宜太大
        trace.append({"hop": hop, "query": query, "chunks": chunks})
        # 判断：够回答了吗？不够的话，下一跳问什么？
        if enough_to_answer(chunks, sub_question):
            return {"chunks": chunks, "trace": trace, "cited": True}
        query = next_query(chunks, sub_question)  # 用本跳结果生成下一跳查询
    # 超上限：诚实回答，写清查了几轮、为什么判定为没查到
    return {"chunks": [], "trace": trace, "cited": False,
            "reason": "查了 3 轮，未命中可回答的资料"}

示例 2：带出处的交付格式（概念代码）

# Knowledge Agent 交给 Supervisor 的结果，必须带出处，不是一堆裸资料
result = {
    "conclusions": [

        {"text": "2025 版改为 15 天", "source": "资料2：2025 变更公告第 2 条"},
    ],
    "trace": trace,  # 每跳的查询和命中块，复盘时定位哪一跳歪了
}

四、可能的面试题与答案

Q1：为什么要把 RAG 做成一个子 Agent？

因为复杂问题一次检索不够：子 Agent 能判断够不够、换策略再查、查不到止损。流水线是固定顺序，子 Agent 是带判断的循环，能处理 Multi-hop 问题。

Q2：Multi-hop 循环怎么跑？

分解、检索、判断、再检索：每跳 TopK 约 5 个，判断本跳够不够、能不能为下一跳提供查询词；每跳留痕，跳数上限 3–5 跳，超了就停、诚实回答。

Q3：Knowledge Agent 的交付标准是什么？

带出处的结果：每条结论标 [资料 N]，每块带标题路径和原文；结论里的数字、日期、人名必须能在标的资料里找到，否则改写或删除。

Q4：检索失败有几种？怎么处理？

三种：几轮都没命中、命中的块无关、资料本身就没有。处理都一样：停下来，写清查了几轮、用什么词、为什么判定没查到，最终说资料里没有，不填空。

Q5：Knowledge Agent 和 Supervisor 怎么分工？

Supervisor 派“需要查资料”的子任务，Knowledge Agent 内部跑检索循环、交出带出处的结果；Supervisor 只汇总带出处的部分，没出处的不进最终答案。
