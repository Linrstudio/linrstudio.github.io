Day 21：混合问答 Agent：RAG 和工具怎么一起调

第 3 周的最后一课，把 RAG 和工具合起来：真实问题很少只沾一边，“深圳今天天气怎么样，顺便讲讲 LangChain 的记忆怎么做预算”——前半句走工具，后半句走 RAG，答案要合起来、出处要分开标。

一、核心解释

2. 混合问题怎么拆：先拆子问题，再分别走

混合问题：“深圳今天天气怎么样，顺便讲讲 LangChain 的记忆怎么做预算”
  → 拆成两个子问题：
    ① “深圳今天天气怎么样” → 走天气工具
    ② “LangChain 的记忆怎么做预算” → 走 RAG
  → 两个子问题的结果都回来，再合起来生成最终回答
  → 出处分开标：天气部分标 Open-Meteo，记忆部分标 [资料N]

拆的原则是：一个子问题只走一条路。子问题本身还是混合的，就继续拆，直到每个子问题只走一条路为止。拆不干净就合起来，答案里天气和文档的出处就会混在一起，查都查不清。

3. 合起来怎么合：先分段，再组织，不要混写

最终回答要分段：天气一段、文档一段，每段后面标自己的出处。不要把天气数字和文档结论写在同一句话里——同一句话里两个出处，引用就没法标了。分段不是排版问题，是出处问题：出处分不开，引用就不可信。

4. 一边失败了，另一边怎么办：失败隔离，不要全盘崩

天气工具超时了，RAG 那段照样可以回答；RAG 检索为空了，天气那段照样可以回答。失败的那段，回答里写清楚“天气工具超时了，没查到”或者“资料里没有这部分”，不要让一边失败拖垮整个回答，也不要用另一边的答案去填失败那段的空——填空就是现编。

容易踩的坑：混合问题不拆，直接丢给模型。模型会凭感觉决定先答哪段、漏哪段，天气数字可能从训练知识里编，文档结论可能从天气工具结果里拼。拆问题是混合问答的第一步，不是可选项。

二、代码示例

示例 1：混合问答骨架（概念代码，先看形状）

def hybrid_answer(question):
    sub_questions = split_question(question)
    # 拆：每个子问题只走一条路，拆不干净就继续拆
    results = {}
    for sub in sub_questions:
        route_result = route(sub)  # Day 20 的路由：天气词走工具，否则走 RAG
        if route_result == "weather_tool":
            results[sub] = get_weather("深圳")  # 工具结果，带出处和时间
        else:
            results[sub] = rag_answer(sub)     # RAG 结果，带 [资料N] 引用
    # 合：分段组织，每段标自己的出处，不要混写
    return compose_answer(results)

# 失败隔离：某一边失败了，另一边照样回答，失败那段写清楚原因，不要填空

四、可能的面试题与答案

Q1：混合问题怎么处理？

先拆成子问题，每个子问题只走一条路，拆不干净就继续拆；分别走工具和 RAG，结果都回来再分段合起来，每段标自己的出处；一边失败了，另一边照样回答，失败那段写清楚原因，不要填空。

Q2：为什么最终回答要分段？

分段不是排版问题，是出处问题：天气出处是 Open-Meteo，文档出处是 [资料N]，同一句话里混两个出处，引用就没法标了。分段写，每段标自己的出处，引用才可信。

Q3：失败隔离怎么做？

天气工具超时了，RAG 那段照样回答；RAG 检索为空了，天气那段照样回答。失败那段写清楚原因，不要让一边失败拖垮整个回答，也不要用另一边的答案去填空。

Q4：第 3 周学完，你能做出什么？还缺什么？

能做出：带评测的 RAG、深圳天气工具、混合问答 Agent。还缺的是：Computer Use 的安全边界、上线加固、面试模拟，这些正是第 4 周和最后 2 天的内容。

Q5：RAG 和工具，什么时候一起用、什么时候分开用？

问题只沾一边，就只走一边；问题两边都沾，就拆开走、再合起来。拆的原则是一个子问题只走一条路，合的原则是分段标出处、失败隔离。
