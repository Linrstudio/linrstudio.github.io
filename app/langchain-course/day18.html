Day 18：重排、引用与防幻觉

检索回来的块，不等于可以直接用的块。今天讲检索之后的三件事：重排怎么把最相关的往前放，引用怎么写才可核查，资料里没有时怎么拦住模型现编。

一、核心解释

1. 重排是干嘛的：向量排的是方向，重排排的是“对这个问题有没有用”

向量检索按语义方向排，方向接近不等于对这个问题有用：比如问题问“退货要几天”，向量可能先返回“退货流程很顺”而不是“退货 7 天内”。重排就是第二遍排序：用一个更强的打分方式（比如交叉编码器、或者让模型自己判断相关性），把真正回答问题的块往前放，把方向接近但答非所问的往后放。重排的代价是多一次计算，所以只对 TopK 里取出来的小批（比如前 20）重排，不对全库重排。

2. 重排的分数怎么合：向量分 + 关键词分 + 新鲜度，封顶 1.0

一个可用的合分公式是：向量相似度打底，关键词精确命中加分，文档越新加分越少越旧扣分，总分封顶 1.0。公式本身不重要，重要的是：分数要可解释——排错了，你要能说出是哪一项把错的块顶上来的，否则调参就是碰运气。

3. 引用怎么写：每句关键结论后面标出处

引用不是文末贴一串链接，而是：每句关键结论后面标 [资料N]，资料编号和拼进提示词时的编号一致。数字、日期、名字、条款，这四类最容易编造，也最必须标引用。引用标错了比不标更糟：标错了，人按引用去查，查到的根本不是那句话，信任就没了。

4. 防幻觉的三道关

关卡怎么做
提示词关写死：只用资料里的内容回答，资料里没有就说“资料里没有”，不要编
检索关相似度下限过滤，低于下限的块不要；检索为空时，直接走“资料里没有”分支，不生成
校验关生成后检查：回答里的数字、日期、名字，是不是都出现在引用块里？没出现的，标出来、打回去重生成

三道关缺一不可：只靠提示词，模型照样会编；只靠检索过滤，模型拿到资料还是会添油加醋；只靠事后校验，校验本身又要花一次调用。防幻觉是系统，不是某一句提示词。

容易踩的坑：检索为空时还让模型生成。检索为空，说明资料里根本没有答案，这时正确输出是“资料里没有”，不是让模型凭训练知识编一个。空检索还生成，是 RAG 里最常见的幻觉来源。

二、代码示例

示例 1：合分重排（本地实测逻辑，小数字算给你看）

def rerank_score(vector_score, keyword_hit, freshness_bonus=0.0):
    # 向量分打底，关键词精确命中加 0.2，新鲜度加分，总分封顶 1.0
    return min(1.0, vector_score + (0.2 if keyword_hit else 0.0) + freshness_bonus)

# 本地实测：向量分 0.8 + 关键词命中 0.2 = 1.0（封顶）
# 向量分 0.8 + 无关键词命中 = 0.8
# 排错了能说出是哪一项顶上来的，分数才可解释

示例 2：防幻觉的提示词模板（照着抄，不要只写“请准确回答”）

# 拼提示词时，指令写死这四条：
# 1. 只用下面资料里的内容回答，资料里没有就说“资料里没有”
# 2. 每句关键结论后面标 [资料N]，编号和资料编号一致
# 3. 数字、日期、名字、条款，必须出现在引用块里才能写
# 4. 不要把资料里没有的数字、日期、名字编出来
# 检索为空时：不调用模型，直接返回“资料里没有”

示例 3：引用一致性校验（字面层检查函数，本地实测过）

import re

def normalize(s):
    return re.sub(r"\s+", "", s)  # 去空格、全角半角归一化后再比对

def check_citation(answer, chunks):
    # chunks: {"1": "资料1原文", "2": "资料2原文"}
    failures = []
    for m in re.finditer(r"([^。；\n]+)\[资料(\d+)\]", answer):
        claim, n = m.group(1).strip(), m.group(2)
        chunk = chunks.get(n, "")
        # 字面层：结论里的数字/日期，必须出现在它标的那块里
        facts = re.findall(r"\d+(?:天|个工作日|%)", normalize(claim))
        for f in facts:
            if f not in normalize(chunk):
                failures.append((claim, n, f))
    return failures

# 资料1 = "自签收之日起 7 天内可申请退货"；资料2 = "仓库签收后 3 个工作日内退款"
# "退货期限是 7 天[资料1]" → 通过（[]）
# "退货期限是 30 天[资料1]" → 失败：30 天不在资料1里，是编的
# "退款 3 个工作日内到账[资料1]" → 失败：事实本身是对的，但它在资料2里，
#   标成 [资料1] 就是引用指向错了，照样不通过
# 字面层只能查数字/日期这类硬事实；结论句的语义对不对（比如“任何情况都能退货”
# 和“仅质量问题可换货”矛不矛盾），要升级成 NLI 判断：引用块能不能推出这句话

四、可能的面试题与答案

Q1：重排和向量检索，差在哪？

向量检索按语义方向排，方向接近不等于对这个问题有用；重排是第二遍排序，用更强的打分把真正回答问题的块往前放。重排只对 TopK 取出来的小批做，不对全库做。

Q2：防幻觉，你会怎么做？

三道关一起上：提示词写死只用资料回答、资料里没有就说没有；检索设下限、为空直接走“资料里没有”分支；生成后校验数字、日期、名字是不是都出现在引用块里，没出现的打回去重生成。

Q3：引用标错了，为什么比不标更糟？

标错了，人按引用去查，查到的根本不是那句话，信任就没了。不标，人至少知道答案没出处；标错，人以为有出处、查完发现是假的，信任损失更大。

Q4：合分公式怎么调？

先保证分数可解释：排错了能说出是哪一项顶上来的。向量分打底、关键词加分、新鲜度加分，总分封顶 1.0；调的时候跑评测集，看命中率和引用准确率一起变，不要只看一个。

Q5：检索为空还生成，会怎样？

模型会凭训练知识编一个，看起来有模有样，实际上资料里根本没有。这是 RAG 里最常见的幻觉来源，正确做法是不调用模型，直接返回“资料里没有”。

六、补充：Cross-Encoder 重排 + 引用一致性校验（结合岗位要求）

Cross-Encoder 和双编码器的区别，一句话：双编码器是问题和文档各编一次向量、再算余弦相似度，快但看不到问题和文档之间的细交互；Cross-Encoder 是把“问题 + 文档”拼在一起送进同一个模型、直接打一个相关性分，慢但准。所以分工是：双编码器（向量）负责从几十万块里捞出 Top 50，Cross-Encoder 只对这 50 个打分、重排成 Top 5，速度和精度都保住。不要反过来——Cross-Encoder 全量跑，成本和延迟都扛不住。

引用一致性校验是重排之后的最后一道关，专门防“引用对了出处、内容却是编的”：回答里的每个关键结论都要能在它标的那个引用块里找到依据。分三层查：字面层——数字、日期、人名、条款号必须原样（归一化后）出现在那块里；语义层——结论句必须能被那块推出，不能矛盾、不能偷换范围；指向层——[资料 N] 必须指向真正支持它的那块，不能张冠李戴。拿《退货政策》举例：资料 1 是“7 天内可申请退货”，资料 2 是“仓库签收后 3 个工作日内退款”——“退货期限是 7 天[资料 1]”通过；“退货期限是 30 天[资料 1]”不通过，30 天是编的；“退款 3 个工作日内到账[资料 1]”也不通过，事实本身是对的，但它在资料 2 里，标成资料 1 就是引用指向错了。找不到依据就两种处理：要么改写成块里确实有的说法，要么把这句删掉并说“资料里没有”。引用不是装饰，校验不通过的引用等于没有引用。

七、打回去重生成一直不通过，怎么办

先定一条铁律：重生成不是无限循环的，重试要设上限，通常 2–3 次。同一句话打回去三次还是不在引用块里，问题大概率不在生成那一步，再生成十次也一样——这时要换处理方式，而不是换运气。

处理分四档，从轻到重：第一档，带上具体原因再生成一次，不要盲目重跑——把校验的失败点喂回去，比如“第 2 句的 30 天不在资料 1 里，资料 1 只写了 7 天，请只用资料里的话重写”，有针对性的反馈比“再生成一次”有效得多；同时把 temperature 调低，让模型少发挥。第二档，删掉那句，只回答有依据的部分，删掉的结论不要留空位、不要找别的话来填。第三档，改写成块里确实有的说法，比如把“30 天”改回“7 天”，但改写必须以块里的原话为准，不能为了过校验而编一个“看起来在块里”的数字。第四档，承认资料里没有：如果那个事实在所有检索回来的块里都不存在，正确答案就是“资料里没有”，这不是失败，是诚实——这时要先排查是不是检索的问题（换个问法再检索一次、把 TopK 放大），如果全库里确实没有，就直接回答“资料里没有”，不要再生成了。

判断走哪一档，看失败的原因：事实在别的块里（比如在资料 2 不在资料 1）→ 是引用指向错了，改指向、或重新检索；事实在训练知识里、不在任何资料里（比如模型凭记忆写了 30 天）→ 是模型在编，删掉或承认没有；每次生成的数字都不一样 → 是模型在猜，降 temperature、改成“先引用原文、再组织回答”的两步生成。最后一点：每次打回都要记日志，进 Day 19 的评测集——同一类失败反复出现，说明要修的是检索或提示词，不是多加一次重试。
