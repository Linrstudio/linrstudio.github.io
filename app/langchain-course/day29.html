Day 29：面试模拟 1：项目深挖讲稿

简历上的项目，面试官一定会深挖：“讲讲你这个项目。”很多人一开口就背流水账：用了什么技术、写了多少代码，三分钟还没讲到重点。这一课给四个项目各准备一段 5 分钟讲稿：三个课程项目，加一个真实项目——广告投放用户之声 Agent（腾讯广告真实落地项目，从 0 到 1 主导搭建）。真实项目和课程项目讲法一样，都是五段结构；区别是真实项目的 Bug 和重做点，要写你真踩过的坑、真复盘过的设计，别编。结构固定：背景 → 架构 → 最难的 Bug → 怎么评测 → 如果重做会改什么。先说清楚：讲稿不是背诵稿，是按这个结构现场组织语言的骨架；结构熟了，现场怎么问都不慌。

一、核心解释

1. 五段结构：背景 → 架构 → 最难的 Bug → 评测 → 重做

五段各约 1 分钟，合起来 5 分钟。第一段背景：一句话讲清项目解决什么问题、给谁用，别讲技术。第二段架构：画出数据怎么流——用户输入进来，经过哪几个节点、调了哪些工具、答案怎么出来，只讲主干，别报菜名。第三段最难的 Bug：这是面试官最想听的一段，讲一个你真卡住过的坑、你怎么定位、最后怎么修的。第四段评测：你怎么证明它好用——跑了多少条测试、准确率多少、有没有人工抽查。第五段重做会改什么：讲你现在回头看，哪个设计最想推翻，这一段最显水平，因为它证明你不是“做完就忘”，而是真复盘过。

2. 四个项目的讲稿骨架：每个项目一句话定位

项目一句话定位架构主干评测抓手
Mini Cursor（第 2 周）命令行里的迷你编程助手：说一句话，它改代码用户指令 → 意图解析 → 白名单工具执行 → 结果回显固定指令集回归：每条指令跑通、越权指令被拦住
RAG + 深圳天气 Agent（第 3 周）会查资料、会查天气的问答 Agent：答案有出处问题 → 检索知识库 → 调天气工具 → 带引用生成答案引用准确率：答案里的引用是不是真出自原文
Computer Use-lite（第 4 周）能看屏幕、能点按钮的电脑操作 Agent截图 → 定位元素 → 执行点击 / 输入 → 校验结果任务成功率：10 个常用操作里几个一次做对
广告投放用户之声 Agent（真实项目）广告投放平台的用户调研分析 Agent：调研数据进、用户需求出调研数据 → 清洗 / 脱敏 / 打标 → 定量 / 定性 / 交叉 / 画像 → 对话追问 → 需求进 TAPD需求闭环可追踪：洞察出的需求能在 TAPD 里找到出处和落地状态，再加人工抽查

讲的时候先报定位，再走五段结构。四个项目别讲成四个流水账，要讲出区别：Mini Cursor 讲的是“安全边界怎么守”，RAG 讲的是“答案怎么可信”，Computer Use 讲的是“不确定的界面怎么操作”，用户之声讲的是“反馈怎么变成需求”——数据治理、权限隔离、需求进 TAPD 的闭环。面试官听完四个，应该记住四个不同的关键词，而不是四个相似的故事。

3. 最难的 Bug 怎么讲：现象 → 定位 → 根因 → 修复 → 防再犯

讲 Bug 不要只讲“修好了”，要讲你是怎么找到根因的。每个项目准备一个例子：Mini Cursor：命令白名单绕过。现象是用户一句话绕过了白名单、让 Agent 执行了不该执行的命令。定位时发现白名单只校验了命令的开头，没校验拼接后的完整命令。根因是“校验点放错了位置”——应该在执行前校验最终要跑的完整命令，而不是用户输入的前几个字。修复是执行前对完整命令做二次校验，防再犯是加一条回归测试：专门写越权指令，看它能不能被拦住。RAG：检索命中但引用错位。现象是答案看着对，引用却指向了另一段原文。定位发现检索返回的片段是对的，但生成时引用的编号和片段对不上。根因是引用编号在拼接上下文时错位了。修复是引用和片段绑定在一起传，不再靠序号对齐；防再犯是评测里加一项“引用准确率”，每次跑测试都查。Computer Use：按钮位置变化定位失败。现象是昨天能点的按钮，今天点不到了。定位发现按钮坐标变了，但截图里的按钮明明还在。根因是定位只靠固定坐标，没做视觉匹配。修复是先视觉定位再点，坐标只做兜底；防再犯是操作后加校验——点完截图确认页面真的变了，没变就重试一次。讲 Bug 的公式就是：现象一句话、定位讲方法、根因讲本质、修复讲动作、防再犯讲机制。广告投放用户之声：权限隔离只做了 UI 层，检索层没过滤。现象是负责创意的产品同学在对话追问里，看到了别家产品的反馈内容。定位时发现权限只在界面层做了隔离，检索是按相似度召回、没带产品过滤，Agent 回答一聚合就把别家数据带出来了。根因是“权限放错了层”——权限是机制，不是提示词，靠提示词里写“别说别的产品”拦不住。修复是每条记录和知识片段都带 product_id，检索时把当前用户可看的产品列表当成硬性过滤条件，再加最小样本数：少于 5 条只给趋势、不给明细。防再犯是加一条权限验收回归：拿没权限的账号去问，问什么都只能看到自己产品的数据。

4. 追问应对：把话题引回自己准备好的点上

面试官一定会追问，追问不是坏事，是送分题。应对就三招。第一招，承认不知道：真不会的就说“这个我没做过，我的思路是……”，别编，编的一追就穿。第二招，桥接：不管对方问什么，答完一两句就搭桥回自己的准备点，比如“这个问题和我当时处理白名单绕过很像，当时的做法是……”。第三招，反问确认：“您是指执行层面的校验，还是提示词层面的约束？”——反问既争取了思考时间，也让回答更对路。还有一条底线：讲稿不是背诵，背诵一卡壳就全崩；结构熟了，现场忘词也能顺着五段往下走。面试前把四个讲稿各讲两遍，录下来自己听一遍，超时就砍细节，卡壳就补过渡句。

容易踩的坑：讲稿写成技术清单。“用了 LangGraph、用了向量库、用了三个工具”——面试官听完只记得名词。每一项技术后面都要跟一句“为什么用它、不用它会怎样”，技术才有说服力。

二、代码示例

示例 1：讲稿结构自查小工具（能跑的纯 Python，检查五段齐不齐）

# 检查讲稿有没有走完五段结构，并按语速估算时长
# 语速按每分钟约 200 字估算（示例），按自己的语速替换
WORDS_PER_MINUTE = 200

def check_talk(title, sections):
    """sections 是五段文字的列表，顺序：背景、架构、Bug、评测、重做"""
    names = ["背景", "架构", "最难的 Bug", "评测", "重做会改什么"]
    total = 0
    for name, text in zip(names, sections):
        words = len(text)
        total += words
        print(f"{name}：{words} 字，约 {words / WORDS_PER_MINUTE:.1f} 分钟")
    print(f"{title} 合计 {total} 字，约 {total / WORDS_PER_MINUTE:.1f} 分钟")
    if len(sections) < 5:
        print("缺段！五段要齐，缺哪段补哪段")
    if total / WORDS_PER_MINUTE > 6:
        print("超时了！砍细节，5 分钟讲稿别超过 1000 字")

check_talk("Mini Cursor", [
    "命令行里的迷你编程助手：说一句话，它改代码。",
    "用户指令先进意图解析，再走白名单工具执行，最后回显结果。",

    "固定指令集回归测试：每条指令跑通，越权指令被拦住。",

示例 3：追问桥接句模板（概念代码）

# 追问应对：先答一两句，再搭桥回自己准备好的点
# 模板不是背诵，是现场组织语言的骨架
BRIDGES = {
    "安全": "这个问题和我处理 Mini Cursor 白名单绕过很像，当时的做法是……",
    "可信度": "这让我想到 RAG 的引用错位问题，我的解法是把引用和片段绑定……",
    "稳定性": "Computer Use 定位失败那次也是这样，定位只靠坐标不行，后来改成……",
    "权限": "这让我想到用户之声的权限隔离：负责创意的产品看不到其他产品的反馈，数据是按产品隔离的……",
}

def bridge(topic, answer):
    """先给简短回答，再用桥接句引回准备好的点"""
    print(answer)
    print(BRIDGES.get(topic, "这个问题我没直接做过，我的思路是……"))

四、可能的面试题与答案

Q1：讲讲你做的 Mini Cursor 项目。

面试官想听的点：定位 + 架构 + 一个真 Bug。答：命令行迷你编程助手，说一句话它改代码；架构是意图解析 → 白名单工具执行 → 结果回显；最难的是白名单绕过，校验只看了命令开头、没看拼接后的完整命令，修复是执行前对完整命令二次校验，并加了越权指令回归测试。

Q2：你的 RAG Agent 怎么保证答案可信？

面试官想听的点：引用机制 + 评测指标。答：答案必须带引用，引用和原文片段绑定传，不靠序号对齐；评测看引用准确率——答案里的引用是不是真出自原文；还遇到过检索命中但引用错位的问题，根因就是编号和片段对不上，修完后评测里一直查这一项。

Q3：Computer Use 定位失败，你是怎么解决的？

面试官想听的点：根因分析 + 兜底设计。答：按钮位置一变就点不到，根因是定位只靠固定坐标；改成先视觉定位再点，坐标只做兜底；操作后加校验，点完截图确认页面真的变了，没变就重试一次。

Q4：如果重做这四个项目，你会改什么？

面试官想听的点：复盘深度，不是客套话。答：Mini Cursor 会把校验移到执行前；RAG 会把引用和片段绑定传；Computer Use 会先视觉定位、操作后截图校验；用户之声会在一开始就给知识库加版本号和更新触发器，需求归纳强制绑定原文引用。每个“改什么”背后都是一个真踩过的坑，改动要具体到机制，不要说“会做得更好”这种空话。

Q5：你怎么评测自己的 Agent？

面试官想听的点：指标 + 方法 + 数字。答：分项目定指标：Mini Cursor 用固定指令集回归，越权指令必须被拦住；RAG 用引用准确率；Computer Use 用任务成功率，10 个常用操作里几个一次做对；用户之声看需求闭环——洞察出的需求能不能在 TAPD 里找到出处和落地状态。指标之外还要人工抽查，自动评测看不出来的问题，抽查能补上。

五、加分项

生产视角：面试讲稿和生产复盘是同一套结构：背景是需求，架构是设计，Bug 是故障复盘，评测是验收标准，重做是迭代计划。工作中写复盘、写事故报告，照这个结构写，别人一眼就能看懂你做了什么、学到了什么。

简历讲法：简历上的项目描述，就是讲稿的压缩版：每行写“做了什么 + 怎么评测 + 数字”。比如 Mini Cursor 写“白名单执行 + 越权指令回归测试”，RAG 写“引用准确率评测”，Computer Use 写“10 个常用操作任务成功率”，用户之声写真“4 年调研数据 + 清洗脱敏打标 + 需求进 TAPD”。面试官顺着简历上的词追问，问到的每一点你都有准备好的讲稿。
