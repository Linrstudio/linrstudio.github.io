Day 7：LangGraph 入门 + LangSmith 追踪 + 第 1 周复盘

第 1 周的最后一课，不讲新 API，讲怎么把前 6 天串起来：手写循环画成图，图加上持久化，再用追踪把所有问题定位到某一步。学完这一课，第 1 周就算闭环了。

一、核心解释

1. LangGraph 到底是什么：一张图，就是一个状态机

LangGraph 把 Agent 的执行过程画成一张图：State 是图里流转的状态（对咱们来说就是消息列表），Node 是图里的一个步骤（比如调模型、执行工具），Edge 是步骤之间的走向，条件边是“按条件决定下一步去哪”。

咱们脚手架的图只有两个节点，结构是：

call_model --(有 tool_call)--> tools --(回填结果)--> call_model
call_model --(无 tool_call)--> END

对照 Day 5 的手写循环看：节点就是循环里的一步，条件边就是循环里的 if，状态就是循环里一直追加的 history。图没有换掉循环，只是把循环画成了可以可视化、可以断点、可以分支的形式。

2. 什么时候用图，什么时候用循环

场景选什么为什么
简单工具循环，几步就完手写循环简单直接，调试成本低
流程有分支、要并行、要人工介入LangGraph分支和介入在图里是原生概念，循环里要自己写状态机
要断点续跑、要持久化、要回放LangGraph + Checkpoint检查点就是图的断点，循环里断了只能重跑

面试时这句很关键：简单循环够用就别上图，流程一复杂、要人工介入、可观测性要求高时，图就值了。把图吹成万能，和把循环说成过时，都是减分说法。

3. Checkpoint：图的断点和持久化

Checkpoint 就是把图执行到某一步的状态存下来，下次可以从断点继续，而不是重跑全程。按会话隔离靠 thread_id：同一个 thread_id 就是同一个会话，不同 thread 就是不同会话，串会话是生产事故。本地演示用 MemorySaver（存在内存里），生产用数据库版的检查点，原理一样，只是存储位置不同。

人工介入（Human-in-the-loop）也是在这个框架里实现的：在工具节点前再插一个确认节点，危险操作先停下来等人确认，确认后才继续。这就是第 4 周 Computer Use 安全底线的图版本，今天先记住位置，动手放在第 4 周。

4. LangSmith 追踪：出了问题，先看轨迹再改代码

LangSmith 不用改业务代码：设好环境变量 LANGSMITH_TRACING=true、LANGSMITH_API_KEY、LANGSMITH_PROJECT，每次调用的轨迹就会被记下来：哪一步的提示词被拼错了、模型回了什么、工具参数长什么样、烧了多少 Token、每步花了多久。

排障的正确顺序永远是：先看轨迹，定位到某一步，再改那一步。小白最常见的调试方式是反复改提示词碰运气，正确方式是先看轨迹，再改出问题那一步。没有追踪的 Agent，出了问题只能靠用户截图猜。

5. 第 1 周复盘：一张表收束

天核心面试时能讲的一句话

二、代码示例

示例 1：脚手架的图版循环（和 Day 5 的手写版对照看）

from langgraph.graph import StateGraph, END
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode, tools_condition
from typing import TypedDict, Annotated

class AgentState(TypedDict):
    # add_messages 的意思是：节点返回的新消息追加到旧消息列表，而不是覆盖
    messages: Annotated[list, add_messages]

def call_model(state):
    return {"messages": [llm.bind_tools(tools).invoke(state["messages"])]}

graph = StateGraph(AgentState)
graph.add_node("call_model", call_model)
graph.add_node("tools", ToolNode(tools))
graph.set_entry_point("call_model")
graph.add_conditional_edges("call_model", tools_condition)
graph.add_edge("tools", "call_model")
app = graph.compile()

对照 Day 5 的循环：call_model 就是循环里调模型那一步，tools 就是执行工具那一步，tools_condition 就是“有没有 tool_call”的那个 if，tools → call_model 这条边就是“结果回填后再调模型”。

示例 2：加上 Checkpoint，断点续跑（本地实测）

from langgraph.checkpoint.memory import MemorySaver

app = graph.compile(checkpointer=MemorySaver())
state = app.invoke(
    {"messages": [HumanMessage(content="算 37*41")]},
    config={"configurable": {"thread_id": "t1"}},
)
# 本地实测（Fake 模型）：最终回答是“图版结果是 1517”，
# 按 thread_id 查状态，消息列表里有 4 条（问题、工具调用、工具结果、最终回答）
# 换一个 thread_id，就是另一个会话，状态互不干扰

注意：MemorySaver 只存在内存里，进程一重启就没了，生产要换数据库版检查点。演示时用它够了，原理和生产版一样：状态按 thread_id 存，断了从断点续。

示例 3：LangSmith 追踪，不用改业务代码（环境变量版）

# 在 .env 里设好，业务代码不用改：
# LANGSMITH_TRACING=true
# LANGSMITH_API_KEY=你的 Key（别写进代码、别提交到 Git）
# LANGSMITH_PROJECT=langchain-course-week1
# 之后每次调用，LangSmith 里就能看到完整轨迹：

四、可能的面试题与答案

Q1：LangChain 和 LangGraph 本质区别是什么？

LangChain 是通用编排，LangGraph 是基于图的编排：状态、节点、条件边、检查点都是原生概念。简单循环用 LangChain 就够，流程复杂、要分支、要人工介入、要断点续跑时，LangGraph 才值。说清楚取舍，比把任何一方吹成万能都可信。

Q2：图执行到一半断了，怎么续跑？

靠 Checkpoint：状态按 thread_id 存下来，下次用同一个 thread_id 从断点继续，而不是重跑全程。本地演示用 MemorySaver，生产换数据库版检查点，原理一样，只是存储位置不同。

Q3：Agent 失败了，你先看什么？

先看 LangSmith 轨迹：模型发了什么、调了哪个工具、工具参数对不对、工具回了什么、哪一步开始偏的。定位到某一步再改那一步，不要先换模型、不要反复改提示词碰运气。

Q4：第 1 周学完，你能做出什么？还缺什么？

能做出：最小链、提示词与 FewShot、结构化输出、手写工具循环、组合记忆、图版循环加检查点。还缺的是：真实项目里的工具设计、检索与评测、Computer Use 的安全边界，这些正是第 2 到第 4 周的内容。面试时能这样分层讲，比罗列 API 可信得多。

Q5：为什么不用 AgentExecutor，一开始就要手写循环？

因为面试和排障都要看清循环：模型出 tool_call、你执行、结果回填、再决策。黑盒跑通了也不知道哪一步出了问题，手写循环每一步都看得见，出了问题能定位到某一步，图版也只是把同一循环画出来而已。

五、加分项

生产视角：图上线后，检查点、追踪、评测集是三件套：检查点管断点续跑，追踪管排障定位，评测集管改动回归。缺任何一件，上线后的 Agent 都是“跑起来了，但出问题不知道、改动不知道变好变坏”。

简历讲法：别写“熟悉 LangGraph”，写“把手写工具循环画成 LangGraph 图，节点是调模型和执行工具，条件边决定是否继续，检查点按 thread_id 做断点续跑，LangSmith 追踪定位到某一步”。前者是名词，后者是可追问的架构。
