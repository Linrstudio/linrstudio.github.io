Day 24：pyautogui 桌面操作与沙箱规则 | LangChain 30 天实战课

第 4 周进入 Computer Use：让 Agent 不只调用 API，还能直接操作桌面——移动鼠标、点按钮、敲键盘。pyautogui 就是干这活的 Python 库：它不关心应用内部长什么样，只模拟人的手。能力越大，风险越大：会点鼠标的 Agent 也会点错、删错，所以这课一半讲操作，一半讲沙箱规则——先学会刹车，再踩油门。

一、核心解释

1. pyautogui 是什么：模拟人的手，不读应用的内部

pyautogui 不调接口、不读 DOM，它只做三件事：移动鼠标、点击、敲键盘。对 Agent 来说，它是“最后的通用工具”：没有 API 的老应用、必须点几下的桌面软件，只有它能碰。但代价也在这里——它不知道自己点的是什么，只知道坐标。点对了是自动化，点错了就是事故。所以桌面操作的第一课不是“怎么点”，而是“点之前怎么确认、点错了怎么停”。

2. 键鼠三件套 + FAILSAFE：先会停，再会动

最常用的就四个 API：moveTo(x, y) 把鼠标移到坐标，click(x, y) 点一下，typewrite("文字") 打字，hotkey("ctrl", "c") 按组合键。每个操作前最好先 pyautogui.position() 确认鼠标在哪、pyautogui.size() 确认屏幕多大——坐标超出屏幕，操作就毫无意义。

最重要的一行是 pyautogui.FAILSAFE = True（默认就是 True，别关掉它）。它的意思是：鼠标一旦被甩到屏幕左上角（0, 0），立刻抛异常、整个脚本停下。这是给人留的急停按钮：Agent 失控乱点时，你把鼠标一甩，程序就停了。还有 pyautogui.PAUSE = 0.5，让每步操作之间停半秒——操作太快，人来不及反应，截图也来不及看清。

3. 窗口与图像定位：先找对窗口，再找对按钮

桌面上有十几个窗口时，直接按坐标点，点的可能是别的窗口。正确顺序是两步：先找窗口、激活窗口，再在窗口里找按钮。找窗口用 pygetwindow 这个库：getWindowsWithTitle("记事本") 按标题找窗口，拿到后调 .activate() 把它提到最前面、获得焦点；之后再操作，点的才是它。

窗口里找按钮靠 locateOnScreen("按钮.png")：拿一张按钮的小截图当模板，在屏幕上找长得一样的地方，找到就返回坐标，找不到返回 None。找不到时千万别硬点——None 就是“没找到”，必须当失败处理。但它有三个硬伤，要记牢：分辨率变了（换台显示器、换了缩放比例），模板就对不上；系统缩放变了（125% 改成 100%），按钮大小变了，也对不上；主题变了（浅色切深色、换了图标样式），颜色一变就认不出来。所以图像定位只能当“最后一招”，不能当唯一依赖——Day 25 会讲它的兜底策略。

4. 沙箱规则：四条红线，写进 README 供面试引用

桌面 Agent 的沙箱规则就四条，背下来，面试能直接引用：

规则内容防什么
白名单应用Agent 只能操作白名单里的应用，不在名单里的应用，碰都不碰误操作别的软件、越权访问
删 / 发 / 支付类操作必须人工确认删除文件、发送消息、支付扣款这类不可逆操作，执行前停下来等人确认一次误判造成不可逆损失
单任务步数上限 20 步一个任务最多走 20 步，超了就停、报失败，不许一直试下去死循环、无限重试拖垮系统
每步截图留痕每执行一步都截图保存，操作前、操作后各一张出事后无法复盘、说不清哪步错了

这四条是层层叠加的：白名单拦“不该碰的”，人工确认拦“不该做的”，步数上限拦“没完没了的”，截图留痕让“出了事能查”。少任何一层，防线就有口子。

容易踩的坑：只在演示时开沙箱，上线时嫌麻烦关掉。演示环境没有真实文件，删错了也没事；生产环境删的就是真数据。沙箱规则要写进代码里当默认值，而不是写在文档里当建议——能关掉的规则，等于没有规则。

二、代码示例

示例 1：键鼠基本操作（概念代码，先看形状）

import pyautogui

pyautogui.FAILSAFE = True   # 急停开关：鼠标甩到左上角就停，默认 True，别关
pyautogui.PAUSE = 0.5       # 每步之间停 0.5 秒，给人反应时间，也给截图留时间

# 先确认屏幕多大、鼠标在哪，再动手
width, height = pyautogui.size()
print("屏幕：", width, height)
print("鼠标现在：", pyautogui.position())

# 三件套：移到、点、打字；组合键用 hotkey
pyautogui.moveTo(500, 300, duration=0.5)   # 慢速移过去，别瞬移
pyautogui.click(500, 300)                  # 点一下
pyautogui.typewrite("hello", interval=0.05)  # 打字，每个字母间隔 0.05 秒
pyautogui.hotkey("ctrl", "s")              # 保存：Ctrl+S

示例 2：找窗口、激活窗口、图像定位（概念代码，先看形状）

import pyautogui
import pygetwindow as gw

# 第一步：按标题找窗口，激活它，再操作
wins = gw.getWindowsWithTitle("记事本")
if not wins:
    raise SystemExit("没找到记事本窗口，先打开它")
win = wins[0]
win.activate()                 # 提到最前、获得焦点
pyautogui.sleep(1)             # 等窗口切过来，别抢跑

# 第二步：图像定位找按钮，找不到就当失败，不硬点
pos = pyautogui.locateOnScreen("save_button.png", confidence=0.9)
if pos is None:
    pyautogui.screenshot("locate_failed.png")  # 失败先截图，再报错
    raise SystemExit("没找到保存按钮，截图已存 locate_failed.png")
pyautogui.click(pyautogui.center(pos))  # 点按钮中心，别点边角

示例 3：沙箱守门函数——四条规则落到代码里

# 四条沙箱规则：白名单、人工确认、步数上限、截图留痕
ALLOWED_APPS = {"记事本", "计算器"}   # 规则 1：白名单应用
DANGEROUS = {"删除文件", "发送消息", "支付扣款"}  # 规则 2：高危操作清单
MAX_STEPS = 20                        # 规则 3：单任务步数上限

def run_step(step_no, app, action, do_it, confirm, shot):
    # 规则 1：应用不在白名单，直接拒绝
    if app not in ALLOWED_APPS:
        return {"ok": False, "reason": f"应用 {app} 不在白名单"}
    # 规则 3：步数超上限，直接停
    if step_no > MAX_STEPS:
        return {"ok": False, "reason": f"步数超上限 {MAX_STEPS}，任务终止"}
    # 规则 2：高危操作必须人工确认，没确认不执行
    if action in DANGEROUS and not confirm(action):
        return {"ok": False, "reason": f"高危操作 {action} 未获人工确认"}
    # 规则 4：执行前后各截图一张，留痕
    shot(f"step{step_no}_before.png")
    result = do_it()
    shot(f"step{step_no}_after.png")
    return {"ok": True, "result": result}

四、可能的面试题与答案

Q1：pyautogui 是什么？适合什么场景？

模拟人键鼠操作的 Python 库，不调接口、不读内部，只移动鼠标、点击、打字。适合没有 API 的老应用和必须点几下的桌面软件，是“最后的通用工具”；代价是不知道自己点的是什么，点错风险高，所以必须配沙箱规则。

Q2：一个 Agent 误操作删了文件，你的系统哪一层能拦住？

四层都能拦，各拦一段：白名单先拦——删文件的应用不在白名单，碰都不让碰；人工确认再拦——删除属于高危操作，执行前必须停下来等人确认；步数上限兜底——即使前面都漏了，单任务最多 20 步，不会无限删下去；审计留痕收尾——每步截图保存，出事后能定位是哪一步、哪个操作删的。四层叠加，单点失效不等于全线失守。

Q3：FAILSAFE 是什么？为什么默认不能关？

鼠标甩到屏幕左上角（0, 0）就抛异常、整个脚本停下，是给人留的急停按钮。Agent 失控乱点时，这是人最快叫停它的办法；关掉它，等于拆掉刹车。

Q4：locateOnScreen 有哪些局限？

三个：分辨率变了模板对不上，系统缩放变了按钮大小变了对不上，主题变了颜色样式变了认不出来。所以它只能当最后一招，不能当唯一依赖，要配合多定位器降级和相对定位（Day 25 讲）。

Q5：桌面 Agent 的沙箱规则有哪四条？

白名单应用、删 / 发 / 支付类操作必须人工确认、单任务步数上限 20 步、每步截图留痕。这四条要写进代码当默认值，不是写在文档里当建议——能关掉的规则，等于没有规则。

五、加分项

生产视角：桌面 Agent 上线前，先问三个问题：白名单是不是代码里的默认值、关不掉？高危确认里写清了“要做什么、影响什么”吗？步数上限和截图留痕在演示环境和生产环境是一套吗？三问有一个答不上来，桌面操作就别上。

简历讲法：别写“用过 pyautogui”，写“pyautogui 键鼠 + 窗口激活 + 图像定位，白名单应用、高危人工确认、20 步上限、每步截图留痕四层沙箱”。前者是名词，后者是可追问的设计。
