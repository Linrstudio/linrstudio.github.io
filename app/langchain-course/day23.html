Day 23：Playwright 浏览器操作：定位、等待与截图留痕 | LangChain 30 天实战课

Day 22 说了先浏览器、后桌面，今天就讲浏览器这一步怎么做。工具用 Playwright：它能打开真实浏览器、点按钮、填表单、截图，Computer Use 在浏览器里的活，基本都由它来干。今天只讲四个基本功：定位、等待、填表、截图留痕。

一、核心解释

1. 定位：role / text / test-id 优先，坐标是最后手段

定位就是告诉 Playwright“要点的是哪个元素”。优先级记住一条线：role / text / test-id 优先，坐标是最后手段。role 是按元素的角色找，比如“提交按钮”“搜索框”，语义最清楚；text 是按页面上显示的文字找，比如“登录”这两个字；test-id 是开发给元素打的专属标记，最稳，但前提是页面真的打了这个标记。

坐标为什么排最后？因为坐标最脆：窗口一变大变小、页面一滚动、布局一改版，坐标就全错了。坐标只用在实在没有别的办法的时候，比如画布里的点、没有文字也没有角色的图标。能用 role、text、test-id 找到的，就别用坐标。

2. 等待：等条件，不等固定时间

浏览器操作最常见的错，不是点错了，而是点早了：页面还没加载完、按钮还没出现，代码就去点了，结果自然是失败。新手最爱写的办法是固定 sleep：睡 3 秒再点。别这么写。

固定 sleep 有两个毛病。第一，睡少了还是会失败：网一慢，3 秒根本不够。第二，睡多了纯浪费时间：页面 0.5 秒就好了，你还在睡，十步下来就多等几十秒。正确做法是等条件：等元素可见、等网络空闲。元素可见就是“这个按钮已经出现、能点了”；网络空闲就是“页面暂时没有新的网络请求了”。条件到了立刻往下走，条件不到就一直等到超时——又快又稳。

容易踩的坑：等网络空闲不等于页面永远空闲。有些页面会一直发请求（比如轮询、埋点），等网络空闲可能一直等不到。做法是：先等关键元素可见，再等网络空闲做辅助，两者取个平衡，超时时间也要设上限，别无限等下去。

3. 填表：fill 和 type 的区别，提交前先校验

填表有两个常用方法：fill 和 type，别混用。fill 是直接把值填进去：先清空输入框，再把整段文字一次写进去，又快又干净，适合大多数表单。type 是模拟一个字一个字敲键盘：慢一些，但会触发页面监听键盘的逻辑，比如输入时实时联想、边输边校验，这种场景就得用 type。

怎么选？默认用 fill；如果填完发现页面的联想、校验没触发，再换 type 试试。还有一步不能省：提交前先校验。点提交之前，先把每个字段读出来对一遍：必填的填了没有、格式对不对、数字是不是数字。提交之后再发现填错了，撤回的成本比校验大得多。

4. 截图留痕：每步一张，失败那张最值钱

截图留痕的意思是：每步截图，失败截图。每做完一步就截一张图，存下来；出问题时，把失败那一刻的截图也存下来。这么做的好处有三条。第一，复盘有据：Agent 说“点了提交”，截图能证明它到底点没点、点完页面变成什么样了。第二，定位问题快：失败截图一眼就能看出是页面没加载、元素没找到，还是填错了值。第三，方便给人看：把截图贴给用户，比说一百句“我觉得没问题”都有用。

截图要存好名字，别全叫 screenshot.png：按步骤编号、带上时间，比如 step-03-after-fill.png，失败的单独放一个文件夹。等你以后把 Agent 交给别人用，这些截图就是最直接的证据链。

二、代码示例

示例 1：打开页面、定位、点击、填表、截图（概念代码，先看形状）

# 真实 Playwright Python 同步 API：先看形状
# 本地没有浏览器环境时跑不起来，这里只看写法，不直接运行
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)  # 打开浏览器
    page = browser.new_page()
    page.goto("https://example.com/login")  # 打开登录页
    # 定位优先用 role / text：按角色和文字找，不用坐标
    page.get_by_role("textbox", name="用户名").fill("demo")
    page.get_by_role("textbox", name="密码").fill("demo123")
    page.get_by_role("button", name="登录").click()
    page.screenshot(path="step-01-after-login.png")  # 每步截图留痕
    browser.close()

示例 2：等条件、填表校验、失败截图（概念代码，先看形状）

# 等条件而不是固定 sleep；提交前校验；失败了也要截图
# 概念代码，先看形状：本地没有浏览器环境时不直接运行
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("https://example.com/form")
    # 等元素可见，再等网络空闲：条件到了立刻走，不用固定 sleep
    page.wait_for_selector("text=提交")
    page.wait_for_load_state("networkidle")
    # fill 直接填值；需要触发键盘联想时，再换成 type 一个字一个字敲
    page.get_by_test_id("email").fill("demo@example.com")
    # 提交前校验：读出来对一遍，错了就停下，别急着提交
    value = page.get_by_test_id("email").input_value()
    assert "@" in value, "邮箱格式不对，先别提交"
    try:
        page.get_by_role("button", name="提交").click()
    except Exception:
        page.screenshot(path="failed-submit.png")  # 失败截图最值钱
        raise
    page.screenshot(path="step-02-after-submit.png")
    browser.close()

示例 3：定位优先级怎么选（可运行，纯 Python）

# 定位优先级：role / text / test-id 优先，坐标是最后手段
# 纯 Python，本地可以直接跑，看输出就懂优先级

def pick_locator(role=None, text=None, test_id=None, x=None, y=None):
    """按优先级选定位方式：有 role 用 role，有 text 用 text，坐标只兜底。"""
    if role:
        return "role: %s" % role
    if text:
        return "text: %s" % text
    if test_id:
        return "test-id: %s" % test_id
    if x is not None and y is not None:
        return "坐标: (%s, %s)，最后手段" % (x, y)
    return "没有可用的定位方式，先停下"

if __name__ == "__main__":
    print(pick_locator(role="button", text="登录", x=100, y=200))
    print(pick_locator(text="提交"))
    print(pick_locator(test_id="email"))
    print(pick_locator(x=100, y=200))
    print(pick_locator())

示例 3 是纯 Python，本地可以直接跑，预期输出是：role 优先于 text 和坐标，text 优先于 test-id，只有坐标时明确标出“最后手段”，什么都没有时提示停下。示例 1 和示例 2 用的是真实 Playwright 同步 API，但本地没有浏览器环境，标为概念代码、先看形状；要跑通它们，需要先装好浏览器环境，费用方面不涉及真实模型调用。

四、可能的面试题与答案

Q1：Playwright 里定位元素，优先级怎么排？为什么？

role、text、test-id 优先，坐标最后。role 按角色找、text 按文字找、test-id 按专属标记找，都是按语义找，改版也不容易失效；坐标依赖布局，窗口大小、滚动、改版都会让它失效，只能做最后的兜底。

Q2：等待为什么不能用固定 sleep？

固定 sleep 睡少了还是会失败，网一慢就不够；睡多了纯浪费时间。正确做法是等条件：等元素可见、等网络空闲，条件到了立刻往下走，条件不到等到超时为止，又快又稳。

Q3：fill 和 type 怎么选？

默认用 fill：直接把整段值填进去，又快又干净。需要触发键盘监听时用 type：比如输入联想、边输边校验，要模拟逐字敲键盘才能触发。选错了的表现就是填上了值，但页面的联想和校验没反应。

Q4：填表提交前要做什么？

先校验再提交：把每个字段读出来对一遍，必填的填了没有、格式对不对、数字是不是数字。提交之后再发现填错，撤回成本比校验大得多。

Q5：截图留痕在生产里有什么用？

每步截图、失败截图，按步骤编号存好。复盘时有据可查，定位问题快，失败截图一眼就能看出是页面没加载、元素没找到还是填错了值；交给别人用时，截图就是最直接的证据链。

五、加分项

生产视角：Playwright 上线前先问三件事：定位是不是都用的 role / text / test-id，坐标是不是只剩兜底？等待是不是等条件，固定 sleep 是不是清干净了？失败截图是不是按步骤编号存好了，出问题能不能十分钟内定位？三问有一个答不上来，就别上生产。

简历讲法：别写“会用 Playwright”，写“role / text / test-id 优先定位、等元素可见与网络空闲代替固定 sleep、fill 与 type 按场景区分、提交前校验、每步截图留痕”。前者是名词，后者是可追问的做法。
