Day 1：LangChain 是什么？最小链跑起来

学完这一课，你要能做到三件事：说清 LangChain 是干嘛的、写出最小链、讲清它和单次调模型的区别。先记住结论，再看细节。

一、核心解释

1. 一句话：LangChain 不是大模型，是胶水

大模型负责思考和生成，LangChain 负责编排：提示词怎么拼、什么时候调模型、模型的结果往哪送、什么时候调工具、历史怎么带。它就像前端框架：不替你写业务逻辑，只帮你把组件、状态、接口组织起来。

2. 三个容易混的名字

  • LangChain：编排框架，就是这门课的主角。
  • LangGraph：基于图的编排方式，适合流程复杂、要分支、要人工介入的 Agent，第 7 天讲。
  • LangSmith：调试和观测平台，能看到每一步发了什么、回了什么、烧了多少 Token，排障时用。

3. 核心就 7 块，先记住分工

  • 模型 ChatModel：消息进、消息出，不是字符串进出。
  • 提示词 Prompt：带变量的模板，System 定规则，Human 给问题。
  • 输出解析器 OutputParser：把模型消息转成你要的形状：文本、JSON、Pydantic 对象。
  • LCEL 与 Runnable：prompt | llm | parser 里的 |，把有统一接口的零件串起来。
  • 工具 Tool：带名字和描述的函数，模型看了描述自己决定调不调。
  • 记忆 Memory：模型本身无记忆，每次调用都要把历史重新发过去，记忆就是你帮它保管的那份清单。
  • 检索器 Retriever：先查资料再回答，解决模型不知道、会编造的问题，第 3 周讲。

4. LCEL 的 | 到底是什么

它是把多个 Runnable 串成一条链，前一步输出就是后一步输入。| 只是先组装，invoke 时才真正从头执行。所有零件都有 invoke / batch / stream，所以可以互换、可以单测某一步、可以用 stream 做打字机效果。中间任何一步抛异常，整条链就向外抛，不会悄悄跳过；另一个常见坑是类型对不上，比如 prompt 输出 PromptValue，下一环却按纯字符串处理。

5. ChatModel 和老式 LLM 的区别

老式 LLM 是字符串进、字符串出。ChatModel 是消息进、消息出：SystemMessage / HumanMessage / AIMessage / ToolMessage，角色是分开的。Agent 必须用它，因为工具调用就藏在 AIMessage.tool_calls 里，工具结果要以 ToolMessage 的形式、带着对应的 tool_call_id 回填，字符串模型做不到这套往返。

小白最容易踩的坑：现在 LangChain 是分包的：langchain-core 是核心，langchain-openai 是 OpenAI 对接，langgraph 另装。老教程的导入路径很多已经变了，抄代码报错先查版本和导入路径，别先怀疑自己。

二、代码示例

示例 1：最小链（Day 1 的骨架，必须会默写）

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

prompt = ChatPromptTemplate.from_template("把 {topic} 讲给小白听，一句话")
chain = prompt | llm | StrOutputParser()

print(chain.invoke({"topic": "LangChain"}))

三步分别是：填变量拼成消息、发给模型、把模型消息里的文本抠出来。注意三点：模板里的 {topic} 和 invoke 传的键名必须对上；StrOutputParser 的 S、O、P 都大写，Python 名字大小写敏感；invoke 返回的就是解析后的字符串。

示例 2：Structured Output（让模型稳定输出结构）

from pydantic import BaseModel, Field

class TaskBreakdown(BaseModel):
    goal: str = Field(description="用户目标，一句话")
    steps: list[str] = Field(description="拆解步骤，3-5 条")
    risks: list[str] = Field(description="可能失败的点")

structured = llm.with_structured_output(TaskBreakdown)
result = structured.invoke("帮我把'给博客加一个深色模式开关'拆解成开发任务")
print(result.model_dump_json(indent=2, ensure_ascii=False))

以前是让模型输出 JSON，再用正则抠代码块、json.loads 解析，模型一加解释、多一个逗号就全崩。现在是把 Pydantic 结构当 schema 交给模型，返回校验过的对象。但它也不是万能：schema 太复杂、描述不清时仍会校验失败，处理顺序是：看错误 → 带错误让模型重试 → 反复失败再改 schema / prompt → 最后才换模型。

动手任务（10 分钟）

1. 把示例 1 的 topic 换成“鸽子”，跑一遍。
2. 把示例 2 的 TaskBreakdown 加一个 deadline 字段，再在 prompt 里明确让它给截止日期，看看模型会不会编一个日期——如果会，把字段改成可选，这就是防编造的第一课。
3. 故意把 invoke 的键写错一个字母，看报错信息，记住 KeyError 长什么样。

三、小测验（点选项判分，答完点解析）

得分：0 / 6

1. prompt | llm | parser 里，| 是干嘛的？

解析：选 B。它组装的是一条 RunnableSequence，invoke 时才从头执行，而且所有零件共享 invoke / batch / stream 接口。

2. 模板里有 {goal}，调用时没传 goal，会怎样？

解析：选 A。事前校验 input_variables 或用 partial 给默认值才是正解，try/except 只能当最后一道防线。

3. 为什么 Agent 必须用 ChatModel，而不是字符串进出的老 LLM？

解析：选 C。消息类型和往返结构才是关键，价格和长度都不是决定因素。

4. Structured Output 校验失败，第一反应应该是？

解析：选 B。很多失败只是一时手滑，重试就过了；反复同一种失败，才是 schema 或 prompt 本身有问题，那时再改 schema。

5. Agent 场景 temperature 一般放多少？为什么？

解析：选 A。注意：0 最稳，0.3 仍带一点随机性；而且 0 也不等于 100% 可复现，模型版本和硬件也可能带来细微差别。

6. 需求只是“输入一句话，调一次模型，返回翻译”，要不要上 LangChain？

解析：选 B。LangChain 的价值在编排，不在单次调用，能说出这个取舍，面试时比把它吹成万能框架可信得多。

四、可能的面试题与答案

Q1：LangChain 和 LangGraph 本质区别是什么？什么时候不用 LangGraph？

LangChain 是通用编排框架，LangGraph 是基于图的编排：状态放进 State，每一步是节点，条件边决定走向，天然支持断点续跑、人工介入、并行分支。简单循环够用就别上图，流程复杂、要人工确认、可观测性要求高时，图才值。

Q2：Agent 死循环一般是哪几种原因？你怎么防？

常见三种：工具选错反复调同一个工具、工具参数一直错、模型不认工具结果一直重试。防法三层：步数上限、工具异常转成 ToolMessage 让模型纠错而不是崩溃、运行日志留轨迹复盘。第 5 天的手写循环就是按这三层写的。

Q3：Tool Calling 失败（参数错、超时、返回空）分别怎么处理？

参数错：把校验错误回填给模型，让它纠正参数再调；超时：设超时 + 有限次重试，仍失败就降级或报给用户；返回空：当成一次失败结果回填，别当成成功继续往下编。共同原则是：工具失败是模型的输入，不是整个 Agent 的崩溃理由。

Q4：RAG 和微调怎么选？（Day 1 先建立直觉，第 3 周展开）

知识常变、需要引用出处、数据量少时选 RAG；知识稳定、要内化成模型风格或能力、且有足够高质量数据时再考虑微调。面试时先给这个判断框架，再谈细节。

Q5：你怎么证明 Agent 变好了，而不是感觉变好了？

先建离线评测集，固定一批任务和预期结果，每次改动都跑一遍，记成功率、步数、Token 消耗、工具调用次数；线上再抽查真实轨迹、按失败原因分类。只说“试了几个例子都挺好”是最弱的回答。

五、加分项

生产视角：核心循环确实就是“模型决策 → 调工具 → 结果回填 → 再决策”这几行，但上线要在外面包上入口校验、状态落库、工具白名单、大小模型路由、成本告警、LangSmith 观测、评测集和回滚。先把发动机搞懂，再一层层往外包，才是真实的上线路径。

简历讲法：别写“熟悉 LangChain”，写“手写过 Tool Calling 循环，含步数上限、工具异常回填、运行日志，LangGraph 版支持断点与人工确认节点”。前者是背诵，后者是证据。
