Day 20：工具路由 + 深圳天气工具（Open-Meteo，免 Key）

RAG 讲完了，今天讲另一条线：工具。问题来了，先判断走 RAG 还是走工具；天气问题走工具，工具去调真实的天气接口——用 Open-Meteo，免 Key，深圳坐标 22.54, 114.06。

一、核心解释

1. 路由是什么：问题来了，先分流，再干活

用户问题
  → 问天气、温度、下雨、风？ → 走天气工具（调 Open-Meteo）
  → 问文档、规则、教程里有的事？ → 走 RAG（检索 + 生成）
  → 两边都沾？ → Day 21 讲混合问答，先分再合
  → 两边都不沾？ → 直接回答“这个问题我答不了”，不要现编

路由可以先做规则版：问题里有“天气、温度、下雨、风”这些词，就走天气工具；没有，就走 RAG。规则版简单、可解释，起步就够了；规则版不够用了，再上模型版路由（让模型自己判断走哪条），不要一上来就上模型版——模型版路由错了，你连它为什么错都说不清。

2. 天气工具怎么做：一个函数，三个要点

  • 参数要收敛：城市名先映射到坐标，深圳就是 22.54, 114.06；不要让模型直接传经纬度，模型编坐标比编天气还快。
  • 接口要免 Key、要超时：Open-Meteo 不用 Key，适合教学和演示；调用要设超时，超时算一次工具失败、转成 ToolMessage 贴回，不要让 Agent 干等。
  • 结果要结构化：温度、湿度、风速、天气码，四项原样返回，不要让工具自己写成一句话——写成一句话，模型就没法再加工、没法再校验了。

3. 工具结果怎么进 Agent 循环：和第 1 周一样，ToolMessage 回填

天气工具和 calculator 工具没有本质区别：模型出 tool_call，工具调接口，结果包成 ToolMessage、按 tool_call_id 回填，再调模型生成最终回答。工具结果里要带出处：数据来自 Open-Meteo、时间是哪一刻，回答里才能写“据 Open-Meteo，深圳当前……”而不是“深圳当前……”——出处是工具结果的一部分，不是回答时现编的。

4. 天气码怎么翻译：不要让模型猜

Open-Meteo 返回的 weather_code 是数字，0 是晴、1 到 3 是多云、61 是雨，诸如此类。翻译表要写在工具代码里，工具返回时直接带中文翻译，不要把数字原样丢给模型、让模型猜——模型猜天气码，和编天气是一个性质。

容易踩的坑：让模型直接传经纬度、直接传城市名去调接口。城市名要先映射到坐标表，坐标表是代码里的白名单，不是模型现编的；不在表里的城市，先问用户、或者直接说“这个城市我还没接”，不要让模型编一个坐标出来。

二、代码示例

示例 1：规则版路由（本地实测）

def route(question: str) -> str:
    # 规则版：问题里有天气词，就走天气工具；没有，就走 RAG
    if any(w in question for w in ["天气", "温度", "下雨", "风"]):
        return "weather_tool"
    return "rag"

# 本地实测：
# route("深圳今天天气怎么样？") → "weather_tool"
# route("LangChain 记忆怎么做预算？") → "rag"
# 规则版简单、可解释，起步就够了；不够用了再上模型版路由

三、小测验（点选项判分，答完点解析）

得分：0 / 6

1. 路由是干嘛的？

解析：选 B。路由是分流，不是翻译；两边都不沾，直接说答不了，不要现编。

2. 路由起步应该用规则版还是模型版？

解析：选 C。模型版路由错了，你连它为什么错都说不清；规则版错了，一眼就能看出是哪条规则错了。

3. 城市名应该怎么处理？

解析：选 A。模型编坐标比编天气还快，坐标表是代码里的白名单，不是模型现编的。

4. 天气工具的结果应该怎么返回？

解析：选 B。写成一句话，模型就没法再加工、没法再校验了；结构化返回，模型才能再组织回答。

5. 天气码应该怎么翻译？

解析：选 C。模型猜天气码，和编天气是一个性质；翻译表写死在代码里。

6. 工具调用超时了，应该怎么办？

解析：选 A。和第 1 周的工具异常处理一样：工具失败转消息回填，让模型纠错或换路，不要崩、不要编。

四、可能的面试题与答案

Q1：路由怎么做？规则版和模型版怎么选？

先分流再干活：天气词走工具，文档问题走 RAG，两边都不沾就说答不了。起步用规则版，简单、可解释；规则版不够用了再上模型版，不要一上来就上模型版。

Q2：天气工具的参数怎么设计？

城市名先映射到坐标白名单，深圳 22.54, 114.06；不要让模型直接传经纬度。接口用 Open-Meteo，免 Key，设超时；结果结构化返回温度、湿度、风速、天气码翻译，带出处和时间。

Q3：工具结果怎么进 Agent 循环？

和第 1 周一样：模型出 tool_call，工具调接口，结果包成 ToolMessage、按 tool_call_id 回填，再调模型生成最终回答。工具结果里带出处和时间，回答里才能写“据 Open-Meteo……”而不是现编。

Q4：天气码为什么不能让模型猜？

天气码是数字编码，翻译表要写在工具代码里，工具返回时直接带中文翻译。把数字丢给模型猜，和编天气是一个性质。

Q5：不在白名单的城市，怎么办？

直接返回“这个城市我还没接”，或者问用户确认，不要让模型编一个坐标出来。白名单是代码里的，不是模型现编的。

五、加分项

生产视角：天气工具上线前，先问三个问题：城市白名单有没有？调用超时设了没有？结果结构化、带出处和时间了吗？三问有一个答不上来，工具就别上。

简历讲法：别写“做过天气工具”，写“规则版路由分流，城市名映射坐标白名单，Open-Meteo 免 Key 调用、超时转 ToolMessage，结构化返回温度、湿度、风速、天气码翻译”。前者是名词，后者是可追问的工具设计。
