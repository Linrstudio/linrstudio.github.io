Day 28：全项目加固 3：成本、限流与降级

前两课把项目做对了、做稳了，这一课算一笔账：你的 Agent 跑一次到底花多少钱？模型 API 不是免费水龙头，每次调用都按 Token 计费，还有每分钟能调几次的上限。今天的目标很实际：会算单次成本、会设预算上限、超了知道怎么降级——让你的 Agent 既跑得动，也烧不起钱。

一、核心解释

1. Token 成本核算：一次调用多少钱，写清楚算式

模型按 Token 收费，输入和输出的单价通常不一样，输出往往更贵。算式就一行：单次成本 ＝ 输入 Token × 输入单价 ＋ 输出 Token × 输出单价。举个例子（以下数字全部是示例，请按你自己的账单替换）：假设输入单价 0.01 元 / 千 Token，输出单价 0.03 元 / 千 Token，一次调用输入 2000 Token、输出 500 Token，成本就是 (2000 × 0.01 ＋ 500 × 0.03) ÷ 1000 ＝ 0.035 元。看着不多，但一天 1000 次就是 35 元，一个月就是 1000 多元。算成本要养成三个习惯：第一，分开算输入和输出，别只记总数；第二，按“一次调用”算，再乘调用次数，别直接拍脑袋估月账单；第三，Agent 每步都调模型，10 步就是 10 次调用的钱，步数也是成本。

2. 速率限制：RPM / TPM 超了会怎样

模型 API 除了收钱，还限制速度。两个指标要记住：RPM 是每分钟能发多少次请求（Requests Per Minute），TPM 是每分钟能用多少 Token（Tokens Per Minute）。超了会怎样？服务方直接返回 429 错误（Too Many Requests），这次调用失败，钱不花、事也没办成。如果你的代码一失败就立刻重试，等于拿头撞墙：重试本身也占额度，越撞越限。正确做法有三层：第一，请求之间留间隔，别一股脑并发几十个；第二，收到 429 后等一等再试，而且越试等越久（这叫退避，比如第一次等 1 秒、第二次等 2 秒、第三次等 4 秒）；第三，设重试上限，比如最多试 3 次，试完还不行就把失败写进结果、走降级，别无限重试把账单和时间都烧光。

3. 配额：每日预算上限，超预算停掉非核心调用

速率限制是“每分钟别太快”，配额是“每天别花太多”。上线前先给自己定一条线：每天最多花多少钱、最多调多少次。做法很直接：每次调用前先查“今天已经花了多少”，超了预算就停掉非核心调用——比如摘要、润色、闲聊式追问先停，核心问答继续跑；预算实在不够了，就回一句“今天额度用完了，请明天再试”，也比悄悄透支强。配额还要分优先级：核心功能有自己的额度，非核心功能共用一个小额度，互不抢。记住一个原则：预算是上线前就定好的数，不是月底看到账单才后悔的数。本地开发时也一样，给测试脚本设个小预算，跑循环测试前先算一算，别让一个死循环测试跑掉一周的预算。

4. 降级策略：小模型路由、缓存、摘要

降级不是“认输”，是“花小钱办同样的事”。三招按顺序用：第一招是小模型路由：任务先分个类，简单任务（分类、抽关键词、格式转换）走便宜的小模型，复杂任务（多步推理、长文生成）才走大模型——大部分日常请求其实都是简单任务。第二招是缓存：同样的问题、同样的问题加同样的上下文，直接回上次的答案，一分钱不花；缓存要设有效期，比如天气类答案 1 小时过期，政策类答案可以放久一点。第三招是摘要：上下文太长时，别把几万字原文全喂给模型，先摘要成几百字再喂，输入 Token 直接砍掉九成。三招可以叠加：先查缓存，没有缓存就看任务难度选模型，上下文太长就先摘要。降级要有开关和日志：哪次走了降级、省了多少钱，记下来，复盘时才知道降级有没有伤到质量。

容易踩的坑：只盯着单价，忘了步数和重试。Agent 一步调一次模型，10 步就是 10 倍成本；重试没有上限，一次 429 能连锁烧掉几十次调用。算账时把“步数 × 重试”也算进去，才是真实成本。

二、代码示例

示例 1：单次成本计算器（能跑的纯 Python，先算再上线）

# 数字全部是示例：请按你自己的账单替换单价
INPUT_PRICE = 0.01   # 示例：输入 0.01 元 / 千 Token
OUTPUT_PRICE = 0.03  # 示例：输出 0.03 元 / 千 Token

def call_cost(in_tokens, out_tokens):
    """单次成本 = 输入 Token x 输入单价 + 输出 Token x 输出单价"""
    return (in_tokens * INPUT_PRICE + out_tokens * OUTPUT_PRICE) / 1000

# 一次调用：输入 2000 Token，输出 500 Token
print(call_cost(2000, 500))   # 0.035 元（示例）
# 一天 1000 次同样调用
print(call_cost(2000, 500) * 1000)  # 35.0 元（示例）
# 对比：同样的量走便宜一半的模型，单价都减半
print(call_cost(2000, 500) * 0.5)   # 0.0175 元（示例）

示例 2：预算守门 + 429 退避（概念代码，先看形状）

import time

DAILY_BUDGET = 35.0   # 示例：每日预算 35 元，按自己账单改
spent_today = 0.0      # 今天已花，实际应存数据库、每天清零

def call_with_guard(call_fn, cost, core=True):
    """核心调用才允许超预算后继续，非核心调用超预算直接停"""
    global spent_today
    if spent_today + cost > DAILY_BUDGET and not core:
        return {"skipped": True, "reason": "今日预算已用完，非核心调用已停"}
    result = call_with_retry(call_fn)
    spent_today += cost
    return result

def call_with_retry(call_fn, max_retry=3):
    """收到 429 就退避重试：等 1 秒、2 秒、4 秒，超上限就认失败"""
    wait = 1
    for attempt in range(max_retry + 1):
        try:
            return call_fn()
        except RateLimitError:   # 429：超速率限制
            if attempt == max_retry:
                raise
            time.sleep(wait)
            wait *= 2

四、可能的面试题与答案

Q1：一次模型调用的成本怎么算？

面试官想听的点：公式 + 实例 + 习惯。答：单次成本 ＝ 输入 Token × 输入单价 ＋ 输出 Token × 输出单价，输入输出分开算；举例（示例数字）：输入 2000、输出 500，按示例单价算约 0.035 元；再乘以调用次数和步数才是真实成本，Agent 每步都调模型，步数也要算进去。

Q2：RPM / TPM 是什么？超了怎么办？

面试官想听的点：知道上限 + 有应对。答：RPM 是每分钟请求数上限，TPM 是每分钟 Token 数上限，超了返回 429；应对是请求间留间隔、429 后退避重试（1 秒、2 秒、4 秒递增）、重试上限 3 次，超了就走降级而不是无限重试。

Q3：你怎么给 Agent 设预算？

面试官想听的点：事前定数 + 分优先级 + 可落地。答：上线前定每日预算和调用上限，每次调用前查已花多少；分优先级，核心调用保住、非核心调用超预算就停；预算不够就明确告诉用户额度用完了，而不是悄悄透支。

Q4：降级策略有哪些？分别适合什么场景？

面试官想听的点：三招 + 适用条件。答：小模型路由适合简单任务（分类、抽关键词、格式转换）；缓存适合重复问题，设有效期；摘要适合上下文太长，先摘要再喂模型。三招可叠加，降级要记日志，复盘时看有没有伤质量。

Q5：怎么证明你做的 Agent 成本可控？

面试官想听的点：数字 + 措施 + 结果。答：报三个数（示例）：单次调用成本、每日预算、日均实际花费；再说措施：小模型路由、缓存命中率、摘要砍输入；最后说结果，比如缓存和路由上线后单次成本降了多少（用自己的实测数字，不要编）。

五、加分项

生产视角：成本、限流、降级是同一件事的三个面：成本是“花了多少”，限流是“多快会撞墙”，降级是“撞墙了怎么办”。上线清单就三行：单次成本算过吗？每日预算和重试上限设了吗？降级开关和日志有吗？三行都答得上，这个 Agent 才敢给真实用户用。

简历讲法：别写“做过成本优化”，写数字和措施。示范一句写法（数字为示例，换成你自己的实测数）：“RAG Agent 单次调用成本控制在 0.04 元以内（示例），小模型路由 + 缓存 + 摘要三招叠加，日均成本下降约 40%（示例）。”把成本数字写进 AI Agent 版简历作品栏，面试官一眼就能追问，追问的每一步你都有准备。
