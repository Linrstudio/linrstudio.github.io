Day 8：项目全景：从调研数据到 TAPD 的一张图

第 2 周开讲一个真实项目：广告投放平台的用户调研数据，怎么变成 TAPD 里能跟踪落地的需求。这课先把全景画出来：一张图，六个节点，一个共享 State。

一、核心解释

🎮 点一点，走完流水线：从调研数据开始，每点一次“下一步”，跑一个节点，State 里就多几个字段。

第 0 步：还没开始。State 是空的。

State = {}

1. 项目全景：从调研数据到 TAPD 的一条流水线

项目叫“广告投放用户之声，AI 驱动的用户反馈分析项目”，拿过微创新奖。起点是腾讯广告投放平台的用户调研数据，结合 4 年调研数据做纵向对比。

流水线是六步：调研数据 → 清洗、脱敏、打标 → 分析 → 对话追问 → 需求归纳 → TAPD。数据先清洗、脱敏、打标，再进分析；产品同学可以直接对话追问；从反馈中洞察出的需求，直接对接 TAPD 跟踪落地。规模上，客服会话数据每天增量更新，负反馈日均 10 万条。技术栈是 Node + Python + LangChain + PostgreSQL + Redis + Playwright；完整链路是意图识别 → 任务拆解 → RAG 检索 → MCP 工具调用 → 安全校验 → 结果合成，工程侧走统一 API 网关 + Docker 部署。

这个项目从 0 到 1，主导搭建，带人一起做。负责核心架构与主要模块实现，主导知识爬取、RAG 检索链路、多 Agent workflow、MCP 工具接入、安全确认流、Eval 与部署观测体系，基于 trace、eval 与用户反馈持续优化。后面 6 天，每一天讲流水线里的一段。

2. State 设计：字段就是流水线的记忆

State 是整张图的共享记忆。每个节点读它要的字段，写它产出的字段。字段设计得好，图就好讲、好改、好查错。

字段谁写的干嘛用
raw_feedback调研数据节点原始调研数据，只读不改
cleaned_feedback清洗 / 脱敏 / 打标节点脱敏后、可进分析的数据
analysis分析节点定量、定性、交叉分析与用户画像的结果
messages对话追问节点（add_messages 追加）产品同学的追问与 Agent 的回答，带原文引用
requirements需求归纳节点洞察出的需求，每条强制绑定原文引用
tapd_statusTAPD 节点需求进 TAPD 后的跟踪状态

注意两条规矩：原始数据只读不改，脏数据永远能追溯；需求归纳强制绑定原文引用，没有出处的需求不进 TAPD。

3. 为什么用图不用链：因为这条流水线会分叉、会循环、会停住

链只能一条路走到底。这条流水线不行：分析要四路并行（定量、定性、交叉、画像），跑完再汇总；交叉分析要按问题类型分流；对话追问要循环问下去；写 TAPD 之前要停住等人工审核；跑一半断了，要从 Checkpoint 续跑。

图能表达这些：并行用 Send fan-out，循环用回边，分流用条件边，停住用 interrupt，续跑用 Checkpoint。链表达不了，图可以。

容易踩的坑：权限隔离只做在 UI 层，检索层没过滤。Agent 回答带出了别家产品的反馈——负责创意的产品同学，看到了其他产品的反馈。这是最难的 Bug，Day 12 专门讲修复：记录和知识片段带 product_id，检索层硬性过滤。

二、代码示例

示例 1：项目全景图（先看形状）

from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver

# State：流水线的共享记忆，字段按“谁写、干嘛用”设计
class FeedbackState(TypedDict):
    raw_feedback: list        # 原始调研数据，只读不改
    cleaned_feedback: list    # 清洗、脱敏、打标后的数据
    analysis: dict            # 定量、定性、交叉分析与用户画像
    messages: Annotated[list, add_messages]  # 对话追问，追加式
    requirements: list        # 洞察出的需求，强制绑定原文引用
    tapd_status: str           # 需求进 TAPD 后的跟踪状态（待写 / 已创建 / 已拒绝）

graph = StateGraph(FeedbackState)
graph.add_node("clean_tag", clean_tag_node)      # 清洗、脱敏、打标
graph.add_node("analyze", analyze_node)          # 分析（内部并行，Day 10 讲）
graph.add_node("chat", chat_node)                # 对话追问（ReAct + 检索，Day 11 讲）
graph.add_node("requirements", requirements_node)  # 需求归纳
graph.add_node("tapd", tapd_node)                # 写 TAPD（工具节点，Day 13 讲）
graph.add_edge(START, "clean_tag")
graph.add_edge("clean_tag", "analyze")
graph.add_edge("analyze", "chat")
graph.add_edge("chat", "requirements")
graph.add_edge("requirements", "tapd")
graph.add_edge("tapd", END)
# 生产里写 TAPD 前的人工审批用 tapd 节点里的 interrupt()（Day 12、Day 13 讲），编译期中断参数只留调试用
app = graph.compile(checkpointer=MemorySaver())

示例 2：跑一次全景图（概念代码，按生产配置）

# 调研数据先放进 State，thread_id 做会话隔离
config = {"configurable": {"thread_id": "feedback-2026"}}
result = app.invoke(
    {"raw_feedback": load_feedback()},  # 数据源按生产配置
    config=config,
)
# 写 TAPD 前的人工审核（tapd 节点里的 interrupt()，Day 12、Day 13 讲）：审核通过后再续跑
# 注意：invoke(None) 传不回决定值，interrupt() 会拿到 None、等于默认批准，人的决定就丢了；
# interrupt() 续跑必须用 Command(resume=决定值）
from langgraph.types import Command
result = app.invoke(Command(resume="批准"), config=config)  # 同一 thread_id，从 Checkpoint 续跑
print(result["requirements"])  # 每条需求都带原文引用
print(result["tapd_status"])   # 需求进 TAPD 后的跟踪状态

四、可能的面试题与答案

Q1：讲讲这个项目是干嘛的？

广告投放平台的用户调研数据，结合 4 年调研数据做纵向对比，先清洗、脱敏、打标再进分析，支持定量、定性、交叉分析与用户画像，产品同学可以直接对话追问，从反馈中洞察出的需求直接对接 TAPD 跟踪落地。从 0 到 1，主导搭建，带人一起做。

Q2：这张图长什么样？State 里有哪些字段？

六个节点：清洗 / 脱敏 / 打标 → 分析 → 对话追问 → 需求归纳 → TAPD。State 字段按“谁写、干嘛用”设计：raw_feedback 只读不改，cleaned_feedback 是脱敏后的数据，analysis 是分析结果，messages 用 add_messages 追加对话，requirements 是带原文引用的需求，tapd_status 是进 TAPD 后的跟踪状态。

Q3：为什么用图不用链？

因为流水线会分叉、会循环、会停住：分析要四路并行再汇总，交叉分析要按问题类型分流，对话追问要循环，写 TAPD 前要停住等人工审核，跑一半断了要从 Checkpoint 续跑。链只能一条路走到底，图能表达并行、循环、分流和中断。

Q4：这个项目最难的 Bug 是什么？怎么修的？

权限隔离只做了 UI 层，检索层没过滤，Agent 回答带出了别家产品的反馈，负责创意的产品同学看到了其他产品的反馈。修复是记录和知识片段带 product_id，检索层硬性过滤，再加最小样本数（少于 5 条只给趋势），防再犯是权限验收回归——拿没权限的账号去问。

Q5：如果重做这个项目，你会先改什么？

两件事：一开始就给知识库加版本号和更新触发器；需求归纳强制绑定原文引用。评测抓手是需求闭环可追踪，加上人工抽查（10%–20%）和权限验收回归。

五、加分项

生产视角：一张全景图上线前，先问三个问题：原始数据是不是只读不改？需求有没有强制绑定原文引用？写 TAPD 之前有没有停住等人工审核？三问有一个答不上来，这张图就别上。

简历讲法：别写“用 LangGraph 做了用户反馈分析”，写“从 0 到 1 主导搭建：广告投放平台用户调研数据，结合 4 年数据做纵向对比，清洗、脱敏、打标后进分析，产品同学可对话追问，洞察出的需求对接 TAPD 跟踪落地；数据按产品隔离权限”。前者是名词，后者是可追问的项目。
