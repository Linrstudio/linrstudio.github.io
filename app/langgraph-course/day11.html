Day 11：对话追问：ReAct、检索与引用绑定

产品同学能直接对话追问，靠的是 ReAct 循环加检索：Agent 先想“要查什么”，再去知识库里找原文，最后把答案和出处绑在一起说出来。今天把这条追问链讲清。

一、核心解释

1. ReAct 循环：先想，再查，再答

ReAct 就是“思考—行动—观察”循环。Agent 收到追问，先想“我要查什么”，再调用检索工具去知识库里找，拿到结果后观察够不够，不够就再查一轮，够了才回答。

检索工具是 ToolNode 里的一员，和别的工具一样走 tools_condition 分流。模型决定要不要查、查什么词，图只负责把工具结果写回状态。

2. 引用绑定：答案的每一句都要有出处

检索到的原文片段要和答案绑在一起。回答时，每一句结论后面挂一个引用，指向具体的知识片段。产品同学点引用，能看到原文。

这个绑定是在重做时定下的规矩：需求归纳强制绑定原文引用。追问回答也一样，没有出处的结论不许直接说。跨文档对比与多跳问题容易召回偏斜、引用不可信，对策是三件套：先把问题做查询拆解，再做证据覆盖检查，最后做引用一致性评估——证据没覆盖、引用对不上的回答不输出。

3. 检索为空：老实说“没有”

知识库里没有，就直接说“知识库里没有”。不编，不猜，不拿模型自己的话补上。说“没有”本身就是正确答案的一部分。

这条规矩保护的是信任：产品同学一旦发现一次编造，以后每句回答都要自己再核对一遍，追问功能就没人用了。

4. thread_id 续聊：追问接着上一轮

同一轮对话用同一个 thread_id，Checkpoint 把每轮的消息都存下来。追问“那创意侧呢”，Agent 能看到上一轮问的是什么，接着往下查，不用用户把问题重说一遍。

换一个 thread_id，就是新的一轮对话。会话隔离靠它，断点续跑也靠它。

容易踩的坑：只在 UI 层做权限隔离是不够的。Day 12 会讲本项目最难的 Bug：检索层没过滤，Agent 回答带出了别家产品反馈。引用绑定要绑在检索层过滤后的片段上，绑错了层，出处本身就是错的。

二、代码示例

示例 1：追问图：ReAct + 检索 + 引用绑定（先看形状）

from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode, tools_condition
from langgraph.checkpoint.memory import MemorySaver
from typing import Annotated, TypedDict

# State：消息走 add_messages 追加；citations 存本轮回答的引用
class ChatState(TypedDict):
    messages: Annotated[list, add_messages]
    citations: list  # 每条是 {"quote": 原文片段, "source": 出处}

# 检索工具：按生产配置接知识库；返回原文片段 + 出处
def retrieve(query: str):
    """从产品知识库检索原文片段，返回带出处的片段列表。"""
    return search_kb(query)  # 按生产配置实现

tools = [retrieve]
agent = build_agent_with_tools(tools)  # 模型绑定工具，按生产配置

def answer_node(state: ChatState):
    # 模型根据检索到的片段作答；每句结论挂引用，写进 citations
    reply = agent.invoke(state["messages"])
    return {"messages": [reply], "citations": extract_citations(reply)}

graph = StateGraph(ChatState)
graph.add_node("agent", agent_node)        # 思考：要不要查、查什么
graph.add_node("tools", ToolNode(tools))   # 行动：执行检索
graph.add_node("answer", answer_node)      # 引用绑定后作答
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", tools_condition,
                            {"tools": "tools", END: "answer"})
graph.add_edge("tools", "agent")           # 观察结果，不够就再查一轮
graph.add_edge("answer", END)

# thread_id 续聊：同一 thread_id 再 invoke，接着上一轮跑
app = graph.compile(checkpointer=MemorySaver())
app.invoke(
    {"messages": [("user", "用户最常抱怨什么？")]},
    config={"configurable": {"thread_id": "creative-001"}},
)

示例 2：检索为空时说“没有”（先看形状）

def answer_node(state: ChatState):
    hits = state.get("retrieved", [])  # 检索工具写回的片段
    if not hits:
        # 知识库里没有：老实说没有，不编、不猜
        return {"messages": [("assistant",
            "知识库里没有相关反馈，我没法回答这个问题。")]}
    # 有片段才作答，每句结论挂引用
    reply = agent.invoke(state["messages"])
    return {"messages": [reply], "citations": extract_citations(reply)}

四、可能的面试题与答案

Q1：对话追问这张图长什么样？

ReAct 循环：agent 节点思考要不要查、查什么，tools 节点（ToolNode）执行检索，查完回 agent 观察够不够，不够再查，够了进 answer 节点做引用绑定再回答。State 里 messages 用 add_messages 追加，citations 存本轮回答的引用。

Q2：引用绑定是怎么做的？为什么重要？

回答的每句结论后面挂引用，指向检索到的原文片段，点引用能看到原文。这是重做时定下的规矩：需求归纳强制绑定原文引用。没有出处的结论不许直接说，这样产品同学才敢直接拿回答去推进。

Q3：检索为空时你们怎么处理？

直接说“知识库里没有”，不编、不猜、不拿模型自己的话补。说“没有”本身就是正确答案的一部分；编造一次，产品同学以后每句回答都要自己再核对，追问功能就没人用了。

Q4：thread_id 在追问里起什么作用？

同一轮对话用同一个 thread_id，Checkpoint 把每轮消息存下来，追问时 Agent 能看到上一轮问的是什么，接着往下查。换一个 thread_id 就是新的一轮对话，会话隔离和断点续跑都靠它。

Q5：检索工具和普通工具节点有什么不同？

没有本质不同：检索工具也是 ToolNode 里的一员，走 tools_condition 分流，模型决定要不要查、查什么词。不同的是结果的处理——检索到的原文片段要进引用绑定，答案的每一句结论都要挂上出处。

五、加分项

生产视角：追问功能上线前，先问三个问题：回答的每一句结论都有引用吗？检索为空时说的是“没有”还是编了一段？同一个 thread_id 追问两句，第二句还接得上上一轮吗？三问有一个答不上来，追问就别上。

简历讲法：别写“做过对话追问”，写“ReAct + 检索的追问图：模型决定查什么，ToolNode 执行检索，答案每句结论绑定原文引用，检索为空直接说没有；同一 thread_id 续聊，Checkpoint 存每轮消息”。前者是名词，后者是可追问的项目。
