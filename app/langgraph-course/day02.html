Day 2：状态与 Reducer：AgentState、add_messages、为什么状态要可合并

Day 1 说过：节点只返回它改了的那一部分，图会把它合并进旧状态。今天讲合并的规矩——Reducer。没有 Reducer，两个节点同时改同一个字段，谁后写谁就赢，消息列表会被新消息整个盖掉，聊天记录直接丢了。

一、核心解释

1. AgentState 是什么：一张有类型的记事本

状态用 TypedDict 定义，每个字段都有类型。Agent 最常用的状态叫 AgentState，核心字段是 messages（消息列表）。

2. Reducer 是什么：旧值 + 更新 = 新值

Reducer 就是一个字段的合并规则，写在字段的 Annotated 里。没有 Reducer 的字段默认是“覆盖”；列表、计数这种字段必须显式指定 Reducer。

3. add_messages 是干嘛的：消息只能追加，不能覆盖

messages: Annotated[list, add_messages] 是最常用的一行。节点返回一条新消息，图把它追加到列表末尾，而不是替换整个列表。

4. 为什么状态要可合并：并行分支的需要

两个节点同时跑、同时往状态里写，没有 Reducer 会互相覆盖，只剩一个；有了 Reducer，两个更新按规则合并，消息都追加、计数都加上。

容易踩的坑：在节点里直接改传入的 state（比如 state["messages"].append(...)）。节点应该返回更新，让图去合并；直接改传入的状态，图不知道你改了什么，Checkpoint 存下来的可能是改之前的状态，断点续跑会丢数据。

二、代码示例

示例 1：AgentState + add_messages（先看形状）

from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages
from langchain_core.messages import HumanMessage, AIMessage

# 状态：messages 字段的 Reducer 是 add_messages（追加，不是覆盖）
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
    steps: int  # 没有 Reducer 的字段：默认覆盖

def agent_node(state: AgentState):
    # 节点只返回更新：一条新消息 + 步数加 1 的增量写法要小心，
    # steps 没有 Reducer，这里返回的是“新值”不是“增量”
    return {
        "messages": [AIMessage(content="我来查一下。")],
        "steps": state["steps"] + 1,
    }

# 跑两步之后，messages 里是两条消息（追加），不是只剩最后一条

示例 2：没有 add_messages 会怎样（对比实验）

class BadState(TypedDict):
    messages: list  # 没有 Reducer：默认覆盖

def bad_node(state: BadState):
    return {"messages": [AIMessage(content="新消息")]}

# 初始 messages = [HumanMessage("你好")]
# 跑完 bad_node 后，messages = [AIMessage("新消息")]——用户的“你好”丢了！
# 这就是为什么 messages 字段一定要配 add_messages

四、可能的面试题与答案

Q1：Reducer 是什么？为什么需要它？

Reducer 是一个字段的合并规则：旧值 + 更新 = 新值，写在 Annotated 里。没有它，字段默认是覆盖；并行分支同时写状态时会互相覆盖。有了它，消息列表追加、计数累加，并发写变成确定性的合并。

Q2：add_messages 做了什么？

它是 messages 字段的 Reducer：节点返回的新消息追加到列表末尾，而不是替换整个列表。没有它，模型节点返回一条消息后，之前的对话记录全丢了。

Q3：节点为什么不能直接改传入的 state？

节点应该返回更新，让图按 Reducer 合并。直接改传入的状态，图不知道你改了什么，Checkpoint 存下来的可能是改之前的状态，断点续跑会丢数据。

Q4：一个字段没有 Reducer，会怎样？

默认覆盖：新值直接替换旧值。计数、列表这类需要累加的字段，必须显式配 Reducer，比如数字用 operator.add。

Q5：AgentState 一般长什么样？

TypedDict，核心字段是 messages: Annotated[list, add_messages]，再按需加 steps、found（检索到的资料）、plan（计划）等字段。每个字段的合并规则都要事先想清楚。

五、加分项

生产视角：定义状态之前先列一张表：每个字段是什么类型、Reducer 是什么、谁会写它。并行分支会同时写的字段，一定要配 Reducer；只读字段可以不配。

简历讲法：别写“会定义 AgentState”，写“messages 配 add_messages 追加、计数配 operator.add 累加，节点只返回更新、图按 Reducer 合并，并行分支写状态不丢数据”。前者是名词，后者是可追问的设计。
