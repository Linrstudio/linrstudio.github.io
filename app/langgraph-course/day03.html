Day 3：条件边与路由：tools_condition、按条件分流、循环与终止

Day 1 的图是直的：START → greet → END，一条路走到黑。真实的 Agent 要会拐弯：模型想调工具就去工具节点，不想调就结束；检索不到就换个问法再试，试三次还不行就认输。拐弯靠的就是条件边。

一、核心解释

1. 条件边是什么：边上挂一个路由函数

普通边是死箭头：做完 A 一定去 B。条件边是活箭头：add_conditional_edges("agent", 路由函数, {"tools": "tools", END: END})，路由函数读当前状态、返回一个字符串，图按这个字符串决定下一步去哪个节点。路由函数只做一件事：看状态，报名字，不做业务逻辑。

2. tools_condition：最常用的现成路由

LangGraph 自带一个路由函数 tools_condition，专门判断“模型最后一条消息有没有工具调用”：有，就返回 "tools"，去工具节点；没有，就返回 END，图结束。ReAct 循环的核心就是它，Day 4 会完整跑一遍。记住：tools_condition 看的是最后一条 AI 消息里的 tool_calls，不是看状态里有没有别的字段。

3. 循环是怎么形成的：回边

循环不是特殊语法，就是一条指回去的边：工具节点跑完，加一条普通边 add_edge("tools", "agent") 回到 agent 节点，agent 再调模型、再判断要不要调工具。循环的每一次都是一次“模型 → 工具 → 模型”的回合，状态里的 messages 在不断变长。

4. 循环怎么终止：两个保险

循环必须能停，有两个保险：第一，业务终止条件——模型不再调工具，tools_condition 返回 END，循环正常结束；第二，步数上限——图编译时默认有递归上限（recursion_limit，默认 25 步），超过就抛错停下，防止模型死循环把账单跑爆。步数上限可以在 invoke 时用 {"recursion_limit": 50} 调，但调大之前先问：模型为什么一直调工具？是不是提示词或工具设计有问题？上限是保险丝，不是解决方案。

容易踩的坑：路由函数返回了映射表里没有的名字。比如映射表只有 {"tools": "tools", END: END}，路由函数却返回了 "retry"，图会直接报错。路由函数的返回值必须和映射表的键一一对应，写完先对一遍表。

二、代码示例

示例 1：自己写路由函数（先看形状）

from langgraph.graph import StateGraph, START, END

def route_by_steps(state):
    # 路由函数：只看状态，报名字，不做业务逻辑
    if state["steps"] >= 3:
        return END          # 步数到了，去 END
    return "work"           # 否则去 work 节点

graph = StateGraph(State)
graph.add_node("work", work_node)
graph.add_conditional_edges(START, route_by_steps, {"work": "work", END: END})
graph.add_edge("work", END)
app = graph.compile()

示例 2：tools_condition 的用法（ReAct 的核心，Day 4 展开）

from langgraph.prebuilt import tools_condition, ToolNode

graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)        # 模型节点：调模型，可能返回工具调用
graph.add_node("tools", ToolNode(tools))   # 工具节点：执行工具调用
graph.add_edge(START, "agent")
# 条件边：最后一条消息有工具调用 → tools；没有 → END
graph.add_conditional_edges("agent", tools_condition)
graph.add_edge("tools", "agent")  # 回边：工具跑完，回到 agent 再调模型
app = graph.compile()

四、可能的面试题与答案

Q1：条件边是什么？和普通边有什么区别？

普通边是死箭头，做完 A 一定去 B；条件边挂一个路由函数，读当前状态、返回一个字符串，图按字符串决定下一步去哪。路由函数只看状态、报名字，不做业务逻辑。

Q2：tools_condition 是干嘛的？

LangGraph 自带的路由函数，判断最后一条 AI 消息有没有工具调用：有去 tools 节点，没有去 END。它是 ReAct 循环的核心。

Q3：LangGraph 的循环是怎么形成的？怎么停？

循环就是一条回边：tools 跑完回到 agent，再调模型、再判断。停靠两个保险：业务终止条件（模型不再调工具）和步数上限 recursion_limit（默认 25 步）。

Q4：路由函数返回了映射表里没有的名字，会怎样？

图直接报错。路由函数的返回值必须和映射表的键一一对应，排错先查映射表。

Q5：recursion_limit 应该调大吗？

先别调。步数上限是保险丝，模型一直调工具说明提示词或工具设计有问题，先修那个；实在需要多步（比如长任务）再调大，并配上步数统计和告警。

五、加分项

生产视角：每条条件边都要配一张表：路由函数会返回哪些值、每个值去哪个节点、哪个值是终止条件。表对不上，图就跑不起来；终止条件想不清楚，图就会死循环。

简历讲法：别写“会用条件边”，写“用 tools_condition 做 ReAct 路由：有工具调用去 ToolNode、没有去 END，工具跑完回边到 agent，recursion_limit 25 步做保险”。前者是名词，后者是可追问的机制。
