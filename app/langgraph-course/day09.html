Day 9：数据层：清洗、脱敏、打标三个节点

分析做得再好，也救不回脏数据。今天只做一件事：把调研数据变成分析能用的干净数据——清洗、脱敏、打标，三个节点，一个都不能省。

一、核心解释

1. 清洗节点：先把不能用的去掉

调研数据里有空反馈、重复提交、乱码和明显无效的内容。清洗节点只干一件事：去掉这些，留下能分析的。客服会话数据每天增量更新：每天只处理新增的会话，入库时做增量索引，新数据进库不用全量重建索引。

清洗不改原意。删的是一条记录，不是改写一句话。删了什么、为什么删，记在状态里，方便回头查。

2. 脱敏节点：入库前做，晚了就没用了

反馈里常带姓名、电话、邮箱、公司名。这些信息分析用不上，但一旦入库，Agent 就能看到。脱敏必须在入库前完成。

顺序不能换。先入库、后脱敏，等于先把隐私交出去，再假装没交过。下面可以点一点，看同一条反馈脱敏前后 Agent 各能看到什么。

互动：一条样本反馈，脱敏前后对比

样本反馈（示意，非真实用户数据）：

“我是小李，电话 138-1234-5678，邮箱 lili@example.com，在 XX 公司做投放。创建广告时，操作步骤太多，经常找不到定向设置，希望能简单一点。”

Agent 能看到：姓名、电话、邮箱、公司名、反馈内容——全部可见。

Agent 看不到：（脱敏前）什么都没藏。

3. 打标节点：模型先打，人再复核

打标是给每条反馈贴上标签：它在说什么、属于哪个环节、情绪是正面还是负面。标签越准，后面的定量、定性、交叉分析才越准。

模型打标快，但会打错。人工复核不是全量重做，是抽查加纠错：发现打错的标签就改过来，改完才算数。下面点一下，看一次人工复核改了什么。

互动：打标演示（模型打标 + 人工改一处）

模型打标：操作复杂 定向设置 负面

人工复核：尚未复核。点下面的按钮，看人工改了哪一处。

4. State 的 reducer：三个节点怎么往状态里写数据

三个节点跑完，状态里要多出三样东西：清洗后的反馈、脱敏后的反馈、打好的标签。每个节点只写自己那一份，不动别人的。

这就是 reducer 的作用：messages 用 add_messages 追加，列表字段用“追加”而不是“覆盖”。两个节点同时写状态，也不会互相丢数据。

节点读什么往 State 里写什么
清洗原始反馈cleaned_feedback（清洗后的列表）
脱敏清洗后的反馈masked_feedback（脱敏后的列表，入库用这份）
打标脱敏后的反馈tags（标签列表，复核后才定稿）
容易踩的坑：脱敏放在入库之后做。数据一进库，Agent 就能检索到；事后删库里的原始文本，也删不掉已经生成的引用和快照。脱敏节点必须排在入库之前，顺序写进图里，别靠人记。

二、代码示例

示例 1：清洗 → 脱敏 → 打标，三个节点串起来（先看形状）

from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver
import operator

# State：每个节点只写自己那一份，用 reducer 追加，不覆盖
class DataState(TypedDict):
    messages: Annotated[list, add_messages]  # 对话记录，追加
    raw_feedback: list  # 原始反馈
    cleaned_feedback: Annotated[list, operator.add]  # 清洗后，追加
    masked_feedback: Annotated[list, operator.add]  # 脱敏后，追加
    tags: Annotated[list, operator.add]  # 标签，追加

def clean_node(state: DataState):
    # 去掉空反馈、重复提交、乱码；删了什么记下来
    cleaned = [f for f in state["raw_feedback"] if f.strip()]
    return {"cleaned_feedback": cleaned}

def mask_node(state: DataState):
    # 脱敏：姓名、电话、邮箱、公司名全部替换掉
    # 注意：这一步在入库前做，入库用的就是 masked_feedback
    masked = [mask_pii(f) for f in state["cleaned_feedback"]]
    return {"masked_feedback": masked}

def tag_node(state: DataState):
    # 打标：模型先打标签，标签列表写进 State
    tags = [tag_one(f) for f in state["masked_feedback"]]
    return {"tags": tags}

graph = StateGraph(DataState)
graph.add_node("clean", clean_node)
graph.add_node("mask", mask_node)
graph.add_node("tag", tag_node)
graph.add_edge(START, "clean")
graph.add_edge("clean", "mask")  # 顺序写死：清洗 → 脱敏
graph.add_edge("mask", "tag")  # 脱敏 → 打标，脱敏在入库前
graph.add_edge("tag", END)
app = graph.compile(checkpointer=MemorySaver())

示例 2：打标后人工复核，interrupt 停住等人工改（先看形状）

from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import interrupt
from langgraph.prebuilt import ToolNode

# 人工复核节点：把模型打的标签给人看，人改完再继续
def review_node(state: DataState):
    # interrupt 停住：等人工复核，改完的标签由人工传回来
    reviewed_tags = interrupt({"tags": state["tags"], "note": "请复核标签，打错的改掉"})
    return {"tags": reviewed_tags}

# 入库节点：只写脱敏后的反馈 + 复核后的标签，不写原始文本
def store_node(state: DataState):
    # 按生产配置接知识库写入工具；这里只看形状
    return {"messages": ["已入库：脱敏后的反馈 + 复核后的标签"]}

graph = StateGraph(DataState)
graph.add_node("tag", tag_node)
graph.add_node("review", review_node)  # 人工复核
graph.add_node("store", store_node)  # 入库
graph.add_edge(START, "tag")
graph.add_edge("tag", "review")
graph.add_edge("review", "store")
graph.add_edge("store", END)
# ToolNode 挂在 store 之后也行：入库本身就是一次工具调用
app = graph.compile(checkpointer=MemorySaver())

四、可能的面试题与答案

Q1：数据层为什么要拆成清洗、脱敏、打标三个节点？

三个节点各管一件事：清洗去掉不能用的，脱敏去掉隐私，打标贴上标签。拆开之后顺序写进图里，出了问题能定位到具体哪一步，也能单独换掉某一步的做法。

Q2：脱敏为什么必须在入库前？放后面会怎样？

数据一进库，Agent 就能检索到；事后删库里的原始文本，也删不掉已经生成的引用和快照。所以脱敏节点必须排在入库之前，顺序写进图里，别靠人记。

Q3：打标是模型打还是人工打？

模型先打，人工再复核。模型打标快但会打错，人工复核是抽查加纠错，发现打错的标签就改过来，改完才算数，入库只用复核后的标签。

Q4：State 的 reducer 在数据层起什么作用？

每个节点只写自己那一份：messages 用 add_messages 追加，列表字段用追加而不是覆盖。两个节点同时写状态，也不会互相丢数据，清洗、脱敏、打标三份结果都留在状态里。

Q5：这个项目的数据层，你从 0 到 1 主导搭建时最难的是什么？

最难的不是三个节点本身，是顺序和权限：脱敏必须在入库前，检索层还要按产品隔离权限。这个项目最难的 Bug 就是权限隔离只做了 UI 层、检索层没过滤，Agent 回答带出了别家产品反馈——数据层做对了，权限还要在检索层再做一层，Day 12 再讲。

五、加分项

生产视角：数据层上线前问三个问题：脱敏在入库前吗？打标有人复核吗？清洗删了什么能查到吗？三问有一个答不上来，数据就别进分析。

简历讲法：别写“做过数据清洗”，写“从 0 到 1 主导搭建数据层：清洗、脱敏、打标三个节点，脱敏在入库前完成，打标加人工复核，State 用 reducer 追加写回，入库只用脱敏后的反馈和复核后的标签”。前者是名词，后者是可追问的项目。
