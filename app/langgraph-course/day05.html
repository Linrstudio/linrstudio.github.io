Day 5：Checkpoint 与断点续跑：MemorySaver、thread_id、从中断处继续

手写循环跑到一半断了，只能从头再跑；LangGraph 的图跑到一半断了，可以从断的地方继续。靠的就是 Checkpoint：每跑完一步，图就把状态存一个快照，下次接着跑时，先读快照、再继续走。

一、核心解释

1. Checkpoint 是什么：每步一个快照

Checkpoint 就是图在每一步跑完后存的状态快照：跑到哪一步、状态长什么样、下一步去哪。没有它，图就是一次性的，断了就没了。

2. thread_id 是什么：一次对话一个编号

每次 invoke 在 config 里传 {"configurable": {"thread_id": "user-1"}}，同一个 thread_id 的多次调用共享同一份状态、同一串快照，不同 thread 互不干扰。

3. 断点续跑怎么跑：同一 thread_id 再 invoke 一次

图自动读最近的快照、从断的地方继续，之前跑过的步骤不重跑——工具不会重复执行，钱不会重复花。

4. get_state 是干嘛的：看看现在跑到哪了

app.get_state(config) 读出当前状态和下一步要去哪，排错和做“继续”按钮都靠它。

容易踩的坑：MemorySaver 存在内存里，进程一重启，快照全丢了。生产里要换持久化的 Checkpointer（比如 PostgresSaver、RedisSaver），否则“断点续跑”只在同一次运行里有效。MemorySaver 是学习用的，不是上线用的。

动手玩：检查点演示 —— 先跑两步、存一个快照，再中断、再恢复

试试这个顺序：跑一步 → 跑一步 → 保存检查点 → 再跑一步 → 中断 → 从检查点恢复。看恢复后是从第几步继续的，消息有没有丢。再试试不保存检查点就中断恢复，会怎样。

二、代码示例

示例 1：MemorySaver + thread_id，多轮对话不断线

from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)  # 编译时挂上 Checkpointer
config = {"configurable": {"thread_id": "user-1"}}  # 一次对话一个编号

# 第 1 轮：问天气，图跑完，状态存进 thread_id=user-1 的快照
app.invoke({"messages": [HumanMessage("深圳今天天气怎么样？")]}, config)
# 第 2 轮：同一个 thread_id，图读快照接着跑，记得上一轮问过天气
app.invoke({"messages": [HumanMessage("那明天呢？")]}, config)
# 换一个 thread_id，就是一次全新的对话，互不干扰
app.invoke({"messages": [HumanMessage("你好")]}, {"configurable": {"thread_id": "user-2"}})

示例 2：中断后从快照继续（概念代码）

# 第 1 次 invoke 跑到第 2 步后中断（比如进程崩了、或人工点了停）
# 第 2 次 invoke 用同一个 thread_id，什么都不用多做：
state = app.get_state(config)  # 看看现在跑到哪了：停在第 2 步，状态里有两轮消息
app.invoke(None, config)       # 不传新输入，从快照继续跑，不重跑前两步
# 工具不会重复执行：已经执行过的工具调用，在快照里有结果，不会再跑一次

四、可能的面试题与答案

Q1：Checkpoint 是什么？断点续跑是怎么实现的？

Checkpoint 是图每步跑完存的状态快照，由 Checkpointer 存。编译时挂上 Checkpointer，invoke 时传 thread_id，图每次跑完一步就存一个快照；中断后用同一 thread_id 再 invoke，图读最近的快照接着跑，不重跑之前的步。

Q2：thread_id 是干嘛的？不传会怎样？

一次对话一个编号，同一个 thread_id 的多次调用共享状态和快照，不同的互不干扰。通常就是用户 ID 或会话 ID。不传它，每次调用都是全新对话，上下文全丢了。

Q3：MemorySaver 和生产用的 Checkpointer 差在哪？

MemorySaver 存在内存里，进程重启快照全丢，只适合学习和演示。生产里用 PostgresSaver、RedisSaver 这种持久化的，重启也不丢。

Q4：续跑时工具会不会重复执行？

不会。已经执行过的工具调用，结果在快照里，续跑时直接用，不重跑。钱不会重复花，消息不会重复发。

Q5：get_state 有什么用？

读出当前状态和下一步要去哪。排错靠它，做“继续”按钮靠它，Day 6 人工审核前看停在哪一步、状态里有什么，也靠它。

五、加分项

生产视角：Checkpoint 上线前，先问三个问题：thread_id 怎么定（用户 ID 还是会话 ID）？快照存哪（内存还是数据库）？快照保留多久（过期清理做了吗）？三问有一个答不上来，断点续跑就别上。

简历讲法：别写“会用 Checkpoint”，写“编译时挂 MemorySaver、invoke 传 thread_id 做会话隔离，中断后同一 thread_id 再 invoke 从快照续跑，工具不重执行，生产换 PostgresSaver 持久化”。前者是名词，后者是可追问的机制。
