Day 6：人工介入与中断：interrupt、human-in-the-loop、审核后继续

Agent 能自己跑，但不是每一步都能自己跑：发全员消息、删文件、扣款这种高危操作，执行前必须停下来、等人看一眼。LangGraph 的中断就是干这个的：图跑到指定的节点前停住，等人审核完，再决定继续、改了再继续，还是不继续。

一、核心解释

1. 中断是什么：图在指定节点前停住

编译时传 interrupt_before=["tools"]，图每次跑到 tools 节点前就停住、返回当前状态，不执行工具。停住不是报错，是正常状态。

2. human-in-the-loop 是什么：人是图里的一步

人不是图的旁观者，是图里的一步。高危操作执行前，图停下来，把“要做什么、参数是什么、影响是什么”展示给人，人看完再决定。

3. 审核后三条路：继续、改了再继续、拒绝

继续：原样执行；改了再继续：用 update_state 改参数再跑；拒绝：不执行，回答里写清楚“已拒绝执行”。三条路都要有，缺了“改”和“拒绝”，审核就只剩一个摆设按钮。

4. 节点内中断：interrupt() 函数

节点里也可以调 interrupt() 动态停住：节点跑到一半，调 interrupt("请确认是否发送")，图停住并把这句话返回给人；人回复后，interrupt() 的返回值就是人的回复，节点接着跑。

容易踩的坑：中断了，但没配 Checkpointer。没有 Checkpointer，图停住后状态没地方存，人回来时图已经忘了跑到哪了。中断和 Checkpoint 是一对：Day 5 是 Day 6 的前置条件。

二、代码示例

示例 1：tools 节点前中断，审核后继续（先看形状）

from langgraph.types import Command
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()
# 编译时定中断点：每次跑到 tools 节点前就停住
app = graph.compile(checkpointer=checkpointer, interrupt_before=["tools"])
config = {"configurable": {"thread_id": "user-1"}}

# 第 1 次 invoke：图跑到 tools 前停住，返回当前状态
app.invoke({"messages": [HumanMessage("给全员发一条通知")]}, config)
state = app.get_state(config)  # 看看停在哪：下一步是 tools，工具调用是 send_broadcast
# 人看完，觉得没问题，继续：
app.invoke(Command(resume="继续执行"), config)  # 从停住的地方接着跑
# 人觉得参数不对，先改状态再继续：
# app.update_state(config, {"messages": [...]})  # 改掉工具调用参数
# app.invoke(None, config)  # 再从停住的地方接着跑

示例 2：节点内用 interrupt() 动态问人

from langgraph.types import interrupt

def send_node(state):
    # 节点跑到一半，动态停住问人；人的回复就是 interrupt() 的返回值
    decision = interrupt("要给全员发这条通知吗？内容是：明天放假一天。")
    if decision == "拒绝":
        return {"messages": [AIMessage("已拒绝发送。")]}
    return {"messages": [send_broadcast()]}

# 第 1 次 invoke 跑到 interrupt() 停住；人回复“继续”后，
# 第 2 次 invoke 传 Command(resume="继续")，节点从 interrupt() 处接着跑

四、可能的面试题与答案

Q1：LangGraph 的中断是怎么实现的？

两种：编译时传 interrupt_before=["tools"]，图每次跑到 tools 节点前停住；节点内调 interrupt()，跑到一半动态停住问人。停住是正常状态，快照已存好，人回来从停住处接着跑，所以中断必须配 Checkpointer。

Q2：human-in-the-loop 是什么意思？

人是图里的一步：高危操作执行前，图停下来，把要做什么、参数、影响展示给人，人看完再决定继续、改了再继续、还是拒绝。人的决定是图继续跑的输入。

Q3：审核后怎么继续？怎么改参数再继续？

继续：再 invoke 一次，或传 Command(resume=...)，图从停住处接着跑。改了再继续：用 update_state 改状态里的工具调用参数，再 invoke。拒绝：不执行，走 END 或“拒绝”分支，回答写清楚已拒绝。

Q4：interrupt_before 和 interrupt() 有什么区别？

interrupt_before 是编译时定死的固定检查点；interrupt() 是节点内动态中断，跑到一半才知道要不要问人时用，人的回复就是它的返回值。

Q5：哪些操作必须人工介入？

高危操作：删文件、发全员消息、扣款、改线上配置。判断标准是“执行错了能不能撤销、影响有多大”，不能撤销、影响大的，都要停下来等人看一眼。

五、加分项

生产视角：人工介入上线前，先问三个问题：哪些节点前要中断（高危操作清单）？审核超时了怎么办（一直等，还是超时自动拒绝）？审核记录留了吗（谁、什么时候、批了什么）？三问有一个答不上来，人就别上。

简历讲法：别写“做过人工审核”，写“tools 节点前 interrupt_before 中断 + Command(resume=...) 续跑，审核三条路（继续、改参数再继续、拒绝），中断配 MemorySaver 存快照”。前者是名词，后者是可追问的机制。
