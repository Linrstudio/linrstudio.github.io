Day 14：知识库更新与复盘：版本戳、竞品对比与面试讲法

最后一课，收束第 2 周：知识库不是建完就完事的，它要一直更新；更新要有版本戳，不然你不知道答案是哪天的。最后把整个项目复盘成一段 5 分钟能讲完的话。

一、核心解释

1. 知识库为什么要持续更新：不更新，答案就过期

产品知识库和竞品知识库都要持续更新。产品发了新能力，库里没有，Agent 就答不出来；竞品上了新能力，库里没有，对比结果就是错的。

所以更新不是“有空再做”，它是图里的一个节点：触发器一到，更新节点就跑，跑完写一个新版本戳。知识库支持 Markdown、JSON、HTML 文档导入，导入后解析、切片再入库，检索时用混合检索，答案带引用生成，更新效果靠 Eval 评估。

2. 更新触发器：什么情况下触发一次更新

触发器分两种。一种是事件触发：产品发布了新能力、竞品有了新动作、新的调研数据到了，就触发一次更新。一种是定时触发：到了固定周期，把两个库都扫一遍。竞品知识库获取困难、定期上新或更新，做法是编写 Skill 设定时任务，定时爬取更新日志及帮助中心文档，拿到新内容后按版本重建索引。

触发器要写在图里，不要只记在人脑子里。写在图里，触发条件、更新内容、版本号都留在状态里，能追溯。

3. 版本戳：每个答案都要能说出自己来自哪个版本

每次更新完，给知识库打一个版本戳，比如 v1.1、v1.2。检索到的每个知识片段，都带上它所属的版本戳。

这样做的好处很直接：用户追问“你这个结论是哪天的”，Agent 能答上来；出了问题，也能定位到是哪个版本的库出了错。

4. 生产复盘：最难的 Bug，和重做会改什么

最难的 Bug：权限隔离只做了 UI 层，检索层没过滤。Agent 回答带出了别家产品的反馈。修复是：记录和知识片段带 product_id，检索层硬性过滤，再加最小样本数——少于 5 条只给趋势。防再犯是权限验收回归：拿没权限的账号去问。

重做点：一开始就给知识库加版本号和更新触发器，需求归纳强制绑定原文引用。这三件事如果一开始就做，后面很多返工都不用做。

容易踩的坑：只给知识库加版本戳，不给答案加。答案里不写版本戳，出了问题还是定位不到是哪个版本的库。版本戳要跟着知识片段一起进答案，跟着引用一起出现。

5. 面试讲法：5 分钟讲稿，五段齐不齐

讲稿结构固定五段：背景 → 架构 → 最难的 Bug → 评测 → 重做会改什么。讲的时候按这个顺序，一段讲一句核心，别展开。

二、代码示例

示例 1：更新触发器 + 版本戳（先看形状）

from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver
from typing import Annotated, TypedDict

class KBState(TypedDict):
    messages: Annotated[list, add_messages]
    kb_version: str          # 当前知识库版本戳，如 v1.2
    updated_chunks: list     # 这次更新入库的知识片段

def check_trigger(state: KBState):
    # 触发器：新调研数据到了，或产品/竞品有新动作，就更新
    # 没触发就直接结束，触发了才进更新节点
    return "update_kb" if state.get("has_new_data") else END

def update_kb(state: KBState):
    # 更新节点：清洗、脱敏、打标后入库，片段带上新版本戳
    # 版本号按生产配置递增，这里只演示形状
    new_version = bump_version(state["kb_version"])  # 如 v1.1 -> v1.2
    chunks = ingest_new_data(state)  # 按生产配置：清洗、脱敏、打标
    for c in chunks:
        c["kb_version"] = new_version  # 每个片段都带版本戳
        c["product_id"] = state.get("product_id")  # 权限过滤用
    return {"kb_version": new_version, "updated_chunks": chunks}

def compare_competitor(state: KBState):
    # 竞品对比节点：拿最新版本戳的两个库做能力比较
    return {"messages": [compare(state["kb_version"])]}

graph = StateGraph(KBState)
graph.add_node("update_kb", update_kb)
graph.add_node("compare", compare_competitor)
graph.add_conditional_edges(START, check_trigger, {"update_kb": "update_kb", END: END})
graph.add_edge("update_kb", "compare")
graph.add_edge("compare", END)
app = graph.compile(checkpointer=MemorySaver())

示例 2：竞品对比节点 + 引用绑定（先看形状）

from langgraph.graph import StateGraph, START, END
from langgraph.prebuilt import ToolNode

def compare_node(state):
    # 对比节点只做一件事：拿最新版本的两个库，对同一个能力做比较
    # 结论必须绑定原文引用：每条结论后面跟一条知识片段出处
    result = compare_capability(
        product_kb=state["product_kb"],      # 产品知识库，最新版本戳
        competitor_kb=state["competitor_kb"],  # 竞品知识库，最新版本戳
        capability=state["capability"],
    )
    # 引用绑定：结论没有出处，就不输出结论，只说“知识库里没有”
    return {"messages": [bind_citations(result)]}

def route_after_compare(state):
    # 对比结果变了（比如竞品追上来了），才需要人工看一眼
    return "human_review" if state.get("comparison_changed") else END

graph = StateGraph(KBState)
graph.add_node("compare", compare_node)
graph.add_node("tools", ToolNode([tapd_tool]))  # 对比结论进 TAPD 跟踪
graph.add_edge(START, "compare")
graph.add_conditional_edges("compare", route_after_compare,
                            {"human_review": "tools", END: END})
graph.add_edge("tools", END)
app = graph.compile(checkpointer=MemorySaver(), interrupt_before=["tools"])

四、可能的面试题与答案

Q1：知识库更新是怎么做的？触发器是什么？

更新是图里的一个节点。触发器分两种：事件触发（新调研数据到了、产品或竞品有新动作）和定时触发（固定周期扫一遍）。触发了才进更新节点，更新完打新版本戳，入库的每个片段都带上版本戳。

Q2：版本戳有什么用？

每个答案都能说出自己来自哪个版本的库。用户追问结论是哪天的，Agent 能答上来；出了问题，也能定位到是哪个版本的库出了错。版本戳要跟着知识片段一起进答案，跟着引用一起出现。

Q3：竞品对比是怎么做出来的？

一个对比节点，拿最新版本戳的产品知识库和竞品知识库，对同一个能力做比较。结论必须绑定原文引用：每条结论后面跟一条知识片段出处，没有出处就不输出结论，只说“知识库里没有”。

Q4：这个项目最难的 Bug 是什么？怎么修的？怎么防再犯？

权限隔离只做了 UI 层、检索层没过滤，Agent 回答带出了别家产品的反馈。修复是记录和知识片段带 product_id、检索层硬性过滤，再加最小样本数（少于 5 条只给趋势）。防再犯是权限验收回归：拿没权限的账号去问。

Q5：如果重做这个项目，你会改什么？

三件事：一开始就给知识库加版本号和更新触发器，需求归纳强制绑定原文引用。这三件事如果一开始就做，后面很多返工都不用做。评测上保持需求闭环可追踪、人工抽查和权限验收回归。

五、加分项

生产视角：知识库上线后，先问三个问题：更新触发器写进图里了吗？每个片段都带版本戳吗？答案里的结论都绑定了原文引用吗？三问有一个答不上来，库越用越不可信。

简历讲法：别写“做过知识库更新”，写“从 0 到 1 主导搭建广告投放用户之声：4 年调研数据纵向对比，清洗、脱敏、打标后进分析，产品与竞品知识库带版本戳持续更新，需求进 TAPD 跟踪落地；最难的坑是检索层权限过滤，修复后加权限验收回归”。前者是名词，后者是可追问的项目。
