Day 10：分析层：并行分析、画像子图与条件边

数据洗干净了，才轮到分析。这一课把分析拆成四路：定量、定性、交叉、画像，四路并行跑，再由汇总节点收口——慢的那一路不堵快的那一路。

一、核心解释

1. 四路分析，各看什么

定量看分布和变化：哪类反馈最多、哪类在变多，还能结合 4 年调研数据做纵向对比。定性看原话：用户到底在抱怨什么、想要什么，每条结论都要能回到原文。

交叉看组合：把两个维度叠在一起看，例如不同使用场景下的同一类反馈，表现是不是不一样。画像看人：把反馈聚成几类典型用户，讲清楚“谁、在什么场景、卡在哪里”。

2. 并行分析：Send 扇出，汇总节点收口

四路互不依赖，就别串行等。先用 Send 把同一份已打标数据扇出到四个节点，四路同时跑；每路跑完把结果写回状态；最后由一个汇总节点收口，把四路结果拼成一份分析。

关键在收口方式：汇总节点只在四路都到齐后才跑。某一路段住了，汇总就等着——这是有意的等，不是 bug。等齐了再拼，分析才完整。

3. 画像做成子图：里面也有自己的小图

画像不是一个节点能装下的：先聚类，再给每类提炼特征，再写成画像描述，最后校验画像有没有原文支撑。把它做成一张子图，内部是“聚类 → 提炼 → 校验”三个节点。

大图只把画像子图当成一个节点：进去是已打标的数据，出来是画像结果。子图内部怎么分、怎么校验，大图不用管；以后画像算法换了，只改子图内部。

4. 交叉分析的条件边：问题决定走哪条路

交叉分析不是每次都全量跑。先看问题长什么样，再决定分流：只问一类用户，就走单维分析；问两类用户的差异，就走交叉对比；问“为什么”，就走定性深挖。

这就是条件边：一个路由函数读状态里的问题类型，返回下一站的名字。问题变了，路线就变了，图不用重画。

分析路回答的问题输出写进状态的什么字段
定量哪类反馈最多？在变多还是变少？quant_result
定性用户原话在说什么？qual_result（带原文引用）
交叉两个维度叠加后，差异在哪？cross_result
画像（子图）这是哪类用户？卡在哪里？persona_result
容易踩的坑：汇总节点过早收口。四路里有一路还没写回状态，汇总就拼出了一份缺角的分析。正确做法是：汇总边只从四路都到齐的状态触发；缺一路，就等一路，别用“先拼一半”凑数。

def fan_out(state):

        Send("qual", state),
        Send("cross", state),
        Send("persona", state),

    return {"summary": "定量 + 定性 + 交叉 + 画像已汇总"}

graph = StateGraph(AnalysisState)
graph.add_node("quant", quant_node)
graph.add_node("qual", qual_node)
graph.add_node("cross", cross_node)

graph.add_node("summarize", summarize_node)
graph.add_edge(START, "fan_out")
graph.add_conditional_edges("fan_out", fan_out,
    {"quant": "quant", "qual": "qual", "cross": "cross", "persona": "persona"})
# 四路都指向汇总节点：到齐后收口
graph.add_edge("quant", "summarize")
graph.add_edge("qual", "summarize")
graph.add_edge("cross", "summarize")
graph.add_edge("persona", "summarize")
graph.add_edge("summarize", END)
app = graph.compile(checkpointer=MemorySaver())

示例 2：交叉分析的条件边（问题决定路线）

# 路由函数：读状态里的问题类型，返回下一站的名字
def route_cross_question(state):
    qtype = state["question_type"]  # single / compare / why
    if qtype == "compare":
        return "cross_compare"  # 对比两类用户，走交叉对比
    if qtype == "why":
        return "qual_deep_dive"  # 问“为什么”，走定性深挖
    return "single_dim"  # 只问一类用户，走单维分析

graph.add_conditional_edges("ask", route_cross_question, {
    "cross_compare": "cross_compare",
    "qual_deep_dive": "qual_deep_dive",
    "single_dim": "single_dim",
})
# 注意：条件边的返回名必须和映射表里的键一一对上，
# 对不上，图会在运行时报错，别靠猜。

四、可能的面试题与答案

Q1：分析层为什么要并行？Send 是怎么用的？

定量、定性、交叉、画像四路互不依赖，串行等就是浪费时间。用 Send 把同一份已打标数据同时扇出到四个节点，四路同时跑，各自把结果写回状态，最后汇总节点收口。

Q2：汇总节点怎么保证四路都到齐了才跑？

四路的边都指向汇总节点，汇总只在四路结果都写回状态后才触发。缺一路就等一路，不拼缺角的分析——过早收口是这一课最容易踩的坑。

Q3：画像为什么做成子图？子图内部长什么样？

画像内部有“聚类 → 提炼 → 校验”三个步骤，一个节点装不下。做成子图后，大图只把它当一个节点：进去是已打标的数据，出来是画像结果；子图内部换了，大图不用改。校验那一步要确认画像有原文支撑。

Q4：交叉分析的条件边是怎么分流的？

路由函数读状态里的问题类型再返回下一站：只问一类用户走单维分析，问两类用户的差异走交叉对比，问“为什么”走定性深挖。返回名必须和映射表里的键一一对上，对不上运行时会报错。

Q5：定量分析里，4 年数据是干嘛的？

做纵向对比：同一类反馈今年和往年比，是变多还是变少。只看一年，只能看到“现在有多少”；叠上 4 年调研数据，才能看到趋势往哪走。

五、加分项

生产视角：分析层上线前先问三句：四路的结果字段会不会互相覆盖（各写各的字段）？汇总节点是不是等齐了才跑？画像子图的进出状态和大图对齐了吗？有一句答不上来，并行分析就别上。

简历讲法：别写“做过并行分析”，写“分析层 Send 扇出定量、定性、交叉、画像四路并行，汇总节点收口；画像做成子图（聚类 → 提炼 → 校验），交叉问题走条件边分流”。前者是名词，后者是可追问的项目。
