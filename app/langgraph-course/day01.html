Day 1：图是什么：StateGraph、节点、边、END

LangChain 课里你手写过 Tool Calling 循环：while 循环里调模型、看有没有工具调用、有就执行、再把结果喂回去。LangGraph 就是把这个循环画成一张图：每一步是一个节点，箭头是边，循环不再是你手写的 while，而是图里的一条回边。今天先把最小的一张图跑起来。

一、核心解释

1. 图的三个零件：节点、边、状态

节点是做事的函数，边是“做完去哪”的箭头，状态是全图共享的记事本。手写循环里散落在变量里的东西，在图里全部收进状态。

2. StateGraph 是什么：先画图，再编译

先用 StateGraph(状态类型) 搭一张“图纸”，往上加节点、加边；再调 .compile() 编译成能跑的图，编译会检查入口、出口和死循环的边。

3. START 和 END：图的入口和出口

add_edge(START, "节点名") 指明第一步去哪，add_edge("节点名", END) 指明哪一步做完就结束。走到 END，整张图就停了。

4. 图比手写循环好在哪：三句话

流程看得见：循环、分支在图里是边，一眼能看出 Agent 会走哪条路；状态有规矩：形状写在状态类型里；能断点续跑：跑一半可以停下来、存下来，下次接着跑。

容易踩的坑：节点函数返回了整个新状态，而不是“更新”。节点应该只返回它改了的那一部分，比如 {"messages": [新消息]}，图会按 Reducer 把它合并进旧状态；返回一整个新状态会把别的字段覆盖掉。Day 2 讲 Reducer 就是讲这个。

动手玩：迷你图运行器 —— 点“下一步”，看图怎么跑

这张图只有一个节点 greet：输入名字，输出一句问候。点下一步，状态会一步步变。

START → greet 节点 → END

二、代码示例

示例 1：最小图跑起来（先看形状，不接真实模型）

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# 状态：全图共享的记事本，这里只有一个字段
class State(TypedDict):
    name: str
    greeting: str

def greet(state: State):
    # 节点：输入当前状态，返回对状态的更新（只返回改了的部分）
    return {"greeting": f"你好，{state['name']}！"}

# 搭图：START → greet → END
graph = StateGraph(State)
graph.add_node("greet", greet)
graph.add_edge(START, "greet")
graph.add_edge("greet", END)
app = graph.compile()  # 编译后才能跑

print(app.invoke({"name": "小明", "greeting": ""}))
# {'name': '小明', 'greeting': '你好，小明！'}

示例 2：两个节点串起来（状态沿边流动）

def add_title(state: State):
    return {"greeting": "尊敬的" + state["greeting"]}

graph2 = StateGraph(State)
graph2.add_node("greet", greet)
graph2.add_node("add_title", add_title)
graph2.add_edge(START, "greet")
graph2.add_edge("greet", "add_title")  # 上一步的输出，是下一步的输入
graph2.add_edge("add_title", END)
app2 = graph2.compile()
print(app2.invoke({"name": "小明", "greeting": ""}))
# {'name': '小明', 'greeting': '尊敬的你好，小明！'}

四、可能的面试题与答案

Q1：LangGraph 的图由哪几部分组成？

节点、边、状态。节点是步骤（一个函数），边是流向（做完去哪），状态是全图共享的记事本。建图分两步：StateGraph 搭图纸，compile 编译成能跑的图。

Q2：为什么用图，不用手写 while 循环？

流程看得见：循环、分支、重试在图里是边，一眼能看出 Agent 会走哪条路；状态有规矩：形状写在状态类型里；能断点续跑：跑一半可以停下来存下来，下次接着跑。

Q3：节点返回整个新状态会怎样？

会把别的字段覆盖掉。节点应该只返回它改了的那一部分更新，图按 Reducer 合并进旧状态。Reducer 的细节是 Day 2 的内容。

Q4：START 和 END 必须有吗？

每张图都有隐含的 START 和 END。入口边指明第一步，出口边指明哪一步做完结束。没有 END 的图会一直跑，直到步数上限把它拦住。

Q5：compile 做了什么？

把图纸编译成能跑的图，并检查入口、出口和死循环的边。没编译的图跑不起来，编译过的图才能 invoke。

五、加分项

生产视角：画图之前先问：这张图有几个节点、几条边、状态里有哪几个字段？画不出来就别写代码——流程想不清楚，代码只会更乱。

简历讲法：别写“会用 LangGraph”，写“用 StateGraph 把手写 Tool Calling 循环改成图：节点是步骤、边是流向、状态是共享记事本，编译后 invoke 跑通”。前者是名词，后者是可追问的动手过程。
