Day 4：工具节点与 ReAct Agent：ToolNode、模型调工具、循环直到无工具调用

前三天把图的零件讲完了，今天把它们拼成一个真正能干活的 Agent：模型节点调模型、工具节点跑工具、条件边在中间分流，循环直到模型不再调工具。这就是 ReAct，用图画出来只有两个节点、两条边。

一、核心解释

1. ReAct 是什么：推理和行动交替进行

模型先想（要不要调工具、调哪个、传什么参数），再做（执行工具），看到工具结果再想、再做，直到它觉得不用调工具了、直接回答。

2. ToolNode 是什么：执行工具调用的现成节点

ToolNode(tools) 干三件事：从最后一条 AI 消息里取出工具调用，按名字找到对应的工具函数，执行它，把结果包成 ToolMessage 追加回状态。

3. 模型怎么调工具：bind_tools

模型节点里，模型要先 llm.bind_tools(tools) 绑定工具列表，调模型时它才会在需要的时候返回 tool_calls。没绑定的模型永远不会调工具，图第一轮就走到 END。

4. 循环什么时候停：模型说了算，步数上限兜底

停的条件是模型某次返回的消息里没有 tool_calls，tools_condition 返回 END。正常两三轮就停；一直调工具就靠 recursion_limit（默认 25 步）拦住。

容易踩的坑：用已经弃用的旧版 ReAct 工厂函数。新版 LangGraph 里它已弃用，推荐做法就是今天这张手写图：StateGraph + ToolNode + tools_condition。手写图多几行代码，但每一步都看得见、改得动，面试也能讲清。

二、代码示例

示例 1：ReAct Agent 完整图（先看形状，模型换成你的）

from langchain_core.tools import tool
from langchain_core.messages import HumanMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode, tools_condition
from typing import Annotated, TypedDict

class AgentState(TypedDict):
    messages: Annotated[list, add_messages]

@tool
def get_weather(city: str) -> str:
    """查指定城市的天气。参数 city 是城市名，比如“深圳”。"""
    return f"{city}当前 26.5°C，多云。（示例数据）"

tools = [get_weather]
llm = ChatOpenAI(model="...")  # 换成你的模型
llm_with_tools = llm.bind_tools(tools)  # 绑定工具，模型才能调工具

def agent_node(state: AgentState):
    # 模型节点：调模型，可能返回工具调用，也可能直接回答
    return {"messages": [llm_with_tools.invoke(state["messages"])]}

graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", ToolNode(tools))  # 现成节点：执行工具调用，包成 ToolMessage
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", tools_condition)  # 有调用去 tools，没有去 END
graph.add_edge("tools", "agent")  # 回边：工具跑完，回到 agent 再调模型
app = graph.compile()

result = app.invoke({"messages": [HumanMessage("深圳今天天气怎么样？")]})
print(result["messages"][-1].content)

示例 2：一轮跑通的轨迹（发生了什么）

# 第 1 轮 agent：模型看到“深圳今天天气怎么样”，返回 tool_calls=[get_weather(city="深圳")]
# 条件边：有工具调用 → tools 节点
# tools 节点：执行 get_weather("深圳")，追加 ToolMessage("深圳当前 26.5°C，多云")
# 回边 → agent：第 2 轮模型看到工具结果，不再调工具，直接回答“深圳今天 26.5°C，多云”
# 条件边：没有工具调用 → END，图结束
# 状态里的 messages 全程是：Human → AI(工具调用) → Tool → AI(最终回答)

四、可能的面试题与答案

Q1：用 LangGraph 搭一个 ReAct Agent，图长什么样？

两个节点、两条边：agent 节点调模型（bind_tools 绑定工具），tools 节点是 ToolNode 执行工具调用；START → agent，agent 上挂 tools_condition 条件边（有调用去 tools，没有去 END），tools 回边到 agent。循环直到模型不再调工具。

Q2：ToolNode 在背后做了什么？

三件事：从最后一条 AI 消息里取 tool_calls，按名字找到工具函数执行，把结果包成 ToolMessage 追加回状态。不用自己写解析、查表、执行、打包的样板代码。

Q3：模型一直调工具、循环停不下来，怎么处理？

先看提示词：有没有告诉模型“查不到就说查不到，不要反复试同一个工具”。步数上限 recursion_limit（默认 25 步）是保险丝，会拦住它，但修提示词和工具设计才是正解。

Q4：旧版 ReAct 工厂函数还能不能用？

已弃用。新版推荐手写图：StateGraph + ToolNode + tools_condition，多几行代码，但每一步都看得见、改得动，面试也能讲清。

Q5：bind_tools 不绑会怎样？

模型永远不会返回 tool_calls，图第一轮就走到 END。绑定的是工具的 schema（名字、参数、描述），模型按描述决定调哪个、传什么参数。
