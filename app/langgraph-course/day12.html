Day 12：权限与安全：检索层过滤与人工介入

权限不是界面上藏几个按钮。数据按产品隔离：负责创意的产品同学看不到其他产品的反馈。这一课讲隔离应该落在哪一层，以及敏感操作为什么要停下来等人。

一、核心解释

1. 隔离落在哪一层：检索层，不是 UI 层

只在界面上藏住别人的反馈，不叫隔离。Agent 检索时如果不过滤，回答里照样会带出别家产品的反馈。

正确做法：每条记录、每个知识片段都带 product_id。检索时先按 product_id 硬性过滤，再排序、再取片段。过滤是检索的条件，不是回答后的修饰。

2. 最小样本数：少于 5 条，只给趋势

样本太少时，逐条引用容易暴露个别反馈的细节。规则是：命中少于 5 条，只给趋势，不展开逐条原文。

这条规则也要写进检索节点里，和过滤一样是硬规则，不是提示词里的建议。

3. 审计：谁问了什么、看到了什么，要留痕

每次检索记下三件事：谁问的、按哪个 product_id 过滤的、返回了哪些片段。出了问题能查，权限验收也有据可查。

4. 敏感操作：interrupt 停住，等人拍板

写 TAPD、改知识库这类敏感操作，不要让 Agent 自己做完。跑到这一步先 interrupt 停住，等人确认后再继续。Day 13 会讲这条路怎么走。TAPD 工单这类有副作用的工具调用要防越权、误执行、重复提交，四件套是：权限上下文、人工确认、幂等键、审计记录——先确认调用者有没有权限，关键一步等人确认，同一请求带幂等键防重复提交，每次调用都留审计记录。

本项目最难的 Bug：权限隔离只做了 UI 层，检索层没过滤，Agent 回答带出了别家产品反馈。修复是记录和知识片段带 product_id、检索层硬性过滤 + 最小样本数；防再犯是权限验收回归——拿没权限的账号去问，看能不能问出别人的东西。

二、代码示例

示例 1：检索节点先过滤，再检索（先看形状）

from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver
from typing import Annotated, TypedDict

class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
    product_id: str       # 当前用户的产品，从登录身份来，不从提问里猜
    retrieved: list       # 检索到的片段

def retrieve_node(state: AgentState):
    # 关键：过滤是检索的条件，写在查询里，不是回答后才删
    hits = search_knowledge(
        query=state["messages"][-1].content,
        product_id=state["product_id"],  # 硬性过滤：只返回本产品的片段
    )
    # 审计：记下谁、按哪个 product_id、返回了哪些片段
    audit_log(state["product_id"], [h["id"] for h in hits])
    # 最小样本数：少于 5 条，只给趋势，不展开逐条原文
    if len(hits) < 5:
        return {"retrieved": [{"trend_only": True, "count": len(hits)}]}
    return {"retrieved": hits}

graph = StateGraph(AgentState)
graph.add_node("retrieve", retrieve_node)
graph.add_edge(START, "retrieve")
graph.add_edge("retrieve", END)
app = graph.compile(checkpointer=MemorySaver())

示例 2：敏感操作 interrupt，写 TAPD 前停住等人

from langgraph.graph import StateGraph, START, END
from langgraph.prebuilt import ToolNode
from langgraph.types import interrupt
from langgraph.checkpoint.memory import MemorySaver

def review_node(state: AgentState):
    # 敏感操作：进 TAPD 之前先停住，等人确认
    decision = interrupt({
        "action": "写入 TAPD",
        "demand": state["messages"][-1].content,
        "options": ["继续", "改了再继续", "拒绝"],
    })
    return {"messages": [decision]}

graph = StateGraph(AgentState)
graph.add_node("review", review_node)   # 人工审核节点
graph.add_node("tools", ToolNode([write_tapd]))  # 写 TAPD 的工具节点，按生产配置
graph.add_edge(START, "review")
graph.add_edge("review", "tools")
graph.add_edge("tools", END)
app = graph.compile(checkpointer=MemorySaver())

四、可能的面试题与答案

Q1：你们的权限隔离是怎么做的？为什么不是只做 UI 层？

数据按产品隔离：记录和知识片段都带 product_id，检索层按 product_id 硬性过滤。只做 UI 层是本项目最难的 Bug——检索层没过滤，Agent 回答带出了别家产品反馈。过滤必须发生在检索之前，不是回答之后。

Q2：最小样本数是什么意思？为什么是少于 5 条只给趋势？

样本太少时逐条引用容易暴露个别反馈的细节。规则是命中少于 5 条只给趋势，不展开逐条原文。这条规则写进检索节点，是硬规则，不是提示词里的建议。

Q3：敏感操作你们怎么管？interrupt 在哪里停？

写 TAPD、改知识库这类敏感操作，跑到这一步先 interrupt 停住，等人工确认后再继续：继续、改了再继续、拒绝三条路。Checkpoint 用 thread_id 做会话隔离，中断后同一 thread 再 invoke 从快照续跑。

Q4：这个 Bug 你是怎么发现和修复的？防再犯做了什么？

发现：Agent 回答带出了别家产品反馈，说明隔离只做了 UI 层。修复：记录和知识片段带 product_id，检索层硬性过滤 + 最小样本数。防再犯：权限验收回归——拿没权限的账号去问，看能不能问出别人的东西。

Q5：权限之外，这个项目还有哪些安全和评测抓手？

数据先清洗、脱敏、打标再进分析，脱敏在入库前；需求归纳强制绑定原文引用；知识库加版本号和更新触发器。评测抓手是需求闭环可追踪 + 人工抽查（10%–20%）+ 权限验收回归。

五、加分项

生产视角：权限上线前先问三句：过滤写在检索条件里了吗？少于 5 条只给趋势了吗？审计记下了谁、按哪个 product_id、返回了哪些片段吗？有一句答不上来，就别上。还有一句：拿没权限的账号问过吗？

简历讲法：别写“做过权限控制”，写“检索层按 product_id 硬性过滤 + 最小样本数（少于 5 条只给趋势），敏感操作 interrupt 等人工确认；修复过只做 UI 层隔离的 Bug，防再犯靠权限验收回归”。前者是名词，后者是可追问的项目。
