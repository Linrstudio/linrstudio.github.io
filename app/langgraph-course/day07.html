Day 7：子图、多 Agent 图与复盘：子图、Supervisor 图、7 天复盘与面试讲法

最后一课，把前面 6 天拼成一张大图：一个 Agent 是一张图，多个 Agent 协作就是多张图拼起来——子图是拼起来的零件，Supervisor 是拼起来的总指挥。今天先把拼法讲清，再把 7 天复盘成一个能放进简历的项目。

一、核心解释

1. 子图是什么：一张编译好的图，当成一个节点用

子图就是一张已经 compile() 好的小图，把它当成一个节点加进大图里。大图只关心：进去时状态长什么样，出来时状态变成什么样。

2. Supervisor 图：总指挥 + 三个子 Agent

一个 Supervisor 节点负责分发和收口，下面是几个子 Agent，每个都是一张子图：检索子图（RAG）、工具子图（ReAct）、校验子图（引用检查）。

3. 子图之间怎么协作：共享状态 + 显式交接

状态要共享：子图结果必须写回共享状态；交接要显式：下一步派给谁、为什么，写在状态里；失败要隔离：某一路挂了，只重试那一路。

4. 7 天复盘：一张表收束

7 天的核心一句话收束如下表，点上面的分发板可以亲手走一遍这张图的协作。

天核心面试时能讲的一句话
Day 1图是什么节点、边、状态；StateGraph 搭图纸，compile 编译后 invoke
Day 2状态与 Reducermessages 配 add_messages 追加，并行分支写状态不丢数据
Day 3条件边与路由tools_condition 分流，回边形成循环，recursion_limit 25 步兜底
Day 4工具节点与 ReActToolNode 执行工具，循环直到无工具调用，不用已弃用的旧版工厂函数
Day 5Checkpoint 与断点续跑MemorySaver 存快照，thread_id 做会话隔离，同一 thread 再 invoke 接着跑
Day 6人工介入与中断interrupt_before 停住等审核，三条路：继续、改了再继续、拒绝
Day 7子图与多 Agent 图编译好的图当节点用，Supervisor 分发收口，失败隔离只重试那一路
容易踩的坑：子图和父图的状态类型不一样。子图进去时状态长什么样、出来时变成什么样，要事先对齐；对不齐，子图读不到它要的字段，或者写回去的字段父图不认。拼图之前先对状态表。

# Supervisor 的分发就是条件边：这次分的不是节点，是子图

四、可能的面试题与答案

Q1：子图是什么？怎么用？

一张编译好的小图，当成一个节点加进大图：graph.add_node("检索子图", retrieval_subgraph)。大图只关心子图进去时状态长什么样、出来时变成什么样，子图内部的节点和边大图不用管。

Q2：Supervisor 图长什么样？

一个 Supervisor 节点负责分发和收口，下面挂几个子 Agent，每个都是一张子图：检索子图、工具子图、校验子图。Supervisor 的分发就是条件边，只不过分的不是节点，是子图。

Q3：多 Agent 图和单 Agent 图最大的区别是什么？

三条：状态要共享（子图结果写回共享状态）、交接要显式（下一步派给谁、为什么，写在状态里）、失败要隔离（某一路挂了只重试那一路，不重跑整张图）。

Q4：Checkpoint 和中断在多 Agent 图里有什么用？

Checkpoint 用 thread_id 做会话隔离，中断后同一 thread 再 invoke 从快照续跑；高危操作在 tools 节点前 interrupt_before 中断，等人工审核三条路（继续、改了再继续、拒绝）。

Q5：7 天学完，你能做出什么？还缺什么？

能做出：一张 Supervisor 多 Agent 图，带 Checkpoint 断点续跑和人工审核。还缺的是：把它接上真实业务（RAG 知识库、真实工具、评测集），这些是 LangChain 课第 3 周和第 5 周的内容，两门课合起来就是完整的项目。

五、加分项

生产视角：多 Agent 图上线前，先问三个问题：子图的状态表对齐了吗？某一路失败了只重试那一路吗？Supervisor 的分发错了能不能追溯（状态里写了为什么派给它）？三问有一个答不上来，多 Agent 图就别上。

简历讲法：别写“做过多 Agent 系统”，写“Supervisor 图：总指挥分发收口，检索、工具、校验三个子图，状态共享、交接显式、失败隔离；Checkpoint 用 thread_id 做会话隔离，高危操作 interrupt_before 中断等人工审核”。前者是名词，后者是可追问的项目。
