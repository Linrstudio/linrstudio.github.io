Day 10：检索与重排：混合检索、RRF、查询改写与重排

Day 9 我们把文档变成了向量、存进了索引。今天讲查询进来之后发生的事：怎么把最对的那几条捞出来。单路向量检索有个短板——它懂语义，却对专有名词和编号不敏感。所以生产里的检索从来不是一条路：向量路 + 关键词路多路召回，再融合、再重排，最后只把 Top-N 交给大模型。

一、核心解释

1. 向量检索 vs BM25：语义强，精确匹配弱

向量检索是把 query 和文档块 embedding 后做 Top-K 最近邻，强在语义相似度。短板是专有名词、型号、编号等精确匹配不如关键词检索。BM25 是经典的词频-逆文档频率加权排序函数，擅长精确词匹配。想象搜一个有数百万商品的向量库，query 是“阿迪达斯参考 XYZ 运动鞋白色”：向量检索返回的都是白色阿迪达斯运动鞋，却没有一个匹配确切的 XYZ 编号——这个结果用户不能接受。反过来，纯关键词检索又不懂“咋办”和“处理流程”是同一个意思。两路各有所短，所以要混合。

2. 混合检索与分数融合：先归一化，再加权

混合检索（Hybrid Search）把 BM25 分数 + 向量分数线性加权或归一化后融合，兼顾语义与字面。直接相加有个坑：两路分数的量纲和分布完全不同，向量相似度在 0.8 附近扎堆，BM25 分数可能从几到几十。正确做法是先做 min-max 归一化把两路分数都压到 0–1，再用权重 alpha 加权：alpha * 向量分 + (1 - alpha) * BM25 分。alpha 往哪边偏，取决于你的场景更怕漏语义还是更怕漏精确词——技术文档与电商场景通常要给 BM25 留足权重。

3. RRF：不看分数，看排名

RRF（Reciprocal Rank Fusion，倒数排名融合）不依赖原始分数的尺度，只融合多路检索的排名：RRF(d) = Σ 1 / (k + rank)，常取 k = 60。一个文档在某路排第 1，得 1/61；排第 10，得 1/70；多路得分相加再排序。为什么用排名而不用分数？因为各路检索的分数常常不可比——一路是相似度、一路是概率、一路干脆只有排名。RRF 更稳健，而且少调参（经典 k=60）。适用条件：当两路分数量纲一致或已可靠归一化时，加权融合直观可调；当分数不可比时，RRF 更稳。RRF 由滑铁卢大学与谷歌合作提出，作者的说法是“产生的结果比任何单个系统更好，也比标准重排方法更好”。

4. 查询改写：对齐术语，但别让 LLM 篡改实体

用户的问题常常很口语、很模糊（“咋办”），而文档是书面语（“处理流程”）——口语与文档书面语不一致会拖累向量召回。查询改写把原始问句改写成更易被检索匹配的形式，或生成多条查询变体做多路召回。策略有同义扩展、拆问句、补全主语，也可用 LLM 生成“检索友好”的 query 变体。但改写会引入噪声：LLM 可能篡改实体或添加未提及的条件。对策有四条：保留原 Query 同时检索再融合（避免改写跑偏，这是最重要的一条）、多路检索 + RRF、重排、引用校验；高敏场景优先用人工词表 + 模板，而不是 LLM 自由改写。

5. HyDE：先让 LLM 写个“假答案”，再拿它去检索

HyDE（假设文档嵌入）的思路是：让 LLM 根据用户 query 生成 k 个“假答案”（采样模式，保证 k 个不一样），再把 k 个假答案和用户 query 的向量取平均，用融合向量去召回。假答案的内容很可能有知识性错误——如果模型能答对，也就不需要召回了——但不要紧，我们只是想借 LLM 理解用户问题，生成一些“看起来还不错”的答案模式。融合向量既有用户问题的信息，也有想要答案的模式信息，能拉近查询与文档在向量空间的距离，缓解查询与文档表述风格不一致。效果上有个关键结论：对没微调过的向量化模型（zero-shot 场景），HyDE 很有用，且辅助 LLM 越大效果越好；但对微调过的向量化模型，如果用比较小的 LLM 生成假答案（小于 52B 参数量），HyDE 甚至会带来负面影响。所以 HyDE 非常依赖打辅助的 LLM 的能力。适合表述差距大、短查询难对齐长文档的场景；不适合强事实约束且模型易胡编的领域，除非加强校验与拒答。假答案可能引入错误主题，需重排与引用校验兜底。

6. Step-back：后退一步，先问背景原理

Step-back Prompting 先让模型生成一个更抽象的、后退一步的问题（背景原理），再并行检索“具体问题 + 抽象问题”，合并上下文。原理是补充背景知识，减少只抓到细枝末节的可能。和 HyDE 的异同：二者都试图拉近查询与文档的语义距离；HyDE 用假想答案文档做 embedding，更激进（易引入虚构事实）；Step-back 用更抽象的问题再检索原理/背景类段落，相对克制（仍停留在问题空间）。实践中可并行检索后由重排裁决。

7. 子问题分解：多跳问题拆开查

对多跳、多条件问题，先由 LLM 或规则拆成子问题序列，对每个子问题检索，再拼接或图式合并证据。单句 embedding 难以覆盖“先 A 再 B”的复合语义，分解后每步检索更聚焦，类似多步检索增强。典型失败模式：分解错误（实体指代错）、子问题遗漏约束、合并时矛盾未检测——需要一致性检查与重排过滤无关块。和 Agent 多步检索的区别：子问题分解可以是固定模板或一次 LLM 调用；Agentic 更强调动态决定是否再检索，工具边界更宽。

8. FLARE：生成过程中主动召回

只在生成前召回一次，在长文本生成场景下效果往往不好：生成的文本越长，越可能扩展出和 query 相关性较弱的内容，模型没有这部分知识就容易幻觉。FLARE（主动检索增强生成）的思路是随着文本生成、多次从向量库中召回。被动的多次召回（每生成固定 n 个 token 召回一次、每生成一个完整句子召回一次、按子问题召回）不能保证“不需要召回时不召回、需要时触发”，FLARE 提出了两种更主动的策略。策略 1：用 prompt + 示例让模型在需要查知识时按格式输出主动召回标识 [Search("模型自动提出的问题")]，用模型生成的问题去召回，召回后把答案放进 prompt、去掉标识继续生成。缺陷是 LLM 不愿意生成标识（解决办法：对“[”对应的 logit 乘 2）、过于频繁的召回影响生成质量（刚召回后几个 token 内禁止生成“[”）、不微调很难靠 few-shot 让模型稳定输出这种模式。策略 2：基于 token 生成概率做置信度判断——每生成 64 个 token，用工具找到第一个完整句子当作“假答案”，如果其中任意 token 的概率低于阈值，就触发召回；低概率 token 很可能含错误信息，处理办法是丢掉低概率 token 再召回，或让大模型对置信度低的内容提问、用生成的问题去召回。注意策略 2 需要拿到每个 token 的生成概率，传统的 ChatGPT 接口是用不了的。

9. RAG-Fusion：多查询 + RRF，弥合“问的”和“想问的”

RAG-Fusion 解决的是 RAG 的固有限制：单一查询可能无法完全捕捉用户感兴趣的全部范围，或者过于狭窄。工作流程是：用提示工程让 LLM 基于原始查询生成多个不同视角的查询（比如原始查询是“气候变化的影响”，生成的查询包括“气候变化的经济后果”“气候变化与公共健康”），每个查询各做一路检索，再用 RRF 融合多路排名，最后把重排后的文档和所有查询一起交给 LLM 生成答案。多查询的一个挑战是可能稀释用户的原始意图，缓解办法是在提示中指示模型更重视原始查询，保留原始查询作为防止误解的保障。优势是源材料更优质、更能捕捉用户意图、能处理复杂查询、甚至能自动纠正用户查询的拼写语法；挑战是输出可能过于冗长、多查询输入会挤压上下文窗口、以及操作用户查询带来的用户自主性与透明度问题——用户应当意识到自己的查询被调整了。

10. 重排：召回几十到几百，精排只留 Top-N

向量检索（Bi-Encoder）为速度对 query 和 doc 独立编码，交互信息不足；Cross-Encoder 把 query 与 doc 拼在一起打分，精度更高但慢，所以只能放在 Top-K 之后做小范围重排。标准流程：召回 Top-K（几十到几百）→ Cross-Encoder 精排取 Top-N（3–10）→ 再生成，平衡延迟与效果。为什么需要这一步？因为召回的前 K 个结果不一定按最相关的方式排序——最相关的块可能是第 5 或第 7 个，而不是第 1 或第 2 个。常用重排模型：Cohere Rerank API、BGE Reranker（如 bge-reranker-large，开源可本地部署）。还有个细节叫 LostInTheMiddle：大模型对上下文中间部分注意力较弱，所以有方案把最相关的文档重新定位到提示的开始和结束边缘。模型名以官方最新文档为准。

11. MMR：相关性与多样性的权衡

Top-K 经常几乎重复——五条都是同一段话的变体。MMR（最大边际相关性）在相关性与多样性间权衡：迭代选择与 query 相关、但与已选集合冗余度低的文档。公式：MMR = argmax_d [λ · sim(q,d) − (1−λ) · maxs∈S sim(d,s)]，其中 S 是已选集合。λ 大偏相关，λ 小偏多样。λ=1 时退化为纯相关性排序；λ 往小调，选出来的文档覆盖面更广，但个别条目可能没那么相关。MMR 是贪心算法：每一步都选当前 MMR 得分最高的候选，选满 Top-K 为止。

容易踩的坑：召回率低先别急着换模型、调参数，按这个顺序排查：知识库里有没有对应答案（没有就是覆盖问题）；有但没召回——是知识被切分切碎了（改切分方式），还是 query 和 doc 的特点没对上（字相关还是语义相关）？一个实用建议是先用关键词检索做召回，再用模型做精排。索引数据的质量决定答案质量：垃圾输入，垃圾输出——摄取前先清理特殊字符、奇怪编码、多余 HTML 标签，去重、删无关文档。

二、代码示例

示例 1：RRF 多路排名融合 + 混合检索分数融合（纯 Python，可直接跑）

from typing import Dict, List, Sequence

def rrf_fuse(ranked_lists: Sequence[Sequence[str]], k: int = 60) -> List[tuple]:
    """ranked_lists: 多路检索结果，每路为 doc_id 从优到劣的列表。"""
    scores: Dict[str, float] = {}
    for ranks in ranked_lists:
        for rank, doc_id in enumerate(ranks, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)

vec_ids = ["d3", "d1", "d2"]    # 向量路 Top-3
bm25_ids = ["d1", "d4", "d3"]  # BM25 路 Top-3
print(rrf_fuse([vec_ids, bm25_ids]))
# d1 两路都靠前，得分最高；d3 次之；d2、d4 只出现在一路

# 混合检索分数融合：先 min-max 归一化，再 alpha 加权
def min_max_norm(scores):
    s_min, s_max = min(scores), max(scores)
    if s_max == s_min:
        return [1.0 for _ in scores]
    return [(s - s_min) / (s_max - s_min) for s in scores]

def hybrid_fuse(vec_scores, bm25_scores, alpha=0.5):
    v = min_max_norm(vec_scores)
    b = min_max_norm(bm25_scores)
    return [alpha * vi + (1 - alpha) * bi for vi, bi in zip(v, b)]

print(hybrid_fuse([0.87, 0.83, 0.81], [12.5, 3.1, 9.8], alpha=0.5))

示例 2：MMR 贪心选择 + Cross-Encoder 重排

# pip install numpy sentence-transformers
import numpy as np

def mmr_select(query_vec, doc_vecs, top_k, lambda_mult=0.5):
    """doc_vecs: shape (n, dim)，已归一化；lambda 大偏相关，小偏多样。"""
    sim_to_q = doc_vecs @ query_vec
    selected: list[int] = []
    candidates = set(range(len(doc_vecs)))
    while len(selected) < top_k and candidates:
        best_idx, best_score = None, -1e9
        for i in candidates:
            redundant = 0.0
            if selected:
                redundant = max(float(doc_vecs[i] @ doc_vecs[j]) for j in selected)
            score = lambda_mult * sim_to_q[i] - (1 - lambda_mult) * redundant
            if score > best_score:
                best_score, best_idx = score, i
        selected.append(best_idx)
        candidates.remove(best_idx)
    return selected

# 玩具数据：5 条文档向量，第 1、2 条几乎重复
rng = np.random.default_rng(0)
vecs = rng.normal(size=(5, 8))
vecs[1] = vecs[0] + 0.01  # 故意造一对重复文档
vecs = vecs / np.linalg.norm(vecs, axis=1, keepdims=True)
q = rng.normal(size=8)
q = q / np.linalg.norm(q)
print("lambda=0.9（偏相关）:", mmr_select(q, vecs, top_k=3, lambda_mult=0.9))
print("lambda=0.3（偏多样）:", mmr_select(q, vecs, top_k=3, lambda_mult=0.3))

四、可能的面试题与答案

Q1：为什么混合检索比单路向量更有效？

向量捕获语义，但可能漏掉专有名词与编号；BM25 补精确匹配。二者融合提高鲁棒性，尤其在技术文档与电商场景。比如搜“阿迪达斯参考 XYZ 运动鞋白色”，向量路返回的都是白色阿迪达斯运动鞋，却没有一个匹配确切的 XYZ 编号。

Q2：RRF 与加权分数融合各适合什么？

当两路分数量纲一致或已可靠归一化时，加权融合直观可调；当一路是排名、一路是概率、或分数不可比时，RRF 更稳，且少调参（经典 k=60）。RRF 不依赖原始分数尺度，只融合排名。

Q3：HyDE 适合什么场景？不适合什么？

适合表述差距大、短查询难对齐长文档的场景；不适合强事实约束且模型易胡编的领域，除非加强校验与拒答。还有个关键结论：对没微调过的向量化模型（zero-shot），HyDE 很有用；对微调过的向量化模型，如果用比较小的 LLM（小于 52B 参数量）生成假答案，HyDE 甚至会带来负面影响——它非常依赖打辅助的 LLM 的能力。

Q4：Step-back Prompting 与 HyDE 有何异同？

二者都试图拉近查询与文档的语义距离。HyDE 用假想答案文档做 embedding，更激进（易引入虚构事实）；Step-back 用更抽象的问题再检索原理/背景类段落，相对克制（仍停留在问题空间）。实践中可并行检索后由重排裁决。

Q5：MMR 是干嘛的？λ 怎么调？

MMR（最大边际相关性）在相关性与多样性间权衡，避免 Top-K 几乎重复的段落。公式：MMR = argmax_d [λ · sim(q,d) − (1−λ) · max sim(d,s)]，S 是已选集合。λ 大偏相关，小偏多样；λ=1 时退化为纯相关性排序。实现是贪心算法，每步选当前 MMR 得分最高的候选。

生产视角：召回率低先按顺序排查：知识库里有没有答案 → 有没有被切分切碎 → query 和 doc 是字相关还是语义相关，别一上来就换模型。索引数据质量决定答案质量，摄取前先清理、去重、删无关文档；查询改写上线前务必保留原 Query 同时检索，高敏场景用人工词表 + 模板。
