Day 15：记忆系统：短期、长期、三因子检索与高级框架

没有记忆的 Agent 像金鱼：每次请求都像第一次见面，用户说过“不要用 Python”，三轮之后它就忘了。今天讲记忆系统——Agent 如何存储、组织、检索、更新信息：短期记忆管“当下这轮对话”，长期记忆管“跨会话的偏好与事实”，摘要负责压缩，三因子检索负责“下一轮该想起什么”，最后看高级框架与生产里的坑。

一、核心解释

1. 记忆是什么：与 RAG 的关系

记忆是 Agent 跨请求持久或半持久的状态：存储、组织、检索、更新信息的一整套机制。单次请求的 prompt 是瞬时输入，记忆是可以被策略性地注入 prompt、工具参数或规划模块的状态。没有记忆，Agent 只能做“无状态函数调用”：多轮对话前后矛盾、长任务断链、偏好每次重问。

记忆和 RAG 是什么关系？长期记忆常与向量检索结合，但 RAG 只是长期记忆的一种实现路径。完整的记忆系统还强调四样 RAG 不管的东西：时间线（这条记忆是什么时候的）、重要性（哪条更值得留）、用户维度（这是谁的记忆）、写入策略（什么值得存、什么该忘）。面试时被问“用 RAG 算不算记忆”，就按这个口径答。

人类记忆的类比能帮你划分模块职责：感觉记忆（极短、未加工）对应原始输入缓存；短期记忆（容量小、可主动操作）对应对话上下文与 ReAct 轨迹里的 scratchpad；长期记忆（持久、需巩固）对应向量库、用户画像表、知识图谱、会话摘要归档。类比不能硬套——计算机没有神经可塑性，“巩固、遗忘、冲突解决”都要工程上显式实现。

2. 短期记忆：窗口与 Token 预算

短期记忆是当前会话内模型能直接“看到”的信息，受 Token 上限与延迟约束。两种基本做法：Conversation Buffer（多轮消息按时间顺序全量拼接，保真度高，但越长越贵、越慢、越易注意力分散）；滑动窗口（只保留最近 k 轮或最近 n 个 Token，成本可控，但可能丢掉写在很前面的关键约束，比如“不要用 Python”）。取舍的关键是：任务是否强依赖“很久以前的一条约束”——是的话，纯窗口必须配合摘要或长期记忆检索，也可以先“关键句提取”把硬约束抽进画像，再对对话做窗口截断。

Token 预算分配建议顺序：system 指令 > 安全/策略 > 工具定义（若必须）> 高优先级记忆（用户偏好/任务状态）> 近期对话 > 其他，并预留 10%～20% 给模型输出与格式冗余。长工具返回要压缩、引用 ID、存外部，而不是全文塞入。工具 schema 特别长时：工具分层（核心工具常驻 + 动态加载）、摘要版 schema、或工具路由先选子集再展开。还要记住长上下文的“中间遗忘”现象：模型对长上下文中间部分的关注会变弱。

3. 长期记忆：向量库 + 元数据

长期记忆用于跨会话保留信息，典型实现是“向量数据库 + 元数据”：记忆文本向量化，同时存 user_id、timestamp、type、source 等元数据；检索时查询向量找 Top-K，再按用户隔离、时间范围、类型过滤，注入 prompt。

CRUD：存——批量 embedding 写入；检——相似度 + 过滤 + 可选重排；更——常见是“删旧插新”或版本字段，纯向量库若无主键管理需要业务层 ID；删——按用户注销、过期策略、显式“忘记”指令执行硬删除或 tombstone。重要性评分来源有三：规则（关键词加权）、模型打分（LLM 输出 1～10 重要性，需 JSON 约束与校验）、用户反馈（点赞/纠正）。

衰减机制：越久未使用、越低相关的记忆应降权或归档。时间衰减常用指数形式 exp(−λΔt)（λ 越大遗忘越快），配合访问强化（被召回则提升最近访问时间权重）与睡眠巩固（离线任务把零散记忆合并成更高层摘要）。衰减会不会误删重要但很久不用的信息？会。缓解办法：分离冷存储与热索引，对高重要/用户固定的记忆降低衰减速度，支持用户“钉住”偏好；强合规场景衰减更偏归档而非物理删除，并保留审计日志与用户导出/删除能力。

4. 会话摘要与压缩：增量在线 + 定期全量校准

对话变长后成本高、延迟高、模型更容易漏看中间约束。摘要把信息搬到更短载体，配合长期记忆检索，实现“短上下文 + 广记忆”。只用向量检索不做摘要可以吗？可以，但你会失去低成本的全局叙事（任务阶段、未决事项）：摘要擅长提供“主线”，向量擅长提供“细节证据”，最佳实践是两者并存。

类型做法优点缺点
增量摘要新消息来了，把“旧摘要 + 新片段”再摘要省算力与成本可能误差累积、早期细节被吞
全量摘要定期对完整对话重摘要更一致成本高、对话极长时仍可能触顶

工程上常见：增量在线 + 定期全量校准。缓解误差累积还有三招：摘要中保留关键事实清单（姓名、日期、硬约束）；对摘要做一致性检查（另一个小模型挑错）；让用户可编辑“长期事实”。分层策略是：硬约束进结构化槽位，软偏好进摘要，细节进向量库按需检索。

旧写法已废弃：源材料里的 ConversationSummaryMemory 在新版 LangChain 中已 deprecated，不要在新代码里用。现代写法是 MessagesPlaceholder + 显式 summarize 链（自己控制何时触发摘要、摘要模板长什么样），或迁移到 LangGraph 状态里的 summary 字段。面试时这样说，说明你跟得上版本变化。

5. 情景记忆 vs 语义记忆

情景记忆（Episodic）是具体事件：时间、地点、参与者、发生了什么，例如“昨天下午用户让我把报表改成 PDF”。语义记忆（Semantic）是一般性知识：概念、事实、规则，例如“公司退货政策是 7 天”。多条情景可抽象成语义（归纳），语义在具体任务中落地为情景（实例化）。

为什么要区分存储？因为更新频率、隐私级别、检索特征不同：情景更个人化、更时间敏感；语义更共享、更稳定。区分后可做不同保留策略（情景更易过期）、不同权限（情景的用户隔离更严格），并减少把“一次性事件”误当“长期规则”。实现上是分表模型：EpisodicRecord(ts, actors, text, embedding_id) vs SemanticFact(key, value, source, confidence)；检索时情景偏时间邻近 + 事件相似，语义偏概念相似 + 权威来源；意图路由上，“上次”“刚才”这类问法走情景库，其余走语义库。

6. 检索策略：三路召回 + 三因子公式

检索策略决定“下一轮生成之前，从记忆池里取什么”。单一策略往往不够，典型 pipeline 是：三路召回（时间 / 向量 / 关键词）→ 去重 → 重排 → Token 截断注入。去重可用语义去重（相似度阈值）或 canonical key（实体对齐），但要防误删相似但不同的约束——用阈值 + 冲突检测，矛盾时触发二次 LLM 仲裁。只做强相关性检索会漏掉仍然有效但表述不相似的硬约束，也会过度偏向“像”但错误的片段，需要时间与重要性补足。

斯坦福 Generative Agents 论文提出的三因子思想是面试高频点：检索时综合相关性（relevance）、近期性（recency）、重要性（importance），每项归一化后加权：

score(m | q) = w_rel·相关性 + w_rec·近期性 + w_imp·重要性

相关性是查询与记忆的向量相似度映射到 [0,1]；近期性随距离上次发生/访问时间增大而下降（常用指数衰减）；重要性由模型或规则给出并归一化。权重需调参，也可用乘法形式强调“必须同时满足”；三路召回的融合可用 RRF（倒数排名融合）或统一打分后线性加权 / Learning to Rank，线上要 AB 测试权重。

7. 高级框架：MemGPT、MemOS、Mem0 与记忆图谱

当对话与工具轨迹变复杂，会出现“上下文装不下、长期记忆难组织”的问题，业界提出了更接近操作系统的记忆架构。MemGPT 把 LLM 上下文当作“有限 RAM”，把外部存储当作“磁盘”，通过分页/换入换出与事件驱动控制信息进出上下文：上下文将满时，控制逻辑决定把哪些内容外溢到外部归档，需要时再加载回来。这与“每次提问都做一次相似度检索”的被动 RAG 不同，更强调对记忆载体的主动管理——这也是它和简单 RAG 的本质区别。MemOS 是“记忆操作系统”式架构：把记忆拆成多层（瞬时上下文、会话工作区、用户级长期存储、共享知识），由调度器决定读写路径与配额，与 MemGPT 同属“分层 + 调度”一脉。Mem0 是面向应用的记忆层中间件：把“从对话中抽取可复用记忆 → 更新 → 检索”做成可集成组件，常与向量检索、图结构、用户画像组合使用；它管抽取与存储管线，MemGPT 管上下文与外存之间的搬运策略，两者可互补。

另外两个方向：反思与整合——周期性让模型回顾轨迹生成更高层见解（反思），把多条低层记录合并成稳定条目（整合），减少冗余与冲突；记忆图谱——实体—关系—实体存储，检索用图遍历 + 向量，强在多跳推理与结构化关系，弱在构建成本高、实体对齐难，对非结构化闲聊未必划算。

8. 生产挑战：隔离、一致性、隐私与重嵌入

从 Demo 到生产，记忆系统要面对多租户、持久化、并发一致性、隐私合规、性能与成本。多租户隔离是硬性要求：user_id / tenant_id 过滤必须贯穿写入与检索，向量库元数据过滤要默认开启——最常见的生产事故就是检索忘记加租户条件导致串数据。一致性：摘要与向量库条目冲突、重复记忆、旧偏好未删除，靠主键、版本号、合并策略、定期对账任务缓解；写路径上先写业务主库拿 memory_id，再异步写向量，失败重试 + 对账比对条目数与哈希。隐私与安全：只存必要字段，敏感信息加密或 token 化，支持删除（被遗忘权）；检索到的记忆可能含恶意内容，需要清洗与信任分级，还要红队测试诱导模型保存恶意指令。Embedding 模型升级后旧向量与新向量不在同一空间、不可混比，做法是双写期（新旧模型并行写）、离线全量重嵌入、检索时标明 embedding_model_version，查询与库版本一致。

容易踩的坑：长期记忆用向量库很方便，但“相似 ≠ 正确”：它会召回到表面相近的噪声，账号、订单号这类精确匹配更适合关键字/关系库。生产里长期记忆的标准姿势是混合检索（BM25 + 向量）+ 重排，而不是纯向量检索。

二、代码示例

示例 1：滑动窗口 + Token 预算（短期记忆）

from dataclasses import dataclass
from typing import List, Dict, Literal
import tiktoken

Role = Literal["system", "user", "assistant"]

@dataclass
class ChatMessage:
    role: Role
    content: str

class WindowedConversationMemory:
    """滑动窗口 + Token 预算：先限条数，再按预算从尾部保留。"""

    def __init__(self, model: str = "gpt-4o", max_tokens: int = 3000,
                 window_messages: int = 20):
        self.max_tokens = max_tokens
        self.window_messages = window_messages
        self.enc = tiktoken.encoding_for_model(model)
        self.messages: List[ChatMessage] = []

    def add(self, role: Role, content: str) -> None:
        self.messages.append(ChatMessage(role=role, content=content))
        if len(self.messages) > self.window_messages:
            self.messages = self.messages[-self.window_messages:]
        self._shrink_to_budget()

    def _count_tokens(self, messages: List[ChatMessage]) -> int:
        text = "\n".join(f"{m.role}: {m.content}" for m in messages)
        return len(self.enc.encode(text))

    def _shrink_to_budget(self) -> None:
        while self.messages and self._count_tokens(self.messages) > self.max_tokens:
            self.messages.pop(0)  # 丢最早一条；生产可优先丢大 tool payload

    def as_openai_messages(self) -> List[Dict[str, str]]:
        return [{"role": m.role, "content": m.content} for m in self.messages]


mem = WindowedConversationMemory(max_tokens=256)
mem.add("system", "你是助手，回答尽量简洁。")
mem.add("user", "我叫阿明。")
mem.add("assistant", "好的，阿明。")
print(mem.as_openai_messages())
print("tokens ~=", mem._count_tokens(mem.messages))

注：示例中的模型名（如 gpt-4o）保留源材料原意，实际使用以官方最新文档为准。

示例 2：长期记忆 + 三因子检索（向量 + 元数据 + 衰减）

import hashlib
import math
import time
from dataclasses import dataclass
from typing import Dict, List

def fake_embed(text: str, dim: int = 8) -> List[float]:
    """演示用确定性伪向量；真实项目请调用 embedding 模型。"""
    h = hashlib.sha256(text.encode("utf-8")).digest()
    vec = [((h[i % len(h)] + i) % 97) / 97.0 for i in range(dim)]
    norm = math.sqrt(sum(x * x for x in vec)) or 1.0
    return [x / norm for x in vec]

def cosine_sim(a: List[float], b: List[float]) -> float:
    return sum(x * y for x, y in zip(a, b))

@dataclass
class MemoryItem:
    id: str
    user_id: str
    text: str
    vector: List[float]
    importance: float  # 0~1
    last_accessed: float

class LongTermMemoryStore:
    """长期记忆：向量 + 元数据 + 三因子检索。"""

    def __init__(self, decay_lambda: float = 2e-7):
        self.decay_lambda = decay_lambda
        self.items: Dict[str, MemoryItem] = {}

    def add(self, user_id: str, text: str, importance: float = 0.5) -> str:
        mem_id = hashlib.md5(f"{user_id}:{text}:{time.time()}".encode()).hexdigest()[:12]
        now = time.time()
        self.items[mem_id] = MemoryItem(mem_id, user_id, text,
                                        fake_embed(text), importance, now)
        return mem_id

    def delete(self, mem_id: str) -> None:
        self.items.pop(mem_id, None)  # 被遗忘权：显式删除入口

    def search(self, user_id: str, query: str, top_k: int = 5):
        q = fake_embed(query)
        now = time.time()
        scored = []
        for it in self.items.values():
            if it.user_id != user_id:
                continue  # 租户隔离：检索必须带 user_id 过滤
            rel = cosine_sim(q, it.vector)
            age = max(0.0, now - it.last_accessed)
            recency = math.exp(-self.decay_lambda * age)  # exp(-λΔt)
            score = 0.6 * rel + 0.2 * it.importance + 0.2 * recency
            scored.append((score, it))
        scored.sort(key=lambda x: x[0], reverse=True)
        return scored[:top_k]


store = LongTermMemoryStore()
store.add("u1", "用户偏好：沟通风格简洁，禁用表情。", importance=0.9)
store.add("u1", "用户在做电商客服项目。", importance=0.6)
for s, it in store.search("u1", "他喜欢怎么说话？"):
    print(round(s, 4), it.text)

四、可能的面试题与答案

Q1：为什么 Agent 需要记忆？没有行不行？

需要，四个原因：多轮一致性（避免重复追问、前后矛盾）、长任务（工具调用链与子目标状态需要延续）、个性化（偏好、禁忌、领域术语）、成本（不必每次把全量背景塞进 prompt，可通过摘要与检索按需加载）。简单 FAQ 或单次工具调用可能够用，但在助理、客服、编程 Agent、游戏 NPC 等场景，没有记忆明显不可用。

Q2：Conversation Buffer 和 Window Buffer 的区别与取舍？

Buffer 强调完整保留（直到触顶），Window 强调只保留尾部。取舍在于任务是否强依赖“很久以前的一条约束”：纯 Window 会丢信息，需要配合摘要或长期记忆检索。也可以补充“关键句提取 + Window”：先抽取硬约束进画像，再对对话做窗口截断。

Q3：长期记忆为什么常用向量数据库？有什么局限？

常用是因为语义检索能处理“换说法”的匹配。局限：相似 ≠ 正确（会召回到表面相近的噪声）、难精确匹配（账号、订单号更适合关键字/关系库）、更新一致性需业务层保障。生产里标准姿势是混合检索（BM25 + 向量）+ 重排。

Q4：增量摘要误差累积怎么缓解？

四招：定期全量重摘要；摘要中保留关键事实清单（姓名、日期、硬约束）；对摘要做一致性检查（另一个小模型挑错）；让用户可编辑“长期事实”。工程上就是“增量在线 + 定期全量校准”。

Q5：Embedding 模型升级后旧向量怎么办？

旧向量与新向量不在同一空间，不可混比。做法：双写期（新旧模型并行写）、离线全量重嵌入、检索时标明 embedding_model_version，查询与库版本一致。

五、加分项

生产视角：记忆系统最容易出的事故是租户隔离失败和敏感数据未加密写入长期记忆。防护清单：强制租户过滤的集成测试、检索审计日志、敏感字段检测、PII 脱敏、最小权限访问向量库；Embedding 升级一定留双写期，不要直接全量切新模型。

简历讲法：别写“做过 Agent 记忆系统”，写“给客服 Agent 做记忆分层：短期用滑动窗口 + Token 预算（system > 安全 > 工具 > 高优先级记忆 > 近期对话，预留 15% 输出），长期用向量库 + 元数据 + 三因子检索（相关性/近期性/重要性），摘要用增量在线 + 定期全量校准，检索强制 user_id 过滤防串租户”。每一句都可追问。
