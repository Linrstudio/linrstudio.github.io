Day 3：反思与搜索：Reflexion、LATS、自一致性

Day 2 的 ReAct 和 Plan-and-Execute 解决的是“怎么做”，今天解决的是“做错了怎么办、哪条路更好”。ReAct 一条路走到黑容易掉进局部最优，Plan-and-Execute 的计划错了会污染全局。三种补强手段各管一摊：Reflexion 让 Agent 做完复盘、带着教训重试；LATS 让 Agent 在决策树上多路探索再选最优；自一致性让模型多答几遍、少数服从多数。共同点是：都用额外计算换可靠性。

一、核心解释

1. Reflexion：三角色分工与语言化反思复用

Reflexion 的核心是：做完不等于结束——还要评估做得好不好，把教训记下来，下次带着教训重试。像考试做错后写错题本，而不是盲目刷同一道题。它强调语言化反思（自然语言反思条目），而不是只改参数；反思作为记忆，影响后续尝试的策略。典型角色分工（概念上）：Actor 生成行动/答案（可接工具）；Evaluator 给反馈（对/错、评分、缺失项），来源可以是规则、更强模型、单元测试、外部工具验证，因任务而异；Reflector 根据反馈写反思文本，指出错误原因与改进策略。反思不是泛泛的“我要更仔细”，而是可执行的指导，例如“应先确认单位换算”“应先检索最新数据而非凭记忆”。

反思记忆的存储与使用：短期是同一任务多轮尝试中维护 reflections: List[str]；长期可写入向量库/键值库，按任务类型检索相似反思（进阶）。使用方式是每轮把反思拼进提示：任务 + “Past reflections” + 反思列表，Actor 在此基础上生成新输出，Evaluator 评分，Reflector 追加新反思，循环直到成功或达到最大尝试次数。和“让模型自己检查一遍”的区别是：自检往往是一次性的；Reflexion 把评估与反思显式化、结构化，并跨尝试复用反思文本，形成可累积的“策略记忆”，工程上更易控制与评测。适用场景是可验证任务（代码、数学、有测试用例的生成）、易犯系统性错误的任务（格式、约束、工具选择），以及预算允许多轮尝试的场景——反思会增加调用次数。反思太冗长时要限制条数与长度，合并相似反思，只保留高信息密度条目。

2. LATS：树搜索 + MCTS，把决策当树来搜

LATS（Language Agent Tree Search）把 Agent 的决策看成在树上搜索：每个节点是一种“状态/中间思路”，分支是不同行动。任务复杂、存在多条可能路径时，与其一次走到底，不如探索多条路，用评估函数判断哪条路更有希望。它常与蒙特卡洛树搜索（MCTS）思想结合：通过选择—扩展—模拟—回传，在探索与利用之间折中，把“语言推理”嵌进搜索节点。节点包含当前上下文、已执行动作历史、可选下一步；边是一次 Thought/Action 或一个子目标步骤；叶节点评估是否完成任务、奖励分数、是否需继续扩展。

MCTS 四步（面试版描述）：① Select（选择）：从根沿策略选到叶（UCB 等平衡探索/利用）；② Expand（扩展）：生成若干可能的下一步（语言分支），在 LATS 中常由 LLM 生成多个候选行动；③ Simulate / Rollout（模拟）：用启发式或模型快速评估结果潜力，可用更便宜模型或短 rollouts；④ Backpropagate（回传）：把评估回报回传到路径上的节点统计量。相比单次 ReAct，LATS 的成本主要来自多分支扩展与多次评估/模拟，换来的是更系统的探索，降低“一条路径走到黑”的局部最优风险，适合决策点多的任务，如策略游戏、规划 puzzle、代码修复（多方案补丁）、需要先提出多种假设再验证的研究型问题。和束搜索（Beam Search）的区别：Beam 偏序列生成；LATS / MCTS 更强调节点价值估计与探索策略（UCB）。工程难点是分支爆炸、评估器设计、延迟控制，需要强剪枝与缓存。

3. Self-Consistency：多条推理路径投票

Self-Consistency 对同一问题采样多条推理路径（不同温度或多候选），对最终答案做投票或一致性检查，选多数派或最可信路径。原理是用计算换可靠性：单条推理链可能在某一步走偏，多条链各自独立推理后投票，能把偶然错误稀释掉。工程实现上，对同一输入调用模型 N 次（temperature 大于 0），解析每次的 JSON 答案字段，对类别做多数投票；若平票，取平均 confidence 较高者或触发人工审核。它适合答案空间有限的任务（选择题、结构化结论、分类），对开放写作类“无唯一正确答案”的任务投票意义较小。Self-Consistency 与 CoT 经常结合：先用 CoT 生成多条推理链，再投票。

4. Self-Reflection 与 Self-Critique 模板，以及成本权衡

Self-Reflection 让模型在初稿之后再生成一轮：检查错误、遗漏、与约束的一致性，并输出修订版或自检清单。相当于同一上下文内的二次采样，但角色从“生成者”切到“评审者”，对部分任务能降幻觉、补约束。双阶段模板：第一轮根据材料写答案；第二轮不要重复第一轮全文，仅输出“第一轮可能存在的问题（最多 3 条）”与“修订后的最终答案（若无需修订则说明‘保持原答案’）”。Self-Critique 更进一步，显式要求模型指出初版答案的问题列表（事实、逻辑、格式），再据此改写。模板结构是：材料 + 初版答案 + 任务（你是严格审稿人，只做两件事：列出可能存在的问题，最多 5 条，若没有明显问题写“未发现明显问题”；给出修订后的答案，若初版已足够好则原样重复并注明“维持不变”），输出两段，标题分别为“问题清单”“修订答案”。

成本权衡是这课的收尾考点。Self-Reflection 通常增加约一倍或更高的延迟与 Token；对高风险、高价值输出（医疗、法律、财务摘要）或格式极易错的场景值得，对低价值闲聊往往不值得。Reflexion 增加的是“尝试次数 × 每轮调用”，LATS 增加的是“分支数 × 评估次数”，Self-Consistency 增加的是“采样次数 N”。三者都是用计算换可靠性，选型时先问：这个任务的错误代价，值不值得付这份计算账单？Re-planning 与 Reflexion 都“改正错误”，区别是：Re-planning 偏计划结构的调整（下一步怎么走），Reflexion 偏策略/经验的语言化总结并跨轮复用。

容易踩的坑：反思写得越长不等于越好。泛泛的“我要更仔细”对下一轮毫无帮助，反思必须可执行（“先确认单位换算”）。同时要限制反思条数与长度、合并相似反思，否则反思记忆会变成上下文里的噪声，反而拖垮下一轮。

二、代码示例

示例 1：Reflexion 循环（离线可跑：Actor 第一次算错，带着反思第二次算对）

def reflexion_loop(task, actor, evaluator, reflector, max_trials=3):
    """Act → Eval → Reflect → Retry：反思作为记忆进入下一轮提示。"""
    reflections: list[str] = []
    out = ""
    for _ in range(max_trials):
        mem = "\n".join(f"- {r}" for r in reflections) or "(none)"
        out = actor(f"Task: {task}\nReflections:\n{mem}\n")
        score, feedback = evaluator(out)  # 例如 (0.0~1.0, str)
        if score >= 0.9:
            return out
        r = reflector(f"Output:\n{out}\nFeedback:\n{feedback}\nWrite concise lessons.")
        reflections.append(r)
    return out


def fake_actor(prompt):
    """假 Actor：没反思时算错（漏了单位换算），有反思时算对。"""
    if "单位换算" in prompt:
        return "3 公里 = 3000 米，3000 米 ÷ 50 米/圈 = 60 圈"
    return "3 ÷ 50 = 0.06 圈"


def fake_evaluator(out):
    return (1.0, "正确") if "60 圈" in out else (0.0, "单位错误：公里与米混用")


def fake_reflector(prompt):
    return "应先确认单位换算：公里转米再计算，不要直接拿公里除以米。"


print(reflexion_loop("3 公里跑道，每圈 50 米，一共多少圈？",
                     fake_actor, fake_evaluator, fake_reflector))
# 3 公里 = 3000 米，3000 米 ÷ 50 米/圈 = 60 圈

示例 2：Self-Consistency 多数投票（离线可跑，假模型采样 5 次取多数）

from collections import Counter


def self_consistency(question, llm, n=5):
    """同一问题采样 N 条推理路径，对最终答案做多数投票。"""
    answers = []
    for _ in range(n):
        out = llm(question)  # 真实场景：temperature > 0，多次调用
        answer = out.split("最终答案：", 1)[1].strip()
        answers.append(answer)
    winner, votes = Counter(answers).most_common(1)[0]
    return winner, votes, answers


# 假模型：5 次采样里 4 次答对、1 次走偏，投票纠回正确结果
_samples = iter(["最终答案：60 圈", "最终答案：0.06 圈",
                 "最终答案：60 圈", "最终答案：60 圈", "最终答案：60 圈"])


def fake_llm(question):
    return next(_samples)


winner, votes, all_answers = self_consistency("3 公里跑道每圈 50 米，多少圈？", fake_llm, n=5)
print(f"投票结果：{winner}（{votes}/5 票），全部采样：{all_answers}")
# 投票结果：60 圈（4/5 票），全部采样：['60 圈', '0.06 圈', '60 圈', '60 圈', '60 圈']

2. 改写 fake_reflector，让它返回一句泛泛的反思（如“我要更仔细”），再把 fake_actor 的判断条件改成只认这句泛泛反思——观察：泛泛反思对纠错毫无帮助，反思必须可执行。
3. 把示例 2 的采样改成 2 对 2 平票（再加 1 次走偏采样，n=6），想想工程上平票时该怎么办：取平均 confidence 较高者，还是触发人工审核？把你的选择写成一行注释。

四、可能的面试题与答案

Q1：Reflexion 和“让模型自己检查一遍”有什么不同？

自检往往是一次性的；Reflexion 把评估与反思显式化、结构化，并跨尝试复用反思文本，形成可累积的“策略记忆”。工程上更易控制与评测：反思条数、长度、复用方式都可以度量和调参。

Q2：LATS 与 ReAct 在“探索能力”上如何对比？

ReAct 通常主路径贪心推进；LATS / MCTS 通过多分支搜索与价值回传更系统探索决策空间（成本更高）。ReAct 适合路径相对明确的任务，LATS 适合决策点多、存在多条可能路径的复杂任务。

Q3：Self-Reflection 会增加多少成本？值得吗？

通常增加约一倍或更高的延迟与 Token；对高风险、高价值输出（医疗、法律、财务摘要）或格式极易错的场景值得；对低价值闲聊往往不值得。选型时先问错误代价是否值得付这份计算账单。

Q4：LATS 和束搜索（Beam Search）有什么区别？

Beam 偏序列生成；LATS / MCTS 更强调节点价值估计与探索策略（UCB）。LATS 的节点是“状态/中间思路”，边是一次 Thought / Action，评估回报会回传到路径上的节点统计量。

Q5：Reflexion 的 Evaluator 从哪来？反思太冗长怎么办？

Evaluator 来源因任务而异：规则、更强模型、单元测试、外部工具验证。反思冗长时限制条数与长度，合并相似反思，只保留高信息密度条目；反思必须可执行，泛泛的“我要更仔细”对下一轮毫无帮助。

五、加分项

生产视角：反思与搜索都是“用计算换可靠性”，上线前先算账：Reflexion 的账单是尝试次数 × 每轮调用，LATS 是分支数 × 评估次数，Self-Consistency 是采样次数 N。先给每种机制设硬预算（最大尝试次数、分支上限、采样数），再谈收益；没有预算的反思循环和没有步数上限的 ReAct 一样危险。

简历讲法：别写“了解 Reflexion”，写“给代码生成 Agent 加 Reflexion：Actor 出代码，单元测试做 Evaluator，失败时 Reflector 写可执行反思（如‘先确认单位换算’）进记忆重试，最多 3 轮；关键分类任务用 Self-Consistency 采样 5 次多数投票，平票触发人工审核”。前者是名词，后者是可追问的机制设计。
