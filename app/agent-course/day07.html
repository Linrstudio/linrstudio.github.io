Day 7：RAG 基础：为什么需要 RAG 与完整 Pipeline

大模型再强，也有三件事做不好：不知道的事它会一本正经地编，训练之后发生的事它不知道，你公司的私域数据它更没见过。RAG（检索增强生成）就是给大模型外挂一个知识库，让它“先查资料，再回答问题”——把“猜”变成“查”。今天先把 RAG 的完整 Pipeline 跑通，Embedding、检索策略、重排各有专课（Day 9–10），这里只点到为止。

一、核心解释

1. LLM 的三处短板：幻觉、时效、数据安全

幻觉问题：大模型是按概率逐个 token 生成文本的，它分不清“自己学过的”和“没见过的”，不知道时也会编一个像真的答案。时效性问题：模型越大训练成本越高、周期越长，训练截止之后发生的事它天然不知道，比如“帮我推荐几部热映的电影”。数据安全问题：通用模型没有企业内部数据和用户数据，企业希望数据留在本地计算，只让在线模型做归纳。这三点有一个共同的根：模型的“记忆”全锁在参数里，改不了、查不了、也说不清来源。

2. RAG 是什么：先查资料，再回答

RAG（Retrieval-Augmented Generation，检索增强生成）指：大模型在回答问题之前，先从外部知识库中检索出最相关的片段，再把这些片段作为上下文一并输入模型，从而约束模型的输出依据。核心思想是把“记忆”从模型参数里搬到可更新的外部存储，生成时按需取用。它由两个模块组成：检索器（R）负责从知识库中找出最相关的前 K 个文档块；生成器（G）负责把检索到的信息转化成自然流畅的回答，并确保生成内容与检索到的信息保持一致。记住一条心法：RAG 不是让 LLM 变聪明，而是给它装了个“外挂硬盘”和“查资料的习惯”。

3. 完整 Pipeline：离线建索引，在线查了再答

离线阶段负责把非结构化知识变成可检索的索引：加载文件 → 读取文本 → 清洗 → 文本分割（分块）→ 向量化（Embedding）→ 写入向量数据库并建索引。离线是一次性或增量做的，换文档就能秒级生效。在线阶段负责理解意图、检索、融合、约束生成：用户提问 → 问题向量化 → 在向量库中匹配最相似的 Top-K 个块 → 把匹配的文本作为上下文和问题一起拼进 Prompt → 提交给 LLM 生成回答。面试时能把这条线画出来，就已经超过大多数候选人。Pipeline 里每一步都有专课：解析与分块是 Day 8，Embedding 与向量库是 Day 9，检索与重排是 Day 10。

4. RAG vs 微调 vs 长上下文：不是三选一，是可组合

维度RAG微调（Fine-tuning）长上下文
知识更新换文档就行，秒级生效得重新训练，费钱费时仍需把新内容放进上下文
推理成本检索 + 生成，略高纯生成，低长上下文推理贵、延迟高
适合场景知识经常变、需要可溯源固定风格 / 任务、输出格式单文档极长且需全局推理
典型短板检索失败则答案差难频繁追新事实，易过拟合注意力分散、“中间遗忘”

选型口诀：知识型任务无脑 RAG，风格型任务（客服话术、代码格式化）微调更香。三者并非非此即彼，常见做法是 RAG 提供事实依据 + 轻量微调改善领域表达 + 长上下文处理单篇超长材料。长上下文是 RAG 的补充，不是替代——每次请求塞上百万 token 贵得离谱、延迟高，而且它给不出“答案来自第 3 页第 2 段”这样的溯源。

5. RAG 的好处与局限：先说好处，再认清天花板

好处：可扩展（不必为每个任务重训整个模型，外挂知识库即可扩展知识）；准确可核实（引用信息来源，用户可以核实答案）；可控（知识可更新、可定制）；可解释（检索到的条目就是预测的来源参考）；及时（检索能识别最新信息）；定制（索引特定领域语料就得到专业知识支持）；安全（数据库的角色与安全控制比微调模型更明确地管理数据访问权限）。局限：检索效果依赖 Embedding 与检索算法，检索到无关信息反而会污染输出；大模型如何利用检索到的信息仍是黑盒，生成文本可能与检索信息冲突；对所有任务都无差别检索 K 个片段效率不高，还会拉长输入；若不做引用设计，答案仍无法精准查证事实。Day 12 会系统讲这十二个痛点与评测方法。

容易踩的坑：RAG 不能完全消除幻觉。若检索错、块质量差、或模型忽略证据，仍可能幻觉。正确姿势是 Prompt 里写清“无法从已知信息中得到答案时就说不知道，不允许编造”，再配合检索、重排、引用约束与评估一起上——只堆 RAG 三个字母是防不住幻觉的。

二、代码示例

示例 1：LCEL 最小 RAG（现代 LangChain 1.x 写法）

# pip install langchain langchain-openai langchain-community faiss-cpu
from langchain_core.documents import Document
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_text_splitters import RecursiveCharacterTextSplitter

# 离线阶段：分块 -> 向量化 -> 建索引
docs = [Document(page_content="公司年假 15 天，需提前两周申请。报销需提交发票原件。")]
splitter = RecursiveCharacterTextSplitter(chunk_size=200, chunk_overlap=20)
chunks = splitter.split_documents(docs)
vectorstore = FAISS.from_documents(chunks, OpenAIEmbeddings(model="text-embedding-3-small"))
retriever = vectorstore.as_retriever(search_kwargs={"k": 2})

# 在线阶段：检索到的 context + 问题拼进 Prompt，再由 LLM 生成
prompt = ChatPromptTemplate.from_template(
    "已知信息：\n{context}\n\n根据上述已知信息，简洁专业地回答问题。"
    "如果无法从中得到答案，请说“根据已知信息无法回答该问题”，不允许编造。\n问题：{question}"
)
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
rag_chain = {"context": retriever, "question": RunnablePassthrough()} | prompt | llm | StrOutputParser()
print(rag_chain.invoke("年假有多少天？"))

示例 2：零 API Key 可跑的最小闭环（理解“先查再答”的逻辑）

# 不调任何模型接口，只用关键词重叠做检索，跑通“查 -> 拼 -> 答/拒答”全流程
CHUNKS = [
    "公司年假 15 天，需提前两周申请。",
    "报销需提交发票原件，每月 5 号前提交。",
    "考勤打卡时间为每天 9:00 前。",
]

def retrieve(query, chunks, top_k=2):
    """最小检索器：按关键词重叠数排序（生产请换向量检索，见 Day 9-10）"""
    scored = sorted(chunks, key=lambda c: len(set(query) & set(c)), reverse=True)
    return scored[:top_k]

def answer(query):
    context = retrieve(query, CHUNKS)
    # 兜底：检索不到相关内容时，诚实拒答而不是编造
    if not any(set(query) & set(c) for c in context):
        return "根据已知信息无法回答该问题"
    prompt = f"已知信息：\n{context}\n\n问题：{query}\n请仅根据已知信息回答。"
    return prompt  # 真实项目把 prompt 交给 LLM 生成答案

print(answer("年假有多少天？"))
print(answer("公司食堂在哪？"))  # 检索不到 -> 拒答

四、可能的面试题与答案

Q1：请用一句话解释 RAG。

RAG 是在生成前先从外部知识库检索相关证据，再把证据作为上下文交给大模型，以减少幻觉并支持实时更新的知识增强范式。一句话版本：让大模型“先查资料，再回答问题”。

Q2：为什么大模型需要外挂向量知识库？

克服遗忘与幻觉、提升回答的准确性、权威性与时效性、覆盖通用模型没涉猎的小众领域、提高可控性与可解释性。模型的记忆锁在参数里，改不了也查不了来源；外挂知识库把记忆搬到可更新、可审计的外部存储。

Q3：RAG 的标准 Pipeline 分几步？

离线四步：加载文件 → 文本分割 → 文本向量化 → 存入向量库建索引；在线四步：问句向量化 → 匹配最相似的 Top-K → 拼进 Prompt → LLM 生成回答。能画出这条线，面试就过关了一半。

Q4：RAG 和微调的根本区别在哪？各适用什么场景？

RAG 是动态查外部知识库，换文档秒级生效，适合知识经常变、需要可溯源的场景；微调是把知识硬训进模型参数，重新训练费钱费时，适合固定风格、格式与任务。两者可组合：RAG 提供事实依据，轻量微调改善领域表达。

Q5：为什么 RAG 能减少幻觉？

大模型瞎编是因为它不知道自己的认知边界，分不清“学过的”和“没见过的”。RAG 强行加了外挂知识库：生成前先查，库里有就照着说，没有就说不知道——把“猜”变成“查”。但注意它不能完全消除幻觉，检索错或模型忽略证据时仍会出错。

五、加分项

生产视角：先想清楚知识更新频率再选方案：每周都变的手册、政策、工单数据，用 RAG；一年不变的输出格式与口吻，用微调。RAG 上线第一天就要把“拒答”写进 Prompt——宁可说不知道，也别让模型拿着错误的检索结果一本正经地编。

简历讲法：别写“熟悉 RAG”，写“搭建 RAG 问答：离线解析分块 + 向量化建索引，在线检索 Top-K 拼 Prompt 生成，Prompt 内置拒答约束；知识更新从重训改为换文档秒级生效”。前者是名词，后者是可追问的动手过程。
