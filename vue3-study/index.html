01状态驱动视图

Vue 的核心思路是：视图是状态的声明式表达。模板读取响应式状态；状态变化后，Vue 会追踪依赖并更新相关 DOM。通常不需要手动查找元素、修改文字或重新绘制整个页面。

<script setup>
import { ref } from 'vue'
const message = ref('准备开始')
function start() {
  message.value = '正在学习 Vue 3'
}
</script>

<template>
  <p>{{ message }}</p>
  <button @click="start">开始</button>
</template>
用户操作→更新状态→Vue 追踪依赖→视图更新

模板负责描述“状态是什么样时，页面应该是什么样”，事件处理函数负责提出状态变更。

02ref 与 const：绑定不变，值可变

在脚本中

ref() 返回一个 ref 对象。读写其内部值时使用 .value，Vue 才能追踪这次读写。

在模板中

顶层 ref 会自动解包，所以通常直接写变量名，不写 .value。

const count = ref(0)
count.value += 1  // 脚本：通过 .value 读写

// 模板中：{{ count }}
// 事件绑定中：@click="count++"
const 和 ref.value 管的不是同一件事：const count 禁止把变量 count 重新绑定到另一个对象；它不禁止修改这个 ref 对象内部的 value。因此 count.value = 1 合法，而给 count 重新赋值不合法。
const count = ref(0)
count.value = 1       // ✅ 修改 ref 内部状态
// count = ref(2)     // ❌ 重新赋值给 const 绑定

简单记法：脚本里的 ref 用 .value；模板顶层 ref 自动解包；const 锁定变量绑定，不是冻结对象内容。

03reactive 与响应式数组

reactive() 通常用于对象或数组，返回一个响应式代理；模板和脚本都可以直接读写属性，不需要对每个属性写 .value。

import { reactive } from 'vue'

const profile = reactive({ name: 'Lin', level: 1 })
profile.level += 1

const cart = reactive([
  { id: 'a', name: '笔记本', price: 12, quantity: 2 },
  { id: 'b', name: '钢笔', price: 8, quantity: 1 },
])
cart.push({ id: 'c', name: '便签', price: 5, quantity: 3 })

用 reduce 汇总数组

汇总值通常是由列表推导出的派生数据。给 reduce 明确初始值，空数组也能得到正确结果。

const totalQuantity = computed(() =>
  cart.reduce((sum, item) => sum + item.quantity, 0)
)

const totalPrice = computed(() =>
  cart.reduce((sum, item) => sum + item.price * item.quantity, 0)
)
注意解构：直接把响应式对象上的普通字段解构到局部变量，可能会切断该变量与原代理属性的联系。需要独立 ref 时，可使用 toRefs()；Pinia store 则使用 storeToRefs()。

04computed 与 watch：派生值和副作用

computed

从已有状态计算出一个值。它会缓存结果，依赖变化后才重新计算。适合总价、过滤列表、格式化显示等派生状态。

watch

监听指定来源变化并执行副作用。适合写入存储、请求数据、记录日志或与非 Vue API 同步。

const keyword = ref('')
const filteredItems = computed(() =>
  items.value.filter(item => item.name.includes(keyword.value))
)

watch(keyword, (newKeyword, oldKeyword) => {
  console.log('搜索词变化：', oldKeyword, '→', newKeyword)
})

判断口诀：“我要一个随状态自动更新的结果”用 computed；“状态变了我要做一件事”用 watch。不要用 watch 手动维护本来可以直接计算出来的值。

05组件：props、事件与单向数据流

父组件通过 props 向下传入数据；子组件通过事件向上表达用户意图。这样数据由谁负责、变化从哪里来会更清楚。

父组件状态— props →子组件展示— emit 事件 →父组件更新
<!-- 子组件 ProductCard.vue -->
<script setup>
const props = defineProps({
  title: { type: String, required: true },
  price: { type: Number, required: true },
})
const emit = defineEmits(['add-to-cart'])
</script>

<template>
  <article>
    <h2>{{ props.title }}</h2>
    <p>¥{{ props.price }}</p>
    <button @click="emit('add-to-cart')">加入购物车</button>
  </article>
</template>
<ProductCard
  :title="product.name"
  :price="product.price"
  @add-to-cart="addProduct(product)"
/>

不要直接修改子组件收到的 prop。若子组件需要编辑值，应发出事件，请父组件更新其状态。

06v-model:quantity 的展开形式

带参数的组件 v-model:quantity 是一组约定：prop 名为 quantity，更新事件名为 update:quantity。它并不是子组件直接改父组件变量。

<!-- 父组件：语法糖 -->
<QuantityPicker v-model:quantity="quantity" />

<!-- 等价于显式绑定 -->
<QuantityPicker
  :quantity="quantity"
  @update:quantity="quantity = $event"
/>
<!-- 子组件 QuantityPicker.vue -->
<script setup>
const props = defineProps({ quantity: { type: Number, required: true } })
const emit = defineEmits(['update:quantity'])

function decrease() {
  emit('update:quantity', Math.max(1, props.quantity - 1))
}
function increase() {
  emit('update:quantity', props.quantity + 1)
}
</script>

<template>
  <button @click="decrease">−</button>
  <span>{{ quantity }}</span>
  <button @click="increase">+</button>
</template>

在 <script setup> 中，如果需要在脚本里读取 props，应将 defineProps() 的结果赋给变量（如 const props = defineProps(...)），再使用 props.quantity；模板中可直接使用 prop 名。

07组合式函数：用 useCart 复用逻辑

组合式函数是普通 JavaScript 函数，常以 use 开头。它把相关的状态和操作封装在一起，让组件只保留页面交互与展示。

// composables/useCart.js
import { computed, ref } from 'vue'

export function useCart() {
  const items = ref([])
  const count = computed(() =>
    items.value.reduce((sum, item) => sum + item.quantity, 0)
  )
  const total = computed(() =>
    items.value.reduce((sum, item) => sum + item.price * item.quantity, 0)
  )

  function add(product) {
    const found = items.value.find(item => item.id === product.id)
    if (found) found.quantity += 1
    else items.value.push({ ...product, quantity: 1 })
  }
  function remove(id) {
    items.value = items.value.filter(item => item.id !== id)
  }

  return { items, count, total, add, remove }
}

在组件中调用 const { items, count, total, add, remove } = useCart() 即可使用。组合式函数默认每次调用有自己的状态；如果需要多个页面共享同一份状态，应考虑提升到 Pinia store。

08表单：修饰符和校验

v-model.trim 会去掉首尾空白；v-model.number 会尝试把输入转换为数字。校验仍应明确处理空值、范围和类型，而不是只依赖输入框的修饰符。

<script setup>
import { computed, ref } from 'vue'
const name = ref('')
const age = ref('')
const nameError = computed(() =>
  name.value.length === 0 ? '请填写姓名' : ''
)
const ageError = computed(() => {
  if (age.value === '' || !Number.isFinite(age.value)) return '年龄须为数字'
  if (age.value < 0 || age.value > 120) return '年龄须在 0 到 120 之间'
  return ''
})
</script>

<template>
  <input v-model.trim="name" placeholder="姓名">
  <p v-if="nameError">{{ nameError }}</p>

  <input v-model.number="age" type="number" min="0" max="120">
  <p v-if="ageError">{{ ageError }}</p>
</template>
.number 不保证所有情况下都得到有效数字；输入为空或无法转换时仍要单独处理。提交时也应再次校验，不能只依赖浏览器控件。

09Vue Router：静态路由和动态参数

静态路由匹配固定路径；动态路由用 : 标记参数。动态参数在路由中一般以字符串形式读取，若业务需要数值，应在使用处显式转换和验证。

const routes = [
  { path: '/', component: HomeView },
  { path: '/about', component: AboutView },
  { path: '/products/:id', component: ProductView },
]
// ProductView.vue
import { computed } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
const productId = computed(() => Number(route.params.id))
const validId = computed(() =>
  Number.isInteger(productId.value) && productId.value > 0
)

例如访问 /products/42 时，route.params.id 通常是字符串 '42'。不要把路由参数直接当数字参与比较或计算。导航可使用 <RouterLink to="/about">，路由出口使用 <RouterView />。

10Pinia：跨页面共享状态

当购物车、登录用户等状态需要由多个页面或组件共同读取和更新时，可把它放到 Pinia store。store 中集中定义状态、派生 getter 和业务 action。

// stores/cart.js
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'

export const useCartStore = defineStore('cart', () => {
  const items = ref([])
  const total = computed(() =>
    items.value.reduce((sum, item) => sum + item.price * item.quantity, 0)
  )
  function clear() { items.value = [] }
  return { items, total, clear }
})

解构 store 时用 storeToRefs

import { storeToRefs } from 'pinia'

const cart = useCartStore()
const { items, total } = storeToRefs(cart) // state 和 getter 保持响应式
const { clear } = cart                     // action 可直接取出

storeToRefs() 会为 store 的状态和 getter 创建 ref，并跳过 action；方法通常直接从 store 解构或通过 cart.clear() 调用。

一般选择原则：局部、单个组件的状态放组件里；复用但不要求全局共享的逻辑放组合式函数；需要跨页面共享的应用状态放 Pinia。

11localStorage 持久化与深度监听

localStorage 只能保存字符串；对象需要先 JSON.stringify()，恢复时用 JSON.parse()。加载时要处理无数据或损坏数据的情况；对对象或数组内部变化进行持久化时，可使用深度监听。

import { ref, watch } from 'vue'

function readCart() {
  try {
    const saved = localStorage.getItem('cart-items')
    return saved ? JSON.parse(saved) : []
  } catch {
    return []
  }
}

const items = ref(readCart())
watch(items, (newItems) => {
  localStorage.setItem('cart-items', JSON.stringify(newItems))
}, { deep: true })
注意：浏览器存储可能不可用或内容格式不正确；写入也可能失败。生产代码可以把读取、解析和写入都放进 try/catch。不要把密码、访问令牌等敏感信息放进 localStorage。服务端渲染环境中，还要等客户端再访问 window 或 localStorage。

12生命周期：启动请求，也要清理

onMounted 适合组件挂载到页面后启动依赖 DOM 或客户端环境的工作；onBeforeUnmount 可在组件销毁前移除监听器、计时器或取消未完成请求。

import { onBeforeUnmount, onMounted, ref } from 'vue'

const data = ref(null)
const error = ref('')
let controller

onMounted(async () => {
  controller = new AbortController()
  try {
    const response = await fetch('/api/items', {
      signal: controller.signal,
    })
    if (!response.ok) throw new Error('请求失败')
    data.value = await response.json()
  } catch (err) {
    if (err.name !== 'AbortError') error.value = err.message
  }
})

onBeforeUnmount(() => {
  controller?.abort()
})

用 AbortController 取消组件不再需要的请求，可以避免卸载后继续处理过期结果，也能节省资源。若请求允许在页面切换后继续完成，是否取消则要按业务决定。

13Vitest 与 Pinia 组件测试

测试要验证用户能观察到的行为：初始内容是否正确、点击后状态是否改变、提交事件是否发出。使用真实 Pinia 实例时，在测试中创建并挂载一个新的实例，避免测试之间共享状态。

// CounterPanel.vue
<script setup>
import { useCounterStore } from './counter'
const counter = useCounterStore()
</script>

<template>
  <p data-test="count">{{ counter.count }}</p>
  <button data-test="increment" @click="counter.increment()">+1</button>
</template>
// CounterPanel.spec.js
import { describe, expect, it } from 'vitest'
import { mount } from '@vue/test-utils'
import { createPinia } from 'pinia'
import CounterPanel from './CounterPanel.vue'

describe('CounterPanel', () => {
  it('点击按钮后显示更新后的计数', async () => {
    const wrapper = mount(CounterPanel, {
      global: { plugins: [createPinia()] },
    })

    expect(wrapper.get('[data-test="count"]').text()).toBe('0')
    await wrapper.get('[data-test="increment"]').trigger('click')
    expect(wrapper.get('[data-test="count"]').text()).toBe('1')
  })
})

可以用 Vitest 的 describe、it 和 expect 组织断言，用 Vue Test Utils 的 mount 渲染组件。测试组件事件时可检查 wrapper.emitted()；测试 Pinia store 时重点覆盖 action 的状态变化和 getter 的计算结果。

14速查：把知识点落到工程选择

响应式与派生

ref：脚本中经 .value 操作；模板顶层自动解包。
reactive：代理对象/数组。
computed：缓存派生值。
watch：监听变化、执行副作用。

组件与状态

props 向下，事件向上。
v-model:quantity ↔ quantity + update:quantity。
useCart 复用领域逻辑；Pinia 共享跨页面状态。
解构 store 状态用 storeToRefs。

  • 要显示的值是否来自响应式状态，而不是手动改 DOM？
  • 派生数据是否用 computed，副作用是否才用 watch？
  • 子组件有没有直接修改 prop？需要更新时是否发出事件？
  • 路由参数是否按字符串处理，并在需要时显式转换、校验？
  • 持久化是否兼顾 JSON 解析失败、空值和敏感数据？
  • 组件卸载时，定时器、事件监听和未完成请求是否按需清理？
  • 测试是否覆盖用户可见结果，而不只是内部实现细节？
